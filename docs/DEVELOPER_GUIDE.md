## Stack and runtime

- **Shell:** Tauri 2 (Rust) — native plugins (audio, STT/TTS, OSC, local HTTP server); capabilities in `src-tauri/capabilities/` replace the v1 allowlist.
- **UI:** Vite, React 18, TypeScript.
- **State:** Valtio for backend/service and document sync; Zustand (`src/core/ui/store.ts`) for shell UI (sidebar, stats panel); Yjs + PeerJS for collaborative document sync.

### Runtime modes

| Mode | How | UI root |
|------|-----|---------|
| **Host** | Default path in desktop app | `SigilRoot` — full editor, integrations, inspectors |
| **Client** | Path `/client` + query (`host`, `port`, `id`) | `ClientView` — canvas/elements only; talks to host over PeerJS |

`AppConfiguration` in `src/config.ts` decides mode and loads network settings (Tauri `plugin:web|config` on host).

## Layering

- **`src/client/`** — Document, scenes, elements, files, particles, sound. Must not depend on host-only APIs (see [Client folder](#client-folder-srcclient)).
- **`src/core/`** — Host services (Twitch, Kick, Discord, OBS, VRC, STT/TTS, translation, transform, etc.), persisted settings (`Service_State`), Sigil chrome.
- **`src/shared/`** — PubSub (PubSub-JS + optional WebSocket + Tauri `pubsub` event), Peer bridge.
- **`src/services-registry.ts`** — `Services` enum (no imports from core/client) to avoid circular types.

## Data flow (host)

1. **Text/events:** `Service_PubSub.publish` → local PubSub-JS topics → `invoke("plugin:web|pubsub_broadcast")` → Rust → `emit("pubsub", …)` → JS listener; plus PeerJS broadcast to clients; optional outbound WS when “linked.”
   - The Rust `web` plugin **no longer relays pubsub between WebSocket peers**. Peer text goes only to the host (`pubsub` event), where `consumePubSubMessage` applies the **inbound allow-list** in [`src/shared/services/pubsub/inbound.ts`](../src/shared/services/pubsub/inbound.ts) and re-broadcasts. Allowed today: `obs.caption` (schema-checked), `stt.external.state` (local pages only) and the `text.*` topics `stt`, `textfield`, `translation`, `transform`, `transform_source`, `transform_raw`. **A new topic that must cross WebSockets needs a route in `inbound.ts`, or it is dropped.** The P6 topics `others.*` and `readings.*` are never accepted from WebSocket peers; `/client` validates them (see [Streamer features](#streamer-features-and-extended-engines-p6)).
   - Wire messages are `{topic, data, via}`; `via` is the chain of host session ids, so a host drops its own echoes and never sends a relayed message back over the Link socket it arrived on (Link-apps loop prevention). `text.stt` from another Sigil is published as text instead of re-entering the local STT pipeline.
2. **Document:** Yjs doc in `ApiClient.document`; `Service_Peer` syncs over PeerJS (see `src/shared/services/peer/`).
3. **Local server:** Rust `web` plugin binds `0.0.0.0:<port>` (all IPv4 interfaces, reachable across the LAN) by default, or `127.0.0.1` when `lanAccess.mode` is `localhost` (`web::serve_supervised` rebinds live and falls back to the previous mode) — `ping`, PeerJS path, pubsub WebSocket, static assets (`src-tauri/src/services/web/`). `/pubsub` and `/peer` handshakes pass an **Origin allow-list** (`web/origin.rs`; kill switch `lanOriginCheck` / `SIGIL_LAN_ORIGIN_CHECK`) and, for clients on other machines, the persistent **LAN token** (`web/auth.rs` `AccessGuard`, stage 2; close codes 4401 / 4403, `/peer` sends `INVALID-KEY`); binary frames close with 1003 and messages are capped at 256 KiB. Commands `server_status`, `set_origin_check`, `set_lan_access`, `regenerate_lan_token`; events `web:server_status`, `web:origin_rejected` (also the token refusals). Build links to `public/*.html` pages with `localPageUrl()` ([`src/utils/localPages.ts`](../src/utils/localPages.ts)).

## Native IPC

- Generic `invoke` commands: `get_native_features`, `get_port`, `app_close`.
- Feature work is mostly `plugin:<name>|<command>` from the frontend.
- Heavy entry points run through `Sigil.exe --headless <command>` (`--headless` must be the **first** argument; it is parsed before the port pre-check, the "port in use" dialog and Tauri, so a headless child never binds the pubsub port or opens a window; `src-tauri/src/services/cli/`). Release builds use the GUI subsystem, so the parent console is attached first and the output reaches the invoking terminal. Exit codes: 0 success, 1 the command failed, 2 usage error (`help` and `--version` exit 0). A handler returns `Result<String, String>`: `Ok` text goes to stdout, `Err` to stderr. In development use `src-tauri\target\debug\Sigil.exe` with a scratch `SIGIL_APP_DATA_DIR`. Commands are added, never renamed:

| Command | Arguments | Handler | What it does |
|---|---|---|---|
| `ep-probe` | `[--out file]` | `diagnostics::headless_ep_probe` | Deep probe of ONNX Runtime execution providers, GPU driver, DXGI adapters and the CUDA / cuDNN DLLs, run in its own process so the app never pays for a CUDA context. JSON on stdout (and to `--out`) |
| `fetch` | `<id>... [--mirror m] [--custom-url url]`, or `--list` | `model_store::headless_fetch` | Installs catalog entries and their requirements one download at a time; `--list` prints the catalog and the install states |
| `bench` | `<spec.json> [--out dir]` | `bench::headless_bench` | Voice-changer benchmark through the real harness: `report.json`, `report.md`, per-run `timeline.csv`; exit 1 when a threshold fails ([Benchmark harness](#benchmark-harness)) |
| `mt-bench` | `<spec.json> [--out dir]` | `mt_local::bench::headless_mt_bench` | Machine-translation chrF and latency over a local corpus ([MT benchmark](#mt-benchmark---headless-mt-bench)) |
| `speech-bench` | `<spec.json> [--out dir]` | `bench::speech::headless_speech_bench` | The P7 speech benchmark: STT accuracy, CPU / GPU speed under load, MT quality, TTS renderings ([Speech benchmark](#speech-benchmark---headless-speech-bench-p7)) |
| `gpu-load` | `<spec.json>` | `bench::gpu_load_child::run` | The benchmark's GPU load in its own process (a game's own process and queue). Started by a benchmark whose `load.gpu.out_of_process` is set; not meant to be run by hand |
| `engine-probe` | `<engine> [model] [wav] [--variant v] [--runtime-dir dir] [--out file] [-- extra]` | `speech_rt::headless_engine_probe` | Loads a native runtime (`sherpa`, `transcribe`, or a `sigil_engine` DLL such as `echo`) and runs a smoke test; JSON report |
| `vc-import-worker` | `<job.json>` | `neural_audio::vc::import::run_import_worker` | Imports an untrusted RVC `.pth` / `.zip` in an isolated child (job schema v1); started by the importer, not by hand |
| `sysinfo` | `[--out file]` | `resources::headless_report` | GPUs, drivers, VRAM budget, claims and every recommendation as JSON, without ONNX Runtime, a GPU runtime or a CUDA context |
| `stt-worker` | `[spec.json]` | `speech::worker_proc::headless_stt_worker` | Hosts one speech engine in an isolated worker process (spawned by the speech plugin through the process host; framed `SGW1` protocol over stdio) |

  For `ep-probe`, `engine-probe` and `sysinfo`, `--out` is a file; for the three benchmarks it is a folder.

## Plugin commands, capabilities and i18n staging

These conventions keep the shared registration files from becoming merge magnets.

- **Command lists are data.** `src-tauri/build.rs` reads `src-tauri/plugin-commands/<plugin>.txt` (one snake_case command per line, `#` comments; the file stem is the plugin name) and generates each plugin's `allow-*` / `deny-*` permissions and `<plugin>:default`. A new command needs the `#[command]` fn, its `generate_handler!` entry **and** a line in that file. `src-tauri/gen/schemas/*` are regenerated by the build; keep the regenerated files and never hand-edit them. When a command is removed, its old permission lingers in `acl-manifests.json` until `cargo clean -p sigil` (the default set is still correct).
- **Capabilities per plugin.** A new plugin gets its own `src-tauri/capabilities/<plugin>.json` (see `diagnostics.json`); `tauri.conf.json` does not enumerate capabilities, so every file loads. `migrated.json` / `desktop.json` hold the older plugins.
- **UI strings go to staging.** Workstreams put new English strings in `scripts/i18n-staging/<WS-ID>.json` (same nested shape as `public/i18n/en/translation.json`; a top-level `"$remove": ["section.key"]` deletes keys from every locale). The integrator runs `node scripts/merge-i18n-staging.mjs` (non-destructive; `--dry-run`, `--only`, `--allow-en-changes`), then `pnpm i18n:sync && pnpm i18n:check`, and removes the merged staging files. The old `merge-neural-i18n.mjs` / `merge-http-tts-i18n.mjs` overwrote locale sections and are retired (they exit 1).
- **Architecture decisions** are ADRs in [`docs/adr/`](adr/README.md).

## UI state

Sidebar tab visibility, expand/collapse, and multi-selection live in **Zustand** (`useAppUIStore`) so React and `ApiServer.changeTab` / `closeSidebar` stay in sync without a Valtio `window.ApiServer.ui` object.

## Release / quality

- **Release artifact** — release builds use `pnpm tauri:release` (`tauri build --config scripts/release/tauri.release.conf.json`). The overlay stages `onnxruntime_providers_shared.dll`, `onnxruntime_providers_cuda.dll` (ORT 1.28, 62 MB) and `DirectML.dll` next to `Sigil.exe` in both the NSIS (per-user, recommended) and MSI installers. The installers do **not** contain the NVIDIA CUDA/cuDNN runtime: it is the opt-in model-store pack `runtime/nvidia-cuda13` (about 1.9 GB, [ADR 0003](adr/0003-gpu-ep-delivery.md), [ADR 0007](adr/0007-native-runtime-packs.md)). The CUDA provider stays bundled until `runtime/ort-cuda13-provider` is published; the registered app-data provider path already works. The execution provider is chosen at runtime and the one actually in use is reported. Plain `pnpm tauri build` still works but ships without the staged provider DLLs. The RVC templates (`src-tauri/resources/vc-templates/`, under 1 MB) are bundled in every build.
- **Never list build-generated files in the base `tauri.conf.json` `bundle.resources`:** tauri-build copies resources at compile time and fails when they are missing, which would break `cargo check` / clippy / test on clean checkouts and in CI. Checked-in source files (the `resources/vc-templates` directory mapping) are fine; build outputs use a release overlay with an (initially empty) directory mapping, as `tauri.release.conf.json` does. The base config uses the map form (`{ "<source dir>": "<target dir>" }`) so the overlay's map merges into it instead of replacing it.
- **CI (GitHub Actions)** — on push/PR to `main` / `master`: an ubuntu job runs `pnpm i18n:check`, `node docs/check-docs.mjs --no-todo` (dead links, anchors, table shapes, facts that must agree with the code, leftover `TODO(P7-numbers)` placeholders), `node scripts/release/check-catalog-pins.mjs` (every published catalog entry is pinned, the release set is complete), `pnpm typecheck`, `pnpm test:unit`, `pnpm build` and the Playwright smoke (`PW_PREVIEW_ONLY=1` after build); a `windows-latest` job runs `cargo clippy --all-targets` then `cargo test` in `src-tauri` (empty `dist/` for `generate_context!`).
- **Build targets:** never cargo-build a scratch **copy** of the crate in the shared `src-tauri/target`: cargo hashes the root package by its relative path, so the copy overwrites the real crate's build script and `OUT_DIR` (symptom: "Permission diagnostics:default not found"). Use a separate `CARGO_TARGET_DIR`; recover with `cargo clean -p sigil`. `src-tauri/.cargo/config.toml` sets `GGML_NATIVE=OFF` / `GGML_AVX2=ON` for whisper-rs-sys (read only when cargo runs from `src-tauri/`; release.yml sets them too).
- `pnpm typecheck` — `tsc --noEmit`
- `pnpm test:unit` — vitest (`vitest.config.ts`, node environment, `@` alias) for pure TS logic: the STT drivers (local backend and segment publisher, the router mirror against the shared fixture, HTTP / webview / Vosk backends), the desktop default planners, the TTS sentence splitter, pipeline and backends, translation sequencer, transform ordering, TTS helpers, voice-changer contract, pubsub inbound routing, diagnostics, the i18n staging merger, the models service and formatters, sysinfo / resources (including a Rust-id drift test), audio devices, `rustAudioInput` and `scripts/models/pin-catalog.mjs`
- Automated runs that launch the full app (benchmarks, footprint, packaged smoke) set `SIGIL_START_MINIMIZED=1`: the main window is created hidden and unfocused, shown minimized without activation, and the window-state restore (which ends in `set_focus()`, a forced foreground switch) is skipped for it (`src-tauri/src/main.rs`). They also seed the scratch profile with `onboardingComplete` and, for both `stt` and `tts`, `desktopDefaultMigrated` and `localOfferShown`, so no one-time offer dialog appears. Someone is usually using the PC while these run.
- **Shutdown and the exit guard** (`src-tauri/src/exit_guard.rs`, P7-D): the app must end after its window closes. The guard arms on the main window's first close request and on the first exit request and, if the process is still alive 20 s later, logs one `exit guard:` WARN line (is the main window still there, shown, minimized, is its UI thread unresponsive) and ends the process with `TerminateProcess` (exit code 0). Cause it was built for: tao's event loop owns an invisible tool window of class "Tao Thread Event Target" (untitled, 16 x 16) that Windows counts as a visible, owner-less top-level window, so `Process.CloseMainWindow()` posts `WM_CLOSE` to it once the real window is minimized (a minimized window sits at the bottom of the z-order); that destroys the loop's own message window, the real window still closes, and the process lingers. Tools that post `WM_CLOSE` to every window of a process (`taskkill` without `/F`, installers, the Restart Manager) can do the same to a real install, and tao's window procedure cannot be changed. **Rule for harnesses:** close the window titled `Sigil` of that process (`scripts/release/packaged-smoke-all.ps1` `SmokeWindows.CloseTitled`, `scripts/speech-bench/campaign/footprint/close-window.ps1`), never `Process.CloseMainWindow()`; keep a `Kill()` fallback. `scripts/release/exit-probe.ps1` reproduces the lingering process.
- Rust tests stay inline (`cargo test --manifest-path src-tauri/Cargo.toml`). Tests never touch the network (the model store uses a local warp fixture server). Tests that need real models, devices or GPU runtimes are `#[ignore]` and read environment variables: `SIGIL_TEST_MODELS_DIR` (Whisper `ggml-*.bin`, `sherpa-onnx/…`, `models/transcribe/…`, `rvc-default-voice/default.pth` + `vc-parity/…`), `SIGIL_TEST_CUDA_BIN` / `SIGIL_TEST_CUDNN_BIN` (CUDA 13 / cuDNN 9 folders for CUDA tests), `SIGIL_TEST_ECHO_DIR`, `SIGIL_TEST_TRANSCRIBE_PACKS`, `SIGIL_TEST_LLAMA_SERVER` / `SIGIL_TEST_LLAMA_GGUF`, `SIGIL_TEST_LOOPBACK_OUT` / `_IN`, `SIGIL_TEST_EXPOSURE=1` (opens a non-loopback socket; triggers a firewall prompt), and for the P2 speech engines `SIGIL_APP_DATA_DIR` (a model store holding the sherpa / GGUF / TTS models), `SIGIL_STT_WORKER_EXE` (worker-isolation tests) and `SIGIL_TEST_OPENAI_SPEECH_URL` (+ `_MODEL`, `_VOICE`). Example: `SIGIL_TEST_MODELS_DIR=<dir> cargo test real_model -- --ignored`; the P2 exit runs are listed in [RELEASE_AND_ENGINEERING.md → P2 exit matrix](RELEASE_AND_ENGINEERING.md#p2-exit-matrix-speech-engine) and [benchmarks/SPEECH_BENCHMARKS.md](benchmarks/SPEECH_BENCHMARKS.md#reproducing).
- Benchmarks: `Sigil.exe --headless bench scripts/bench/specs/stub-smoke.json` (plumbing) and `pwsh scripts/bench/run-perf-gate.ps1` (release builds; see [docs/benchmarks/README.md](benchmarks/README.md)). A voice-changer change records a run before and after; a p95 regression over 5 % blocks it. Speech (STT, translation, TTS): `Sigil.exe --headless speech-bench <spec>` and the Python tests of `scripts/speech-bench` ([Speech benchmark](#speech-benchmark---headless-speech-bench-p7)).
- `pnpm test:e2e` — Playwright smoke (build + preview; `/` and `/client` shells mount `#root`; set `PW_PREVIEW_ONLY=1` if `dist/` is already built)
- `pnpm i18n:check` — locale JSON key parity vs `public/i18n/en/translation.json` and registered codes in `src/i18n.ts`
- `pnpm docs:check` (`node docs/check-docs.mjs [--no-todo]`) — relative links, `#anchors` against heading slugs, table cell counts, facts that must agree with the code (UI labels, the Streamer thread rule, unrouted models, the headless table) and, with `--no-todo`, leftover `TODO(P7-numbers)` placeholders in `docs/`, `README.md` and the unreleased part of `CHANGELOG.md`; `pnpm release:pins` (`node scripts/release/check-catalog-pins.mjs [--online]`) — the release catalog pin check ([scripts/release/README.md](../scripts/release/README.md))
- `pnpm i18n:sync` — merge missing keys from English into other locale files (new keys copy English until translated)
- `pnpm i18n:report` — list keys whose value still matches English (prioritize refresh / human review)
- `pnpm i18n:translate` — regenerate MT locales from English via `scripts/build-translations.py` (slow; excludes `zh` / `zh_cn` / `zh_tw`, which are maintained manually)
- `node docs/check-docs.mjs` — checks every Markdown file under `docs/`, the README and the current part of the changelog for dead relative links, anchors that match no heading (headings are slugged the way the in-app Help reader does) and table rows whose cell count differs from the header (a `|` inside a code span must be written `\|`). `--no-todo` also fails while a `TODO(P7-numbers)` placeholder is left. It also checks the facts a review found wrong against the code, each rule with a self-test that runs every time: the speech-to-text labels (**Processor only**, **Graphics card**, **Two-pass accuracy**, **Enable interim results**) against `public/i18n/en/translation.json`, the CPU Streamer's thread rule (all physical cores but two, never fewer than 4 nor more than 6 threads, the constants in `ort_session.rs`, and a promise of spare cores only with its condition), speech models that no `stt-routing.json` row lists (installable, never described as planned by **Best for my PC**), that every `--headless` command of `cli/mod.rs` has a row in the headless table, and that the Moonshine long-utterance section of SPEECH_BENCHMARKS.md stays. Run `node scripts/sync-manual.mjs` afterwards (it copies the consolidated guides and the manual into `public/`; edit the sources under `docs/`, never the copies).

### Translation review (human / community)

Priority locales for native or fluent review: **ja**, **ko**, **ar**, **ur**, **zh_cn**, **zh_tw**, then high-traffic EU languages.

Reviewers should preserve **`{{placeholders}}`**, **`<code>...</code>`** spans, product names (**OBS**, **VRChat**, **Twitch**, **Kick**, **Discord**), and abbreviations (**STT**, **TTS**). Prefer domain-correct wording for streaming and voice tooling over literal machine translation.

Use **`pnpm i18n:report`** to list keys that still match English; fix or file follow-up PRs per locale.

### RTL smoke checklist (`ar`, `ur`)

1. Switch UI language to **Arabic** or **Urdu** in Settings and confirm `<html dir="rtl" lang="…">` (handled in `src/i18n.ts`).
2. Open **Settings**, **sidebar**, and at least one **inspector**; confirm no clipped text or overlapping controls.

## Security notes (Tauri 2)

- **Capabilities:** IPC and filesystem access are gated by capability JSON (`migrated`, `desktop-capability`, and one file per newer plugin such as `diagnostics`). Prefer tightening `fs:scope` and plugin permissions over broad `*:default` when adding features.
- **Asset protocol:** `convertFileSrc` URLs are served only from `$APPDATA/vosk-models/**` (`app.security.assetProtocol.scope` in `tauri.conf.json`); Vosk is the only consumer. A new asset consumer should add its own narrow folder rather than widening the scope, and list `https://asset.localhost` (Windows, `useHttpsScheme`) / `asset:` in the matching CSP directive.
- **Threat model (short):** The Rust `web` plugin binds its HTTP/WebSocket stack to **`0.0.0.0`** (all IPv4 interfaces), so it is reachable across the **LAN**, not just localhost — a deliberate choice matching upstream Curses (`src-tauri/src/services/web/mod.rs`; a `127.0.0.1`-only bind rejected some localhost paths). It serves PeerJS signaling, the pubsub WebSocket, and static assets with **no authentication or TLS**. Since LAN security stage 1 the WebSocket handshakes pass an **Origin allow-list** (browser cross-site hijacking and DNS rebinding are refused), binary frames are refused and the host allow-lists inbound topics. Since stage 2 (P6-D) clients on **other machines** also need the persistent LAN token (same-PC peers are exempt), "This PC only" binds 127.0.0.1, and a legacy no-token switch (off by default) exists as an escape hatch; the token travels in cleartext on the LAN (no TLS). Remote clients use the **PeerJS** path and do not execute Tauri commands. Treat that LAN exposure as the real, shipped attack surface, and any change to the bind address, authentication, or TLS model as high-risk.
- **Expanded network model:** [RELEASE_AND_ENGINEERING.md](RELEASE_AND_ENGINEERING.md#network-security-and-threat-model) — LAN `/client`, linked pubsub, and operator hardening.

## Host services, persistence, and UI tabs

This section describes how **integrations**, **host-only modules**, and **sidebar/nav tabs** relate in Sigil. It complements the [connectivity audit](#service-and-feature-connectivity-audit) (Rust ↔ TS wiring).

### Three layers

1. **`Services` enum** ([`src/services-registry.ts`](../src/services-registry.ts))  
   Stable string ids used for **inspector navigation** (`InspectorTabPath.tab`), action bar ordering where applicable, and UI routing. Kept free of imports from `src/core` to avoid circular dependencies.

2. **`BackendState.services`** ([`src/core/schema.ts`](../src/core/schema.ts))  
   Zod-backed **persisted** settings per integration. Keys here are **`PersistedHostServiceKey`** (see `PERSISTED_SERVICE_KEYS`, `isPersistedServiceKey`, and `isPersistedServicesTab` in the same file). Use **`window.ApiServer.patchService(key, fn)`** only for these keys.

3. **`ApiServer` fields** ([`src/core/index.ts`](../src/core/index.ts))  
   Live service instances. Some correspond 1:1 with a persisted key (e.g. `stt` ↔ `state.services.stt`). Others are **host-only** (no row in `BackendState.services`).

### Central registration (TypeScript)

- **Startup init order and labels**: single registry in [`src/core/index.ts`](../src/core/index.ts) (`getHostServiceInitTasks`).
- **Inspector lazy imports, nav groups, sidebar buttons, header titles**: [`src/core/ui/servicePanels.tsx`](../src/core/ui/servicePanels.tsx).

### Checklist: add a **persisted** integration

1. Add `Services.<id>` in [`src/services-registry.ts`](../src/services-registry.ts) if it needs a sidebar/inspector tab.
2. Add `Service_*_Schema` and register under `BackendSchema.services` in [`src/core/schema.ts`](../src/core/schema.ts). Update **`PERSISTED_SERVICE_KEYS`** (TypeScript will enforce exhaustiveness against `PersistedHostServiceKey`).
3. Implement `src/core/services/<id>/` (`index.ts`, `schema.ts`, optional `services/` backends).
4. Add **`ApiServer`** field and include **`init`** in the registry inside [`src/core/index.ts`](../src/core/index.ts).
5. Add a panel entry in [`src/core/ui/servicePanels.tsx`](../src/core/ui/servicePanels.tsx) (lazy inspector, nav, sidebar, title).
6. If the service should appear on the bottom action bar, add the id to **`DEFAULT_ACTION_BAR_SERVICE_ORDER`** in [`src/core/schema.ts`](../src/core/schema.ts).
7. Optional: Tauri plugin + TS `invoke` (see connectivity audit).

### Checklist: add a **non-persisted** inspector tab

1. Add `Services.<id>` if it is a first-class tab.
2. **Do not** add a `BackendSchema.services` slice unless you intend to persist settings.
3. Implement service module and wire **`ApiServer`** + **init registry** as needed.
4. Register the panel in **`servicePanels.tsx`** only (avoid `patchService` for this id).

### Checklist: host-only module (no inspector)

Engine contract (`ISTTReceiver`): `onStart`, `onStop(error?)`, `onInterim(text, meta?)`, `onFinal(text, meta?)`, **`onStatus(text, {progress, level})`** (UI only, never published; engines must never send status through `onInterim`) and **`isMuted()`**. `meta` (`SttTextMeta`: `segmentId`, `revision`, `lang`, `turnEnd`) is copied onto the published `TextEvent` by `textEventMeta()` (only valid values; engines without segments publish unchanged events). `Service_STT.serviceState` carries `statusText`, `statusLevel` and `progress`; `setMuted(bool)` and `toggleRunning()` serve the shortcuts; `start({ automatic })` sets `ISTTService.startAutomatic` (auto-start at launch, so no consent dialog).

- **`local` driver** ([`services/local.ts`](../src/core/services/stt/services/local.ts)): accepts events only for pipeline `mic` and the right epoch (while a start waits for its result, the first epoch above the last one seen). `SegmentPublisher` publishes segments strictly in order, each as interims with rising revisions and then at most one final. With two passes the first-pass final is held as an interim until its replacement arrives (Rust's two-pass budget plus 1 s, or 1.5 s once the next sentence waits; after 2 misses in a row first-pass finals publish at once until replacements come back); a dropped segment abandons its interim. Interactive starts ask before downloading (`plugin-dialog` `message` with three buttons: the full plan, a smaller single-pass plan when it downloads at most 80 % of the full one, or not now); automatic starts never ask. Auto-restart after a retryable fatal error: back-off 1 / 2 / 5 / 10 / 20 s, 5 attempts, reset after 60 s of stable running; a missing model never restarts. `speech:status` codes are localized (`stt.local_status_*`), unknown ones show their `detail`.
- **TS router mirror** ([`stt/router.ts`](../src/core/services/stt/router.ts)) reads the same `model-catalog/stt-routing.json` as Rust and runs the shared fixture `src-tauri/test-fixtures/routing.json` in `router.test.ts`: change `router.rs` and `router.ts` together.
- **HTTP backends** (`openai_audio`, `moonshine`): [`rustCapturePolling.ts`](../src/core/services/stt/rustCapturePolling.ts) (`RustUtteranceService`) only drives the Rust pipeline; voice detection, pacing, merging, retries, the Groq limiter and the hallucination filter are Rust's. It publishes `speech:final` once per segment, shows `speech:status` on the status line only, and reports `speech:utterance` `dropped` only when speech was lost. Stopping sends exactly one `stop_pipeline`. `openAiAudioSetup` / `moonshineSetup` validate settings the way Rust does (`normalizeEndpointUrl`). The retired TS `UtterancePipeline` / `GroqRateLimiter` are gone.
- **Webview engines:** Azure loads `microsoft-cognitiveservices-speech-sdk` only when a session starts (as TTS does); Deepgram pauses the recorder while STT is hard-muted and sends KeepAlive every 4 s; Web Speech uses a `beforeunload` listener. Vosk stays a webview WASM engine fed 16 kHz mono by the capture hub; an unchanged partial is published once.
- Persisted VAD / Whisper settings become Rust options in [`sttOptions.ts`](../src/core/services/stt/sttOptions.ts) (`RustVadConfig`, `RustWhisperDecodeOptions` in `src/types.ts`). The desktop default migration is [`migrate.ts`](../src/core/services/stt/migrate.ts) (see [Desktop defaults](#desktop-defaults-p2)); the model picker catalog [`whisperModels.ts`](../src/core/services/stt/whisperModels.ts) is tested against `whisper.rs`.

The offers are dialogs (`@tauri-apps/plugin-dialog` `ask`), shown once each and one after the other by `ApiServer.runSpeechDefaultOffers()` after i18n is ready (`stt.runStartupOffer()`, then `tts.runStartupOffer()`); `localOfferShown` records that an offer was shown either way. Whisper users migrated by P0 get no offer. The Kokoro offer only goes to profiles that use TTS, because most users only run captions: `profileUsesTts` (`tts/defaults.ts`) counts a start recorded in `tts.everStarted` (set by `Service_TTS.onStart`), `autoStart`, or a voice picked for the Web Speech / SAPI backend. A profile without any of these gets the plan `wait`, which records nothing, so it is asked at the first launch after it starts TTS.

## Speech stack internals

Rust modules added by the speech-stack phases ([plan](SPEECH_STACK_IMPLEMENTATION_PLAN.md)): P0 stabilization, the P1 platform foundations (runtime policy, model store, capture hub, native runtime packs, sherpa-onnx, transcribe.cpp, process host, system probe and resource governor, RVC templates, benchmark harness) the P2 speech engine (the `speech` pipeline with its engines, router, two-pass finals and Smart Turn; the TTS sink, in-process local TTS and the OpenAI-compatible speech client) the P3 voice engine (template importer and slot store, engine core, GPU layer, pitch bank, retrieval and post stage, the runtime loop on the capture hub, benchmark v2 with the autotuner and the voice-changer frontend; see [Sigil Voice Engine](#sigil-voice-engine-p3)) and the P4 translation stack (the shared LLM client, the `llm-server` llama-server helper and proxy, the translation pipeline, `mt-local` NLLB and Bergamot, DeepL, the MT benchmark and revising captions).

### Real-time rules

- Audio callbacks never allocate, lock, log or do IPC: they write whole frames into an `rtrb` ring and wake a worker (`unpark`). Conversion from any cpal sample format uses the allocation-free `pcm_convert::build_input_stream_f32_timed` (with cpal's capture timestamps; the capture hub is its only caller since the voice changer moved onto the hub in P3).
- MMCSS "Pro Audio" is registered **once per callback thread** (`rt_thread::register_mmcss_pro_audio_once`); inference workers never register. Worker priority comes from `rt_thread::set_worker_priority` (auto / protect_game / protect_voice). Admin rights are never requested.
- Epoch discipline: engines bump the epoch under the stop lock on every start and stop and emit only while the epoch is current.

### `speech_core` and utterance capture

`src-tauri/src/services/speech_core/`: `silero.rs` (embedded Silero VAD v6.2 on Sigil's ORT, CPU, 1+1 threads, spinning off), `segmenter.rs` (hysteresis 0.5/0.35, 400 ms pre-roll, 500 ms end silence + 200 ms tail, `SpeechStart` only after 250 ms of confirmed speech, forced split at 18 s at the quietest frame), `resample.rs` (streaming downmix + rubato to 16 kHz, exact length, measured group delay), `hallucination.rs` + `phrases/<lang>.txt` (whole-sentence stock phrases, `~` soft phrases, repeat collapsing, marker stripping), `utterance.rs` (`SpeechFrontEnd`, drop-oldest `BoundedQueue`, take-once `UtteranceStore` capped at 8 utterances / 120 s).

`speech_core` also has the `SpeechSegmenter` trait (so the [speech pipeline](#speech-pipeline-speech) runs on a synthetic classifier in tests) and `BoundedQueue::pop_timeout` / `pop_front_if` / `is_empty`.

`audio/{speech_capture,utterance_capture}.rs` read a `Raw16kMono` consumer of the [capture hub](#capture-hub) on a worker thread and feed the front end; each discontinuity (restart, device move, mute edge, overrun) closes the open utterance first, and on loopback sources silence is filled in so an utterance still closes when playback stops. A lost device no longer ends the capture (the hub reconnects it). Since P2 no TS code calls utterance capture (the HTTP backends run on the speech pipeline); the commands stay for one release. IPC contract:

- `plugin:audio|start_utterance_capture { deviceName?, vad?: VadConfig }` → capture id.
- Event `audio:utterance` (tagged by `kind`): `speech_start {capture_id, seq, start_ms}`, `utterance {capture_id, seq, start_ms, end_ms, sample_rate, samples, forced}`, `dropped {capture_id, seq, reason}`, `error {capture_id, message}`. Ignore other capture ids.
- `plugin:audio|take_utterance { captureId, seq }` → binary `ArrayBuffer` of little-endian f32 mono 16 kHz (take once).
- `plugin:audio|stop_utterance_capture`.

The legacy `audio:chunk` stream (Vosk) is batched about every 20 ms from a hub consumer on a worker thread; `start_audio_capture({ sampleRate: 16000 })` delivers 16 kHz mono (about a sixth of the old 48 kHz stereo IPC), any other request the device's own format, and every payload states its `sample_rate` / `channels`.

### Whisper

Decoding lives in the pipeline's Whisper engine (`speech/engines/whisper.rs`, see [STT engines](#stt-engines)); `whisper.rs` keeps model management and the legacy IPC. `start_recording` / `stop_recording` run a speech pipeline on the crate-internal key `legacy-whisper` with a `LegacyWhisperSink`, which maps pipeline events back to `whisper:segment_transcript` (string), `whisper:speech_start` (`seq` is now the pipeline segment id), `whisper:utterance_dropped` (`reason` `backlog` or `latency_budget`) and `whisper:capture_error`, so `whisper.ts` works unchanged. `start_recording` accepts optional `vad` (`RustVadConfig`) and `decode` (`RustWhisperDecodeOptions`: `n_threads`, `initial_prompt`, `hotwords`, `no_speech_threshold`, `hallucination_filter`, `max_backlog`); the legacy RMS fields are ignored. Pipeline behaviour applies: the 20 s latency budget, several waiting utterances merged into one decode, and `whisper:capture_error` also when the recording stops itself on engine errors (5 in a row, or a fatal kind).

Models: `CATALOG` / `ALIASES` in `whisper.rs` (mirrored by the `whisper/<id>` entries of `model-catalog/stt-legacy.json`). `ensure_dependencies` downloads through the model store (its queue, resume and mirrors; progress bridged to `whisper:download_progress`; `cancel_whisper_download` keeps the partial for resume) and loads into a model slot shared with the engine. Local copies and imports are hashed while copying and registered with the store when they match the catalog. Capture always goes through the capture hub (`start_recording` rejects `captureLocal: false`); device loss is `audio:stream_error` / `audio:stream_recovered`. Log target `sigil::stt::whisper`.

### ONNX Runtime sessions and diagnostics

All Sigil ORT sessions go through [`neural_audio/ort_session.rs`](../src-tauri/src/services/neural_audio/ort_session.rs): `session_builder_for_vc(ep_hint, opts)?.component("vc.pitch").commit_from_file(p)` (or `build_session(component, ep_hint, opts, ModelSource)` → `(Session, EpOutcome)`). The ladder is CUDA → DirectML → CPU, each GPU step checked by a cached canary model, registered with `error_on_failure`, then an explicit CPU retry; the outcome is recorded with `diagnostics::record_ep_outcome`. Component keys: `vc` (bring-your-own ONNX generator), `vc.enc` / `vc.flowdec` / `vc.knn` (template voices), `vc.content`, `vc.pitch` (`vc.pitch.voicing` for the fusion's SwiftF0 part, `governor.vc.pitch` for the governor's light extractor), `vc.denoise`, `vc.onnx`, `tts.kitten` (also Kokoro on Sigil's ORT, shown as "Local TTS"), `stt.vad`, `stt.turn` (Smart Turn); benchmark sessions record under `bench.*`. Code that needs builder tweaks uses `build_session_with(component, ep_hint, opts, source, &configure)` (a hook run on every rung of the ladder: in-memory external initializers, dimension overrides; a hook error on a GPU rung is that rung's fallback reason) or `build_session_ext` with `GpuExtras` (CUDA stream, TF32, arena, cuDNN options, the DirectML high-priority queue, a TensorRT rung; what applied comes back in `GpuApplied`), never a bare `SessionBuilder`. `VcSessionOptions::cpu_arena` opts a CPU session into ONNX Runtime's CPU memory arena (ort rc.13's `ep::CPU::default()` disables it, which costs dynamic-shape graphs 20–35 % on every new input shape); Kokoro uses it. The voice changer keeps it off: template voices run fixed shapes, where the arena helps little (a benchmark option to measure it is a P3 follow-up). Since rc.13 (`runtime_version()` = 1.28.0, `CUDA_MAJOR` = 13): before the first CUDA session `native_runtime::nvidia::ensure_preloaded()` loads the NVIDIA runtime pack; the CUDA provider comes from `Sigil.exe`'s folder first, else from the registered app-data pack (`cuda_provider_in_use()` reports which). Test-only builders: `neural_audio::test_onnx::Graph` (hand-encoded ONNX), `vc::test_models` (fake RVC slots), `local_tts::test_model` (fake Kitten package). KittenTTS 0.3.0 is vendored in `local_tts/kitten/` (Apache-2.0 headers kept; `hub.rs` replaces hf-hub and downloads one file at a time into `app_data/models/kitten/`).

The `diagnostics` plugin (`src-tauri/src/services/diagnostics/`) owns the rotating file log (`logging.rs`, 10 MB × 5, `SIGIL_LOG`), the EcoQoS / timer throttling opt-out (`qos.rs`), DXGI adapters and VRAM (`gpu_mem.rs`), the canary (`canary.rs`), the light and deep EP probe (`ep_probe.rs`, deep probe via `--headless ep-probe`) and the NVIDIA runtime pack (`nvidia_pack.rs`). Its commands are listed in `plugin-commands/diagnostics.txt`; TS side in `src/core/services/diagnostics/`.

### Voice changer worker

`voice_changer/worker.rs` loads every model and bridge before any stream opens (it reports `resources::set_vc_running` on start and stop), then reads the [capture hub](#capture-hub) (P3-E): `ConsumerOptions::device_rate("vc")` with `MuteGroup::VoiceChanger` and a 3 s maximum backlog, while STT keeps its own `Raw16kMono` consumer of the same stream, so speech-to-text always hears the raw microphone. The voice changer's own conditioning runs on its copy only: input gain, the device-rate denoiser (DPDFNet at 48 kHz, or GTCRN resampled for the non-RVC modes; in RVC mode GTCRN runs inside the harness, `denoise::harness::DenoisedModel`, 16 kHz, exactly the new samples of every call), then the TTS aux mix. `ReadInfo::gap_after` / `restarted` become crossfaded splices plus `reset_model_stream`, and `end_qpc_ns` drives the per-tick timeline; while the microphone is gone or muted, silence is synthesized on the QPC clock so routed TTS keeps playing. `devices::InputFollow` follows a USB microphone that Windows renamed on another port (looked up off the worker thread after 500 ms of reconnecting, then every second; `device_lost` after 1 s, `device_restored` when back); outputs and the monitor retry every 250 ms and follow the system default. The worker drains the hub ring on every wake (a read larger than the ring's free space keeps the newest audio) and applies the latency budget (`budget.rs`: drop the oldest whole frames past max(budget, one block) down to max(block, budget/2) with a 5 ms equal-power splice; accounting captured = consumed + dropped + backlog). `aux_feed.rs` queues whole TTS clips (rubato, back-pressure at 60 s) and applies the mic gate; `resample.rs` is the stateful polyphase monitor resampler; `playback.rs` trims the output queue back to its steady valley with 5 ms equal-power splices after a starved device or an input discontinuity, and trims clock drift once a second's minimum level exceeds the gate plus one period (this fixed the P1 finding of 74 → 94 ms standing latency after a stall: a 3 s stall now returns to 74.4 ms within 95 ms); `persist.rs` writes settings atomically (tmp, fsync, `.bak`, rename) through a 400 ms debounced writer flushed on exit. The WebSocket sidecar bridge (`neural_audio/sidecar_bridge.rs`) has connect/handshake timeouts and budget-bounded exchanges.

### Runtime policy (what runs where)

Sigil.exe links only its own static ONNX Runtime (ort 2.0.0-rc.13, ORT 1.28.0, [ADR 0001](adr/0001-ort-upgrade.md)) and whisper-rs's static ggml. Everything else is optional and loads lazily, so **the app starts, and every existing feature works, with no pack installed** (`scripts/release/expected-imports.txt` and `verify-bundle.ps1` guard the load-time imports):

| Runtime | How it runs | Where it lives | Owner module |
|---|---|---|---|
| Sigil's ORT (Silero, pitch models, RVC, Kitten, future Smart Turn / NLLB / the voice engine) | in-process, static | `Sigil.exe` | `neural_audio/ort_session.rs` |
| NVIDIA CUDA 13 + cuDNN 9 runtime | DLLs preloaded by full path before the first CUDA session | model-store pack `runtime/nvidia-cuda13`, else the interim Settings pack | `native_runtime::nvidia` |
| ONNX Runtime CUDA provider | next to `Sigil.exe` (installer), else the registered app-data pack `runtime/ort-cuda13-provider` (`register_ep_library`) | installer / app data | `ort_session` (`SIGIL_CUDA_PROVIDER=exe\|pack` dev override) |
| sherpa-onnx 1.13.8 (CPU STT/TTS) | in-process C API, its own CPU-only `onnxruntime.dll` loaded by full path | `runtime/sherpa-onnx` | `speech_rt::sherpa` ([ADR 0002](adr/0002-sherpa-onnx.md)) |
| transcribe.cpp (GGUF STT, GPU tier) | in-process `sigil_transcribe.dll` (static ggml inside, unique name) | `runtime/sigil-transcribe-<variant>` | `speech_rt::transcribe` ([ADR 0003b](adr/0003b-transcribe-cpp.md)) |
| other `sigil_engine` DLLs (echo today) | in-process, lazily loaded, hash-checked | `runtime/sigil-<engine>-<variant>` | `native_runtime` ([ADR 0007](adr/0007-native-runtime-packs.md)) |
| llama-server (and later Bergamot, qwentts, sbv2) | helper process in a kill-on-close Job Object, 127.0.0.1 only | `runtime/llama-server-<variant>` | `process_host` ([ADR 0005](adr/0005-process-host-llama.md)) |

Rules that follow from it:

- **ORT sessions** are built only through `ort_session` after `ensure_ort_environment`, with spinning off. rc.13's plain `SessionBuilder::new()` applies ORT's auto-EP policy, which only an explicit EP overrides, so never build sessions elsewhere. Import `TensorElementType` from `ort::value`; builders are `mut` before `commit_from_*`. Do not use `ort::ep::cuda::preload_dylibs` (its Windows list still names CUDA 12 DLLs). The CUDA EP needs driver R580+ and a Turing or newer GPU; anything else falls back to DirectML with the reason recorded. A provider DLL whose PE version differs from the linked ORT is refused (`provider_version_mismatch`).
- **Loading native code:** `native_runtime::load_library_in_dir` (`LoadLibraryExW` with `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | DEFAULT_DIRS`) from the folder `model_store::installed_path(id)` returns. Every in-process ggml engine links ggml statically inside a uniquely named DLL built with `/MD`, `GGML_NATIVE=OFF`, `GGML_BACKEND_DL=OFF`; two engines that both loaded a shared `ggml.dll` would bind to whichever loaded first. sherpa's `onnxruntime.dll` stays CPU-only inside its pack and is refused if another `onnxruntime.dll` (for example Windows ML's System32 1.17) is already in the process.
- **Helpers** run through `process_host::spawn` only: `CREATE_NO_WINDOW | CREATE_SUSPENDED`, joined to their own Job Object before they run, `127.0.0.1` with a random 256-bit key passed by environment variable (never on the command line, never serialized), and a listener-table audit that stops a helper exposing any non-loopback port.
- **Loaded native code stays loaded** until exit (the NVIDIA runtime, the registered provider, GPU engine DLLs). Removing such a pack while Sigil runs is reported as removed, and CUDA falls back to DirectML until the next start.

### Model store and catalog authoring

`model_store` (`src-tauri/src/services/model_store/`, plugin `model-store`) replaces the per-plugin downloaders: `catalog.rs` (embedded catalog plus `SIGIL_MODEL_CATALOG_OVERRIDE`, validation, dependency order), `download.rs` (HTTP Range resume into `<sha>.partial` + `.partial.json`, 30 s stall timeout and no total timeout, streaming sha256 or git blob id, failover on connect errors / 403 / 404 / 429 / 5xx / HTML / wrong size / hash mismatch), `mirrors.rs` (catalog order plus an automatic hf-mirror twin; preference; custom mirror), `extract.rs` (zip, tar.gz, tar.bz2 with traversal, link, device-name, case-duplicate, entry, size and ratio caps), `install.rs` (plan, acquire by legacy adoption / `SIGIL_LOCAL_ASSETS` / network, stage, one-rename commit, atomic `installed.json`), `queue.rs` (FIFO, 1–2 jobs, one per host, cooperative cancel), `legacy.rs` (adopts `whisper/` and `vosk-models/` files by hash), `events.rs` (`models:progress` at most 4 Hz, `models:state`) and `commands.rs` (9 IPC commands).

- **Consumers** locate files only with `model_store::installed_path(id)` and install on demand with `model_store::ensure(&[ids]).await` (on a tokio runtime; works headless). Never build install paths by hand.
- **Layout:** ordinary entries `app_data/models/<family>/<id rest>/<version>/`; runtime packs `app_data/runtimes/<id rest>/<version>/<variant|default>/`; families `whisper` and `vosk` install into the legacy `whisper/` and `vosk-models/` folders the plugins read. `models/<family>/<id rest>/installed.json` is the commit marker.
- **Trust:** release catalogs are fully pinned (`build.rs` refuses a `published` entry with an unpinned file in release builds). Trust-on-first-use exists only in debug builds and never for executables. `unpublished` entries (Sigil-built packs, templates, exports; asset hosting is local only for now) come only from Import, `SIGIL_LOCAL_ASSETS` or a custom mirror, never from their catalog URLs.
- **Authoring:** add a fragment `src-tauri/model-catalog/<area>.json` (format, rules, layout and mirrors in [`model-catalog/README.md`](../src-tauri/model-catalog/README.md)); ids are forever (`whisper/<plugin id>`, `vosk/<id without vosk-model->`, `runtime/sigil-<engine>-<variant>`, `runtime/<name>`). Pin with `node scripts/models/pin-catalog.mjs [--fragment f] [--only prefix] [--write] [--hash-by-download]` (sequential, at least 2 s apart, cached in `%LOCALAPPDATA%\sigil-dev-cache`). `"size": 0` on an unpinned file means unknown. `--headless fetch <id>` with a scratch `SIGIL_APP_DATA_DIR` is the quickest end-to-end check.
- **Tests** run against a warp fixture server (resume, stall, failover, zip-slip, adoption, queue limits) and never touch the network.
- **TS:** `window.ApiServer.models` (`src/core/services/models/index.ts`): state `catalog`, `states`, `progress`, `disk`, `loaded`, `pending`, `opErrors`, `configProblem`, `configError`; methods `install`, `cancel`, `remove`, `verify`, `importLocal`, `refresh`, `load`, `pushConfig` (none reject; a reload never overwrites a newer `models:state` event). Pure helpers are in `models/format.ts`. The Models & Runtimes tab is `inspector_models.tsx`; deep-link with `window.ApiServer.changeTab({ tab: "models", value: "<entry id>" })`.

- `src/core/services/stt/downloadProgress.ts` formats both the legacy STT `{file, progress}` events and `models:progress` (`normalizeDownloadProgress`, `formatSpeed`, `formatEta`, `formatByteProgress`).

### Capture hub

`audio/{hub,consumer,watchdog,stream,loopback,device_watch}.rs` open **one cpal stream per physical source** and fan it out to consumers:

- **Source ids** are what the pickers store: `default`, an input name, `loopback:default` or `loopback:<output name>`. "default" and the same mic picked by name share one stream; a `default` source follows the Windows default device (epoch kept), a named one stays.
- **Consumers:** `hub::global()?.attach(SourceSpec::parse(device), ConsumerOptions::speech("stt") | ConsumerOptions::device_rate("vc"))`, optionally `.with_mute_group(Some(MuteGroup::…))`. Output is `Raw16kMono` (the speech front end's rubato resampler, exact length) or `DeviceRate`. Each consumer has its own rtrb ring with a header (frames, QPC capture time, discontinuity flags); a lagging consumer drops its own oldest blocks (`max_backlog_ms`), and `wait()` uses park/unpark. A read never mixes audio from both sides of a restart, device move, mute edge or overrun: `ReadInfo.gap_after` / `restarted` tell the caller to close its state first; `end_qpc_ns` stamps latency.
- **The audio callback** only copies into rings and unparks (no allocation, lock, log or IPC); consumers are added and removed through a command ring and their memory is returned through a second ring.
- **Watchdog:** a cpal error or 2.5 s without audio restarts the stream under the same epoch (backoff 100 ms doubling to 3 s); `audio:stream_error` once per outage, `audio:stream_recovered` once audio flows again, or `audio:stream_closed` when the source lost its last consumer before it recovered. Loopback sources never count as stalled.
- **Device watcher:** a hand-written `IMMNotificationClient` (polling fallback, 10 s re-check) emits `audio:devices_changed` with reason `added` / `removed` / `default_changed` / `state_changed`.
- **Mute gate:** `plugin:audio|set_capture_mute({ group, muted })` per `MuteGroup` (`stt`, `voice_changer`, `others`); muted consumers receive nothing.
- Commands: `get_device_snapshot`, `set_capture_mute`, `get_capture_status` (plus the existing capture commands). `SIGIL_CAPTURE_SHARING=0` restores one stream per consumer (soak A/B only). Log target `sigil::audio::hub`.
- The speech pipeline (every Rust STT engine, Whisper included), the legacy utterance capture and `audio:chunk` (Vosk) run on the hub. The voice changer still opens its own cpal input until P3-E moves it to a `DeviceRate` consumer in the `voice_changer` mute group.
- **TS:** `src/core/services/audioDevices.ts` (`ApiServer.audioDevices`) mirrors device lists and defaults, toasts outages and recoveries, mirrors the STT hard mute to the Rust gate, and restarts only browser-captured STT backends (Azure, Deepgram, Web Speech) after a microphone change or a hub backend whose start failed because its device was missing. `InputRustAudioInput` reads it (a saved but disconnected device stays listed as "not connected"; `includeLoopback` adds loopback sources, used only by the future other-player pickers); `src/utils/rustAudioInput.ts` has the source-id helpers.

### Native runtime packs and the `sigil_engine` ABI

`native_runtime` (plugin `runtime`, [ADR 0007](adr/0007-native-runtime-packs.md)) loads engine DLLs that implement **`native/common/sigil_engine.h` ABI v1**: 16 C exports (`sigil_engine_abi_version`, `_get_info`, `_last_error` (thread-local), `_set_log_callback`, `_create`, `_destroy`, `_cancel`, `_query`, `_process`, `_render`, `sigil_stream_open/_push/_finish/_close`, `sigil_free_string`, `sigil_free_audio`), capability bits `SIGIL_CAP_PROCESS | STREAM | RENDER | CANCEL | GPU`. Everything crossing the boundary is JSON plus interleaved f32 audio; memory returned by the engine is freed only by that engine; calls on one instance are serialized and `cancel` may come from any thread; no exception, `abort` or `exit` may cross the boundary.

- **Packs:** catalog id `runtime/sigil-<engine>-<variant>`, variants in preference order `cuda13`, `vulkan`, `cpu-avx512`, `cpu-avx2`, `cpu` (GPU variants need AVX2). Each pack carries `sigil-pack.json` (sizes and sha256 of every file, the engine's own info); the loader checks the hashes, the ABI version first, all 16 exports and the engine info before use. `native_runtime::open_engine("<engine>", &OpenRequest { … })` picks the best installed variant this PC supports and falls through to the next on a load failure or `SIGIL_E_BACKEND_UNAVAILABLE`. A missing, damaged or foreign DLL is an error, never a panic.
- **Writing an engine:** derive from `sigil::Engine` (`native/common/sigil_engine_impl.hpp`; the shared implementation provides the 16 exports, JSON, errors, cancel and logging) and call `sigil_add_engine(<name> VERSION … SOURCES …)` from `native/engines/<name>/CMakeLists.txt`; `native/cmake/SigilVariant.cmake` forces `/MD`, static third-party libraries, `GGML_NATIVE=OFF`, `GGML_BACKEND_DL=OFF` and the variant's instruction sets (MSVC-only flags are limited to C/C++ so nvcc never sees them). `pwsh scripts/native/build-runtime-packs.ps1 -Engine <name> -Variant <v>` builds, checks with `sigil_engine_check`, and writes reproducible zips to `native/out/` (`dev/`, `packs/`, `local-assets/`); an engine with its own `build.ps1` (transcribe) is delegated to it. See [`scripts/native/README.md`](../scripts/native/README.md).
- **Probe:** `Sigil.exe --headless engine-probe <engine> [model] [wav] [--variant v] [--runtime-dir dir] [-- extra]` (`sherpa`, `transcribe`, or any `sigil_engine` such as `echo`).
- **NVIDIA runtime:** `native_runtime::nvidia` preloads `runtime/nvidia-cuda13` (CUDA 13.2, cuBLAS 13.3, cuFFT 12.2, cuDNN 9.26 `cuda13`, plus every other cuDNN 9 sub-library the pack ships) by full path, falling back to the interim `diagnostics::nvidia_pack`. `fingerprint()` changes when a runtime or provider pack is installed or removed: cached GPU canaries and saved deep EP reports are discarded then. `list_runtime_packs` / `remove_legacy_runtime` list and delete `legacy/*` runtime folders of earlier Sigil versions.

### CPU speech runtime: `speech_rt::sherpa`

sherpa-onnx 1.13.8's C API through vendored bindgen output (`bindings.rs`, 46 functions, regenerated reproducibly by `scripts/runtime-packs/sherpa/gen-bindings.ps1`). The runtime pack `runtime/sherpa-onnx` (upstream `win-x64-shared-MT` build, 8 MB download) is loaded once per process and never unloaded: the pack's `onnxruntime.dll` by full path first (C API level 28), then `sherpa-onnx-c-api.dll`, with the version pinned to exactly 1.13.8. Wrappers (`online`, `offline`, `tts`, `lid`, `speaker`) are `Send + Sync` behind a per-object call lock; blocking calls go on `spawn_blocking`. TTS generation is serialized process-wide (espeak-ng keeps global state). Thread defaults: 2 (streaming recognizers 1, because ORT's spin-wait cannot be disabled through the C API), capped at 4. C++ exceptions do not cross the C API, so a corrupt model aborts the process: catalog models are hash-verified and user folders go through `probe::validate_in_child` first. `detect.rs` recognises official package folders. Dev override `SIGIL_SHERPA_RUNTIME_DIR`; real-model tests use `SIGIL_TEST_MODELS_DIR/sherpa-onnx/{pack-1.13.8,models/…}`.

**Engines on it (P2-B):** `speech/engines/sherpa_offline.rs` (utterance engine: Parakeet Ultra and v3, Qwen3-ASR-0.6B, SenseVoice, Moonshine base; the Whisper-base language-ID engine; the runtime preload at plugin setup, kill switch `SIGIL_SHERPA_PRELOAD=0`) and `sherpa_online.rs` (Nemotron 3.5 streaming). `speech_rt::sherpa::catalog` is the source of truth for how each catalog model runs (ids, family, languages, `final_languages()`, capabilities; a unit test keeps it equal to `model-catalog/stt-sherpa.json`); `languages.rs` holds Qwen3 language names, SenseVoice codes and Nemotron's prompt dictionary; `hotwords.rs` cleans phrases, builds Qwen3 context text and derives a `bpe.vocab` from `tokens.txt` (score = −id) for NeMo transducer hotwords. Engine options (`EngineSpec.options`): `language`, `hotwords`, `hotwordsScore`, `prompt`, `decoding`, `maxActivePaths`, `maxNewTokens`, `useItn`, `tailPaddingMs`, `kind` / `mode` / `fp32`.

- **Nemotron** takes the language through the per-stream `language` option, checked against the encoder's `prompt_dictionary`; with none (or an unknown one) it runs on auto and warns once (`sherpa_language_auto`). Streams start with 0.3 s of silence and end with one decode window (`window_size` × 10 ms + 30 ms) of silence, or the first and last words are lost. It cannot take hotwords. The 560 ms model is the default (RTF 0.30–0.35 on one 7800X3D thread); the 160 ms model costs 0.80–0.87.
- **Qwen3-ASR-0.6B** takes the language as its English name ("Japanese") and hotwords plus the prompt as per-stream context; it does not report the language it detected (the language-ID engine covers auto mode). **Parakeet** switches to modified beam search with the derived `bpe.vocab` the first time hotwords arrive. **SenseVoice** finals carry `lang:`, `emotion:` and `event:` tags; its language can be pinned only at creation (`options.language`). The **language-ID engine** returns empty text plus `lang` and a `lang:<code>` tag.
- **Moonshine v2** (`stt/moonshine-base-en-int8`, English): sherpa-onnx 1.13.8 returns an empty result for one decode of 148,351 samples (9.272 s at 16 kHz) or more (an ORT broadcast error inside `DecodeStream` that sherpa swallows), so `sherpa_offline` cuts utterances over `MOONSHINE_MAX_SEGMENT_MS` (9,000) at quiet points with `long_utterance::Splitter` (the quietest 20 ms frame, rated over a 140 ms span, in the back half of the limit; the window never reaches closer than a third of the limit to either end), decodes the pieces in order (`decode_in_chunks`, the cancel flag checked after each), joins the texts (`long_utterance::append_text`: no space for CJK, Thai, Lao, Khmer or Myanmar, none before closing punctuation) and decodes a clearly voiced piece that came back empty again as two halves (`retry_in_halves`). The engine option `moonshineMaxSegmentMs` (2000..=9000) can only lower the limit, `0` never splits, and a v1 layout (no merged decoder) is split only when it is set. An empty result for 3 s or more of audio with at least half of its frames voiced logs one rate-limited (60 s) warning under `sigil::sherpa` (`EmptyDecodeLog`; Moonshine only, since the other families answer non-speech with no text on purpose). The ignored test `real_moonshine_sherpa_length_limit_is_still_where_the_split_assumes` pins the 148,350 / 148,351 threshold: re-run it on every sherpa-onnx upgrade (commit f8eedb8; operator view: [Moonshine inside Sigil](OPERATOR_REFERENCE.md#moonshine-inside-sigil-sherpa-onnx)).
- Threads: 1 for streaming, 2 for utterance engines, at most 4. Cancel is supported and a stale cancel never affects the next utterance. Missing models or packs give `NotInstalled` naming the catalog id; user folders are validated in a child process first.
- Tests: real-model tests need `SIGIL_APP_DATA_DIR` pointing at a store with the models and `SIGIL_TEST_MODELS_DIR/sherpa-onnx/clips` (dev setup `%LOCALAPPDATA%\sigil-dev-cache\appdata-p2b`). The probe takes catalog ids and `lang=`, `hotwords=`, `beam=1`, `hotwords_score=` extras: `Sigil.exe --headless engine-probe sherpa stt/nemotron-3.5-streaming-560ms-int8 <wav> -- lang=en chunk_ms=560 threads=1`.

### GPU speech runtime: `speech_rt::transcribe`

transcribe.cpp v0.2.4 (pinned commit, `native/engines/transcribe/UPSTREAM.json`) behind the `sigil_engine` ABI as `sigil_transcribe.dll`, built by `pwsh native/engines/transcribe/build.ps1 [-Variant cpu,cpu-avx2,cpu-avx512,cuda13,vulkan] [-SelfTest] [-FetchOnly] [-CudaArchitectures …]`. `TranscribeModel::open` picks the best installed `runtime/sigil-transcribe-*` variant (or `SIGIL_TRANSCRIBE_RUNTIME_DIR`), falls through GPU failures to the next variant or the same DLL's CPU backend (`fallback_reason()`), and offers `transcribe` / `transcribe_audio` (resampled with rubato), a canceller, `open_stream`, `warmup` and `device_memory`. The `cuda13` variant imports only `cublas64_13.dll` (cudart static) and requires `runtime/nvidia-cuda13`. Qwen3-ASR in 0.2.4 checks for cancel only before its single-shot decode, so callers drop stale results by epoch. Dev variables `SIGIL_TRANSCRIBE_CUDA_BIN`, `SIGIL_TEST_TRANSCRIBE_PACKS`; real-model tests read `SIGIL_TEST_MODELS_DIR/models/transcribe/`.

**The engine (P2-D):** `speech/engines/transcribe.rs` runs Qwen3-ASR-1.7B Q8_0 / BF16, Cohere Transcribe Q4_K, Granite Speech 5.0 TurboCTC, Voxtral Mini 4B Realtime (streaming) and bring-your-own GGUF files (`model-catalog/stt-gguf.json`, pinned to Hugging Face commits). The spec's `variant` decides the want: none = the governor decides, `cuda13` / `vulkan` = the GPU when admitted, `cpu-*` / `cpu-any` = the CPU. Options: `language`, `deviceId` / `device`, `cpuFallback`, `minFreeVramMb`, `nCtx`, `warmup`, `warmupSeconds`, `maxSegmentSeconds`, `pnc` / `itn`, `noSpeechThreshold`, `commit` / `agreement` / `appendOnly`, `isolation` (`inProcess` | `worker`), `workerMemoryLimitMb`.

- **Family rules** hold in the engine whatever the router says: Cohere is never used for ja / zh / ko / ru / yue and always needs a language; a hint a language-detecting model does not support is dropped so it detects instead; a detected language is tagged `lang:<code>`. Utterances over 20 s (the GPU warm-up length) are split at their quietest point and joined (no spaces between CJK pieces). `appendOnly` streaming shows only committed text; a stream closed by a CPU fallback is reopened and the utterance replayed. Stale results after a cancel are dropped by generation.
- **Governor** (`speech_rt::transcribe::governor`): admission uses `resources::policy`'s room for the STT final (GPU class, CUDA eligibility, the voice changer on cards under 16 GB in the auto tier, VRAM left after other claims) and reaches the variant walk as `ModelOptions::allowed_variants`, so the GPU is never used without it; the unmeasured `vulkan` build is used only when a spec names it. Admission and claims happen in one locked step: the model claim is resized to the measured process-VRAM delta, and one context claim per runtime (about 400 MB) stays for the process lifetime once a model ran on the GPU, because `native_runtime` keeps GPU DLLs loaded. Denied GPU → the CPU with a reason; with `cpuFallback: false` the load fails (`OutOfMemory` for a full card or a running voice changer, `Unsupported` without a usable GPU).
- **Measured on the RTX 4090** (process VRAM including the ~0.38 GB CUDA context): Qwen3-ASR Q8_0 3470–3494 MiB, BF16 5914 MiB, Cohere Q4_K_M 1950 MiB, Granite 890 MiB (lower-case, no punctuation: never routed as a caption final), Voxtral about 4100 MiB. ORT's CUDA EP and ggml-cuda coexist in one process and share one CUDA context. `resources::policy` and `stt-routing.json` use these numbers.
- **Worker isolation** (`speech/worker_proc.rs`, optional, off by default): `isolation: "worker"` or `SIGIL_STT_ISOLATION=worker` runs the engine in `Sigil.exe --headless stt-worker [spec.json]` under the process host (Job Object with a memory cap, no window, stderr to the log). Parent and child speak the framed binary `SGW1` protocol over stdin / stdout (stray native output is skipped); status and cancels cross the pipe. A crashed worker restarts; it moves to the CPU after 2 GPU crashes or one crash while loading and stops restarting after 5 crashes; a call with no answer past its deadline kills the worker. The parent holds one external VRAM claim for the child, resized to its measured VRAM. `SIGIL_STT_WORKER_EXE` (debug builds only) points tests at a worker executable.

### Helper processes (`process_host`)

`process_host::spawn(HelperSpec)` → `HelperHandle { name, pid, port, base_url, api_key }` (the key is never serialized): `{port}` / `{api_key}` are substituted in args and environment, `PortRequest::{none, auto, fixed}` (auto binds `127.0.0.1:0`; a startup port collision retries on a new port), TCP then `GET /health` readiness, restart policy with doubling backoff (budget resets after 60 s of stable running), stop = close stdin, wait `stop_grace_ms`, then `TerminateJobObject`. ### System probe and resource governor

- **`sysinfo`** (`probe()`, `cached()`, `refresh()`; IPC `get_system_info`; event `sysinfo:changed`; `Sigil.exe --headless sysinfo`): DXGI adapters plus a D3D12 capability test, NVML (loaded from System32, kept for the process) for driver, CUDA version, compute capability and device memory, `cuDriverGetVersion` from nvcuda without `cuInit`, CPUID features and core counts, total RAM. It never loads ORT or a GPU runtime and never creates a CUDA context; the GPU part has a 15 s timeout. EP eligibility (`sysinfo::eps`): CUDA and TensorRT need Turing (compute capability 7.5) and R580; TensorRT-RTX needs Ampere and R580; DirectML needs D3D12 feature level 11_0; unknown facts give `eligible` with code `unverified`. Eligibility covers GPU, driver and OS only, not whether the runtime pack is installed.
- **`resources`**: GPU-model subsystems call `resources::claim_vram(Subsystem, label, estimate_mb)` before loading (`claim_external_vram` for helper processes), `resize` the RAII claim to the measured footprint, claim 0 MB on the CPU, and ask `resources::recommend(topic, &sysinfo::cached(), &resources::snapshot())` (IPC `get_recommendation`) before choosing a model size. The voice changer reports `set_vc_running` on start and stop and `set_vc_gpu` once its models are loaded (until then `resources` infers the device from the `vc` / `vc.*` EP outcomes; benchmark sessions record as `bench.vc*` and never count). The policy is pure and integer-only: room = primary VRAM − reserve (30 %, at least 2 GB) − the voice changer (its claims, or 1.2 GB while running without one) − other subsystems' claims; candidates in quality order, the first that fits wins; live budget numbers are deliberately not an input. Recommendation ids are `resources::policy::ids` (mirrored and drift-tested in `src/core/services/resources/format.ts`); the STT-final footprints are measured (P2-D: Qwen3-ASR 1.7B Q8_0 3500 MB, BF16 6000 MB, Cohere 2000 MB, each including the CUDA context), the others provisional until the P7 measurement campaign. Event `resources:changed` (coalesced, 250 ms).
- **TS:** `ApiServer.sysinfo` and `ApiServer.resources` (`src/core/services/{sysinfo,resources}/`) feed `GpuRuntimeCard` on the Models & Runtimes tab.

### RVC templates and the importer

`scripts/vc-templates/` (maintainer-only Python: torch 2.3.1, onnx 1.17.0, onnxruntime 1.19.2) exports the RVC architecture as **split graphs** with external initializers ([ADR 0004](adr/0004-rvc-templates.md)): `enc` (phone + pitch → m_p / logs_p), `flowdec` (flow reverse + NSF decoder over a window, inputs z_noise, src_noise, phase0, g) and `knn` (exact retrieval blend), each fp32 and fp16-inside with fp32 I/O, plus `layout.json` mapping every initializer to its checkpoint key or weight_norm fold. `export_rvc.py` is deterministic; `parity_test.py` gates fp32 at 1e-4 and fp16 at 5e-3 against upstream PyTorch (`--write-fixture` regenerates `src-tauri/test-fixtures/vc/tiny`, `--rust-weights` byte-compares the Rust writer). The bundled templates `src-tauri/resources/vc-templates/<id>/` ship as installer resources (`tauri.conf.json` `bundle.resources`, found at `<exe>/resources/vc-templates`, `SIGIL_VC_TEMPLATES_DIR` for experimental exports): 22 templates, 15.5 MiB. `matrix.json` lists them and the 26 cells no trainer produces, with the reason: RVC v1 at 32/40/48 kHz and v2 at 24/32/40/48 kHz, HiFi-GAN NSF with and without F0, plus Applio's RefineGAN and MRF HiFi-GAN with F0 on v2. `export_matrix.py` exports and parity-checks the whole matrix (`--dml-python <venv>` adds the DirectML class).

**Layout version 2** (15 templates: every f0-less, MRF and RefineGAN cell) names what a reader must support in `features`: `flowdec-inputs-by-layout` (the flowdec inputs are listed per variant), `nof0` (no pitch or source inputs), `nsf-harmonics` (MRF: 9 harmonics, `src_noise` `[1,S,9]`, fixed per-harmonic `phase_ini`), `adain-noise-pool` (RefineGAN: a pool of `streaming.adain.pool.count` normal values in an external `noise.f32.bin`, indexed per absolute frame by `noise_offsets` `[1,F]` int64) and `linear-f0` (closed-form interpolation instead of ONNX Resize). Both Applio vocoders take `phase` `[1,F]`: the phase0 carry evaluated at every window frame, computed by the engine in f64. RefineGAN decodes its main path only over `main_margin` (about 11 frames) + R, but its source path needs `dec_margin` 85–89 frames, so its **source** window is about 1.1–1.2 s. Its flowdec has two windows ending at the same frame (`graphs.flowdec.variants.*.inputs` name the dims): the source window `F = flow_margin + dec_margin + R` feeds `f0`, `phase`, `noise_offsets` `[1,F]` and `src_noise` `[1,F·upp]`; the latent window `Fz = F − streaming.latent_offset = flow_margin + main_margin + R` feeds `m_p`, `logs_p` and `z_noise` `[1,C,Fz]` (`latent_offset` is `dec_margin − main_margin` for RefineGAN, absent = 0 elsewhere; feeding F-frame latents is an ONNX Runtime error). So a RefineGAN voice needs only Fz frames of content-encoder / `enc` context (about 0.40 s at 32 kHz with R = 4); only the cheap source inputs (F0 from the cache, phase, counter noise) need the long history, and the graph reads none of `f0` before `flow_margin − 1`, `phase` / `src_noise` before `flow_margin` or `noise_offsets` before `flow_margin + latent_offset` (zero-fill them). `streaming.excitation.f0_lookahead_frames` is 1 for RefineGAN (0 elsewhere): decode R + 1 frames and drop the last, or delay the output 10 ms, else the excitation phase steps at tick boundaries. Size lookahead and crossfade per template from `matrix.json` `seam_frames_fp32` (the measured no-lookahead seam at 1e-4: 9–17 frames for HiFi-GAN / MRF, 20–29 for RefineGAN), not from `dec_receptive_right_frames` (a structural bound: 85–89 for RefineGAN's symmetric sinc resampler). **The importer and the engine read layout version 1 only** (the 7 f0 HiFi-GAN templates): version-2 voices (f0-less, RefineGAN, MRF) are refused at import until both implement these features (the first P3 follow-up; the fixtures in `src-tauri/test-fixtures/vc/tiny/v2` exercise every feature with Applio's `parametrizations.weight.original0/1` keys).

Precision policy from the measurements: `enc` always fp32; `flowdec` fp16 on GPU where the template's DirectML parity rows stay under 0.8 × the gate (16 of 22; RefineGAN, v2-48k HiFi-GAN and v2-24k f0-less run fp32 on GPUs; each `layout.json` records `parity` and `recommended` per device class), fp32 on CPU; `knn` fp16 on GPU. The GPU parity class is DirectML's (no CUDA 13 build of `onnxruntime-gpu` for Python); CUDA is at least as accurate. `export_embedders.py`, `export_pitch.py`, `export_denoise.py` and `export_bench.py` export and check the base assets: the content encoders (each entry with an `embedder.json` contract: I/O, frame formula, `parity` per variant and EP class, `recommended` variant), SwiftF0, CREPE-tiny, the FCPE adapter and RMVPE, GTCRN, DeepFilterNet3 and DPDFNet, DNSMOS, CAM++ and `bench/gpu-load`. `scripts/assets/vc_catalog.py` writes the four catalog fragments (`--check` verifies them) and `scripts/assets/check-local-assets.mjs` verifies a `SIGIL_LOCAL_ASSETS` folder against the catalog. The vendored Applio model code (`scripts/vc-templates/applio_arch/`, MIT, unchanged) is imported only by the maintainer cross-check `parity_test.py --upstream-applio`; the RefineGAN and MRF references are Sigil's own ports in `rvc_arch/vocoders.py`, measured in float64.

`neural_audio::vc::import` is the importer behind `Sigil.exe --headless vc-import-worker <job.json>` (job schema v1: `version`, `source`, `out_dir`, `templates_dir`, `time_limit_s`, `smoke`, `smoke_fp16`, plus `name` and `index`; output `weights.f32.bin`, `speakers.f32.bin`, `sigil-import.json`): zip guard, an arena-based allow-list pickle VM (legacy pickles and TorchScript refused; string dict-key hashes are cached per shared allocation and `_codecs.encode` of ASCII text is a plain copy, which bounds CPU amplification), bounds-checked tensor views, metadata detection, template match by architecture (training checkpoints `G_*.pth`, bare and DataParallel state dicts and multi-`.pth` archives included; a config-less checkpoint gets its template from the tensor shapes), an f64 weight_norm fold bit-identical to Python, a weights writer that rejects leftover tensors, and a smoke decode that feeds only the inputs each template graph declares. Errors carry one of 18 codes (`params_contract.json` `import_error_codes`, sent over IPC as `<code>: <message>`).

- **Isolation** (`import::worker`): the IPC import runs the worker through `process_host::spawn::launch` in its own Job Object (3072 MB commit cap, BelowNormal, `CREATE_NO_WINDOW`, bounded output, the worker's 120 s watchdog plus a 20 s parent grace, cancellable). A memory-cap hit maps to `archive_rejected`, the hard timeout to `time_limit`, a cancel to `job`, a crash to `io`; after any failure the slot folder is recovered, so a worker killed mid-swap never loses the previous voice. Windows-only (`worker::available()`); legacy pre-1.6 pickles stay refused.
- **Slot store** (`import::slot`, manifest format `sigil-rvc-1`): one atomic swap writes `weights.f32.bin`, `speakers.f32.bin`, `added.index`, `sigil-import.json` (`importer_version`, `name`, `index`, `warnings`, `created_unix_ms`) and `manifest.json`; `slot.json` and a kept index survive a re-import. A manifest-less bring-your-own folder gets `sigil-slot.json` for its display name, so its generator is never re-interpreted. Work happens in hidden folders and `recover_all` restores interrupted swaps and removes trash; delete first renames into a hidden trash folder (it fails cleanly while a file is in use and never follows links). The sha256 import cache requires the same importer version, the template's current `weights_id` and intact weights. Merge blends the folded weights and speaker rows (RVC's row rule) and refuses different templates or embedders. `import::set_templates_dir` / `templates_dir()` tell the factory where the bundled templates are.
- **Index adoption:** an `added_*` index next to the `.pth` or inside the zip is adopted when unambiguous (a name match wins); a `trained_*` index never is. It is checked with `faiss::FaissIndex` inside the worker (panic-contained; the channel width must match), and any problem is a warning, never a failed import.
- **Embedders:** Applio and w-okada names map to Sigil's: `contentvec`, `contentvec-256` (v1), `spin-v2`, `spin` (Applio's first SPIN, `vc/embedder-spin`, P3-I0), `hubert-ja`, `hubert-ko`, `hubert-zh`. Custom and unknown embedders are refused with `unsupported_model`.
- **IPC** (`voice_changer/cmd_import.rs`): `voice_changer_{import, cancel_import, list_slots, rename_slot, delete_slot, duplicate_slot, set_active_slot, merge_slots, import_default_voice}` with the events `voice_changer:import_progress` (stages `queued`, `reading`, `converting`, `writing`, `done`, `failed`) and `voice_changer:slots_changed`. One lock serialises every slot change; deleting the running voice is refused; set-active selects the slot in RVC mode through `update_params` and emits `voice_changer:params`. The default voice is `model_store::ensure(vc/voice-default)` plus an import with its sibling index, activated when no voice is selected.
- **Fuzz corpus:** `python src-tauri/test-fixtures/vc/fuzz/generate_corpus.py` regenerates the 200 files deterministically; `the_fuzz_corpus_never_crashes_or_hangs` runs them in-process, the ignored `the_whole_corpus_crosses_the_process_boundary` through 200 worker processes, and the ignored `community_corpus_report` (`SIGIL_TEST_VC_CORPUS_DIR`, `_OUT`, `_STRICT`) writes the T8 report for a folder of real voices. The default-voice parity test is `cargo test vc::import -- --ignored` with `SIGIL_TEST_MODELS_DIR` (`rvc-default-voice/default.pth`, `vc-parity/<template>/reference.*`), optional `SIGIL_TEST_CUDA_BIN` / `SIGIL_TEST_CUDNN_BIN` / `SIGIL_TEST_SKIP_DML`.

### Sigil Voice Engine (P3)

The voice changer's main engine ([plan → VC best engine](SPEECH_STACK_IMPLEMENTATION_PLAN.md#vc-best-engine)): imported `.pth` / `.zip` voices run on split-graph templates in Sigil's own ONNX Runtime, behind the same stream harness, budget and metrics as every other mode. Measured status against the targets T1–T10: [docs/benchmarks/VC_BENCHMARKS.md](benchmarks/VC_BENCHMARKS.md). The voice-changer IPC contract, including every P3 parameter, is [`params_contract.json`](../src-tauri/src/services/voice_changer/params_contract.json).

#### Engine factory, hot voices and the governor (`voice_changer::factory`, `vc::engine::governor`)

- `create_engine` / `create_engine_with(request, denoiser)` dispatch on the slot's `manifest.format`: `rvc` (or no manifest) → the legacy full-decode `RvcModel` wrapped in the post stage (a bit-exact pass-through with neutral controls, so every voice answers every control); `sigil-rvc-1` → `SigilRvcEngine`; a P5 family format (`ddsp-svc-6.3`, `sigil-zs-1`, `meanvc-2`, `sovits-4.1`, `sidecar-v2`) → `vc::families::create` ([Voice families](#voice-families-p5)); anything else is refused. The worker and the benchmark both build engines here, so a benchmark measures what the user runs.
- The pitch extractor comes from the pitch bank, `f0_fusion::create_pitch_extractor_with(&req, GpuLevers::from_effective(&levers))`: with `io_binding` + `cuda_graphs` on, RMVPE (alone or inside the fusion) runs as its CUDA-graph plan (P3-I0 wiring).
- `EngineRequest::lookahead_ms` (param `lookahead_ms`, 0–80 ms, P3-I0) calls `SigilRvcEngine::set_lookahead_ms` before the harness is built; `CreatedEngine::model_delay_16k` / `LoadedVoice::model_delay_16k` carry it into the e2e estimate. Bring-your-own ONNX voices ignore it with a lever note, and so does a voice whose content encoder cannot run as a fixed-shape plan on DirectML (an fp16-I/O explicit file; with lookahead its dynamic window costs 35–49 ms per call there, while the plan costs about 1.5 ms since P3B-D).
- **Hot voices** (`VoiceSet`): the running voice plus up to `hot_slots − 1` recently used ones stay loaded (within `vram_budget_mb` when set); a switch to a loaded voice happens at the next block, any other voice loads on a `sigil-vc-load` thread while the current one plays, and evictions drop on a helper thread. `LoadedVoice::prime_blocks` primes a fixed-block voice with one model block plus its hold-back plus one device block before the one-block equal-power crossfade (`crossfade_into`), so a switch never plays silence. Each voice holds `resources::claim_vram(Subsystem::Vc, …)` sized to the measured process delta (0 MB on the CPU). `noise_seed_for` keys the anchored noise per voice (source sha256, else the folder name). The worker publishes the slot folders the run holds (`VoiceSet::slot_dirs`: active, ready, idle and loading voices) in `VoiceChangerState::held_slots` whenever the set changes (compared without allocating; `None` when the run ends), and the import commands refuse to replace or delete those folders (`cmd_import::held_slot_dirs`). After the harness is built, `LoadedVoice::load_cancellable` folds the model's `stream_report` (sessions rebuilt by `configure_stream`, e.g. a CPU fallback or a CUDA graph that no longer captures) into the voice's outcomes, levers and warnings; the factory and denoiser wrappers forward it.
- **Governor** (the `governor` lever, off by default until the benchmark measures it): levels 0–4 switch retrieval off, then (planned) 50 % context, then the light F0 extractor, then the light denoiser. A block is hot on a budget drop, a backlog over half the budget or compute over 0.85 of the block, calm under 0.55 of the block with a backlog under two blocks; it steps down after about 150 ms of pressure (at once on a budget drop) and up after about 5 s of calm, with an 8-block settle after each step, a relapse back-off up to 16×, and no-op steps skipped. With the lever on, the factory builds SwiftF0 (CPU, one thread, warmed at load) next to a heavier F0 method and `GovernedModel` + `SwitchablePitch` switch at the next tick (session key `governor.vc.pitch`). The context step is not implemented (it needs pre-planned shapes) and is skipped.

#### Engine core (`vc::engine`, P3-C1)

- **Fixed-block harness.** A model that declares `fixed_block()` gets exactly one block per call at one context length: a pre-accumulator (starting with 4 zero samples) absorbs the resampler's jitter, `configure_stream(block, want, extra)` lets the model size its plan to the harness's real SOLA tail, the output hold-back for block-sized bursts is computed from the rates (0 when the device block equals the plan block at the device rate, `block_16k × rate / 16000`), and `stream_pos` stays on the block grid. `ConversionCtx::stream_pos_16k` is the absolute 16 kHz index of `mono_16k[0]` (0 for warm-ups). The legacy mode is unchanged (every exact-length test still passes). `VcStreamHarness::last_join()` returns the SOLA join offset and its normalized cross-correlation.
- **Shapes** (`ShapePlan`): blocks round up to 20 ms so the content-encoder framing stays anchored in absolute time; return = block + SOLA tail; the flowdec window = return + flow_margin + dec_margin (the whole context with partial decode off); the context is at least the window (about 0.43 s at 40 ms blocks for 40 kHz voices); optional lookahead frames (10 ms each, at most 80 ms) end the returned audio that much before the newest input.
- **Levers and their legacy paths** (each independently switchable; `EffectiveLevers` says which run): `partial_decode` off decodes the whole context; `anchored_noise` off draws fresh noise every tick (on: Box-Muller over a SplitMix64 counter keyed by seed, stream and absolute index; the flow noise index is `channel × 2^40 + frame`; a per-frame cache generates only new frames); `nsf_phase0` off restarts the NSF sine at phase 0 every tick (`PhaseTracker` carries it exactly like the graph, fp32 increments, wrapped); `f0_cache` off extracts F0 over the whole context every tick (on: new block + margin + lead frames, spliced by absolute frame, falling back to a whole-window extraction on gaps; `PitchExtractor::receptive_frames` sizes the lead). The four algorithmic levers default on; the GPU levers' `auto` table is in `engine::presets::auto_lever` with the numbers behind each entry (P3-I0: `io_binding` on CUDA and DirectML, `cuda_graphs` on CUDA; `gpu_priority`, `gpu_knn` and `governor` off).
- **Content encoders** (`engine::content`): `EmbedderKind` = ContentVec 768 / 256, SPIN-v2, SPIN (v1), HuBERT ja / ko / zh; the manifest name or the RVC / Applio `embedder_model` picks it and the channel count is authoritative for ContentVec. Resolution order: an explicit path (ContentVec kinds only), then the model store's variants (`model.fp16.onnx` first on GPUs, `model.int8.onnx` first on VNNI CPUs, `SIGIL_VC_INT8` overrides the detection, then fp32), then the legacy `voice-changer/base/` files. A GPU variant whose session lands on the CPU is rebuilt from the CPU variant. Sessions are shared across hot voices (`ContentEncoderPool`) and released on drop. P3-A's `embedder.json` marks fp16 ContentVec and HuBERT-ja as failing the gate on DirectML for a 6 s clip (rel. L2 2.5e-2); on the ≤ 1 s windows the engine runs they pass (4.6e-3–5.9e-3), so the pool keeps fp16 on GPUs.
- **Generator** (`engine::generator`): `enc` always fp32 on the context, `flowdec` per `layout.json` (fp16 on a GPU only with the voice's fp16 image and a variant that passes parity on that device class; an automatic fp16 session that lands on the CPU is rebuilt fp32 and keeps its original fallback reason). `SpeakerTable` clamps speaker ids and blends weighted speakers (`set_speaker_blend`). Load checks the import record's `weights_id` and template, the weights size and file names confined to the slot, then runs a validating test conversion. Silence skip has an 80 ms hangover. Diagnostics components: `vc.enc`, `vc.flowdec`, `vc.content`, `vc.knn`, `vc.pitch`.
- **Legacy `RvcModel`** (bring-your-own ONNX): fp16-I/O generators and encoders run; exports with `skip_head` / `return_length` decode only the returned frames plus a 12-frame decoder guard; `LegacyNoise::Anchored` feeds time-anchored `rnd` only when `anchored_noise` is explicitly `on` (`engine::presets::byo_lever`: the lever table is measured on template voices, so `auto` keeps the export's zero `rnd`; the factory reads the user's mode from `EngineRequest::anchored_noise_mode`); a per-slot content encoder is used when the manifest names one (`hubert`, or a non-ContentVec `embedder`).
- Dev-rig harnesses (ignored tests, env vars in their docs): `engine::tests::sve_context_scaling_bench`, `sve_render_default_voice`, `generator::tests::default_voice_partial_decode_matches_full_decode`.

#### GPU layer (`neural_audio::gpu`, P3-C2)

- **Session plans** (`gpu::plan::SessionPlan`, frozen API `build`, `input_f32`, `input_i64`, `run`, `output`, plus `notes`, `residency`, `vram_mb`, `set_output_download`, `copy_rows_to`, `warm_up`): three I/O paths. The legacy host path (unchanged); bound host tensors on CPU, DirectML and TensorRT (read in place on the CPU; on a GPU only inputs written since the last run are re-bound); and device-resident CUDA tensors at fixed addresses with pinned host mirrors, run on the plan's own stream (a tick = uploads, graph or run, downloads, one sync). Every run goes through the raw `RunWithBinding` call (ort's `run_binding` allocates per call), so a bound tick makes no host allocation.
- **CUDA driver API** (`cuda_driver`): `nvcuda.dll` loaded lazily from System32 (primary contexts, streams, async and 2D copies, pinned memory, graph capture and launch); the driver API keeps the lever independent of the NVIDIA runtime pack. `cuda_stream::PriorityStream::highest()` (priority −5 vs 0).
- **CUDA graphs** (`cuda_graph`): Sigil records the graph itself in thread-local capture mode (two warm-up runs, one recorded run with device sync off, one replay checked against the regular run, then a plain `cuGraphLaunch` per tick with no ONNX Runtime call). ONNX Runtime's own `enable_cuda_graph` is not used: its global capture mode made concurrent CUDA work elsewhere in the process fail (`CUDA failure 900: operation not permitted when stream is capturing`, measured), and ggml aborts on CUDA errors. A failed capture leaves the plan running without a graph, with a note.
- **DirectML high-priority queue** (`dml_queue`): a D3D12 device, a DIRECT queue at priority HIGH (no admin rights) and a DirectML device through raw COM, handed to ONNX Runtime with DML1; one queue per adapter is shared (accelerator `dml_hp`).
- **TensorRT** (`trt`): TensorRT-RTX through its plugin EP pack (`runtime/tensorrt-rtx`, unpublished local pack; `SIGIL_TRT_DIR` for development), with the EP-context engine cache under `<app_data>/voice-changer/trt-cache/<key>` (the key covers model, weights, shapes, GPU, compute capability, driver, ORT and pack version; least-recently-used eviction at 16 entries or 8 GB) and progress on `voice_changer:trt_progress` (`cache_hit`, `building` twice a second, `done`, `failed`). Classic TensorRT is an option when its provider sits next to `Sigil.exe`. `available()` reads the providers' PE import tables and never loads anything; a pack whose imports do not resolve is refused with the missing DLLs named (the pyke rc.13 provider imports TensorRT 10 names, not TensorRT-RTX 1.x). Not run live yet (see the P3 exit matrix).
- **VRAM** (`arena`): plans measure their own VRAM through DXGI and hold it in `arena::ledger()` per component until dropped; an opt-in shared CUDA arena exists (graph plans cannot use it). **TF32** follows the precision request (`GpuLevers::tf32`: on unless `fp32` is requested): off made enc + flowdec 2.3× slower (3.43 → 7.85 ms p50) for an error the fp16 budget already covers. `SIGIL_CUDA_TUNING` overrides the CUDA settings for sweeps; `SIGIL_CUDA_PROVIDER=exe|pack` picks the provider (the device path is verified with the provider next to the exe).

#### Pitch bank, retrieval and post stage (P3-D)

- **Pitch bank** (`vc::f0_fusion::create_pitch_extractor(_with)(&PitchBankRequest, GpuLevers)`, used by the factory and the benchmark): `fcpe`, `rmvpe`, `dio`, `swiftf0`, `crepe`, `pesto`, `fusion`; every extractor returns F0 on the hop-160 grid, declares `receptive_frames`, and reports its session's EP outcome (`vc.pitch`; P3-I0 added RMVPE and FCPE). SwiftF0 and PESTO run on the CPU with one thread. SwiftF0 is front-padded to whole 256-sample frames (end alignment); CREPE-tiny uses torchcrepe framing and RVC decoding; PESTO streams through a `SliceTracker` (import-only model). RMVPE log-mel exports run as a fixed-shape `gpu::plan` (always on DirectML; on CUDA with `io_binding` + `cuda_graphs`, as a CUDA graph), falling back to the plain session; since P3B-E the plan is built once at load from the file's protobuf metadata (no plain copy first), shared across hot voices and never grown ([Voice-engine optimization](#voice-engine-optimization-p3b)). RMVPE's mel is **end-aligned** in its padded length (the silence floor `ln(1e-5)` before the audio, where RVC's `mel2hidden` appends zero log-mel after it, a loud flat spectrum the BiGRU carried into the newest frames of every short incremental call; measured by `engine::f0_cache::tests::lead_sweep_against_whole_clip_f0` and the P3 final gate's benchmark, [VC_BENCHMARKS.md → P3 final gate](benchmarks/VC_BENCHMARKS.md#p3-final-gate-pitch-track-fixes)). FCPE keeps the F0 cache's default lead-in: a 20-frame lead-in improved its pitch track but lowered DNSMOS on the benchmark (same section). `F0Post`: octave island gate, edge-replicating median, `F0Limits` (speech 50–1100 Hz, singing 50–2500 Hz). **Fusion** takes voicing from SwiftF0 and pitch from RMVPE on a GPU (FCPE on the CPU); its rule and constants are in the `f0_fusion` module docs (`FuseParams`). A/B: `f0_fusion::ab` (synthetic corpus with exact truth, offline and streaming through `engine::f0_cache`), `ab::report` for a future benchmark `pitch_ab` mode, dev-rig tests `pitch_ab_report` and `fusion_sweep`.
- **Retrieval** (`vc::engine::retrieval`): the CPU IVF search runs on a persistent pool (at most 4 threads, 1 on Streamer, used above 1.5 M multiply-adds per tick), bit-identical to serial and allocation-free. The GPU kNN is the bundled `knn.fp32/fp16.onnx`, found by feature width and sha256-checked; index and norms are bound once and the search is exact over every row (fewer than 8 rows refused, fewer than 64 padded, the CPU rung refused; component `vc.knn`).
- **Post stage** (`vc::engine::post`): `rms_mix` (RVC's 40 ms / 10 ms envelopes, gain capped at +20 dB), the cepstral formant shift (`vc::formant`, ±12 semitones, F0 kept within 5 cents, frames anchored to the tick end, no added latency), the silence gate on the input level `silence_db` (2 ms attack, 20 ms release, hangover) and the limiter (−0.3 dBFS, 1.5 ms look-ahead); gate and limiter state follow absolute time across overlapping ticks. `chunk_processor::rvc_output_tilt` applies the legacy one-pole tilt only while the formant shift is 0, so the two never stack. `vc::autokey::AutoKey` (a transpose suggestion from the voiced F0) is implemented but not wired yet.

#### Denoisers, timeline and metrics (P3-E)

- **Denoisers** (`neural_audio::denoise`, CPU EP): `gtcrn` (16 kHz, one 512-point STFT frame plus three caches; about 16 ms of overlap-add plus up to one hop) and `dpdfnet` (48 kHz, about 50 ms plus hop fill); a stored `dfn3` runs DPDFNet with a `denoiser_warning` (the published DeepFilterNet3 ONNX keeps its GRU state internal and cannot stream frame by frame). Both are included in `metrics.e2e_ms`.
- **Timeline** (`voice_changer::timeline`): a lock-free seqlock broadcast ring of 4096 `VcTick` entries (QPC ns; flags `ERROR`, `UNDERRUN`, `BUDGET_DROP`, `GAP`, `GOVERNOR_STEP`, `SILENT`); `publish()` is a no-op without subscribers (the live record subscribes).
- **Metrics:** `process_p50_ms` / `process_p95_ms` over a 512-block window; `e2e_ms` = the median of first playout + owed frames + the harness's algorithmic latency (identity probe) + the denoiser delay + the model's lookahead − the capture time of the block's newest frame (exact for RVC; the classic, ONNX and sidecar modes leave out their engines' own delay); `vram_mb`, `governor_level` and `levers` are null while stopped. New `voice_changer:error` codes: `device_lost`, `device_restored`, `denoiser_warning`, and `rvc_load` while running (a switch failed; the current voice keeps playing).

#### Voice-changer frontend (`src/core/services/voice_changer`, P3-G)

- The service is the only writer of the params: the library never calls `set_active_slot` or an import's `activate`, voice selection goes through the params sync. `restart.ts` decides per param and mode whether a change is hot, a switch (voice, F0 method and F0 range swap without a restart in RVC mode, matching the worker's `VoiceSet`), a restart (engine shape: block, lookahead, levers, precision, context, …) or idle, judged against the params the engine started with; concurrent changes restart once.
- `options.ts` builds every choice from `voice_changer_get_capabilities`; a stored value this build cannot run stays visible with what runs instead (Rust's own fallback rules). `requirements.ts` maps voice / F0 / EP / denoiser to model-store ids (the first-run card). `presets.ts` holds Streamer / Low latency / Quality / Studio-TRT (each preset's EP equals the contract's `default_ep`). `library.ts` runs imports one at a time (progress events belong to the running job); `bench.ts` / `tuning.ts` drive autotune, "Benchmark this PC" (a paced run through `plugin:bench|run_benchmark`, its spec checked field by field against `bench/spec.rs`) and live recording.
- **Voice hotkeys** (`hotkeys.ts`): `BackendState.shortcuts.{vcToggle, vcNextVoice, vcPrevVoice, vcVoice1..4}` plus `BackendState.vcHotkeyVoices` (slot ids of hotkeys 1–4, P3-I0 schema); the keyboard service dispatches them to `VoiceChangerService.runShortcut`.

#### Zero-shot and singing families (P3-H)

`scripts/vc-families/{seed_vc,ddsp_svc,meanvc}/` export Seed-VC realtime, DDSP-SVC 6.3 and MeanVC2 to ONNX with reference Python samplers and parity scripts (≥ 35 dB SNR); the go / no-go per family, graph I/O specs and costs are [ADR 0006](adr/0006-vc-zero-shot-singing.md). The in-engine ports are P5 (next section).

#### Voice-engine optimization (P3B)

P3B measured first and found the per-call cost to be overhead rather than arithmetic (about 1 ms of GPU math against 9.6 ms measured; [ADR 0010](adr/0010-sve-optimization-p3b.md)). Every change below has a kill switch (rule R5); the ones that can lower fidelity ship off (rule R6). Evidence and numbers: [docs/benchmarks/VC_BENCHMARKS.md → P3B](benchmarks/VC_BENCHMARKS.md#p3b-voice-engine-optimization-p3b-i0); per-workstream commands: `scripts/bench/specs/p3b/<a..h>/README.md`.

- **Engine layout.** `vc/engine/mod.rs` holds the types and the `VoiceConversionModel` impl; `load.rs` the load (final shapes, parallel branches, generator build, replan), `tick.rs` the per-tick convert, `overlap.rs` the F0 helper thread, `content_stats.rs` the running content statistics, `probe.rs` the benchmark's inert probe (`active()` is false in the app; every hook is skipped unless it is). `neural_audio/telemetry.rs` is a no-op, allocation-free recorder (stage and load spans, syncs, GPU time, VRAM marks) that only a benchmark turns on. `StageRecord` / `FedF0` / `ModelTelemetry` in `vc/traits.rs` are how the bench reads a voice's stages and fed F0.
- **Content encoder as a plan** (`engine::content`, P3B-D). ContentVec runs as a `gpu::SessionPlan` at the content window's length (pinned dimension, IOBinding, a CUDA graph checked at build; one whole compiled graph on DirectML). Plans are keyed by `(length, levers)` inside the pooled encoder, voices hold a `ContentLease`, and the dynamic session is released once only plans use the encoder. An encoder that has a dynamic session is checked against it at build (relative L2 ≤ 2e-2); a deferred encoder (the production GPU path) is checked against a CPU-EP session of the same file on a helper thread (relative L2 ≤ 0.1, verdict cached per process, a failing plan falls back to the dynamic session). #### Voice families (P5)

Voices beyond RVC run behind the same `VcStreamHarness`, latency budget, timeline, metrics, TTS aux path and hot-voice set as RVC voices. Measured status: [VC_BENCHMARKS → P5 voice families](benchmarks/VC_BENCHMARKS.md#p5-voice-families); decisions: [ADR 0006 → P5 outcomes](adr/0006-vc-zero-shot-singing.md#p5-outcomes).

- **Registry** (`vc::families`, `mod.rs`): `FamilyKind {DdspSvc, SigilZs, MeanVc, Sovits, SidecarV2}` ↔ `manifest.format` (`ddsp-svc-6.3`, `sigil-zs-1`, `meanvc-2`, `sovits-4.1`, `sidecar-v2`). Every family module implements `available()`, `info()` (`FamilyInfo`: experimental / zero-shot / singing flags, EP rungs, whether it needs the pitch extractor or the shared content encoder, how slots are made (`reference`, `import`, `sidecar`), import extensions, the controls it answers, model-store requirements), `create(FamilyRequest) -> FamilyEngine`, `check_slot`, `normalize_options` (typed options in `manifest.family`), `create_slot` and `run_import_job` (the isolated `vc-import-worker` body for untrusted checkpoints). A family module may grow child modules in `families/<x>/`. A family slot holds `manifest.json` (format, name, `family` options), whatever the family imports, and `slot.json` (per-voice settings, `reference_voice_id`).
- **Factory** (`voice_changer::factory::create_family`): refused by name when the family is not in the build, does not run on the EP rung, or (made from a reference) has no reference; builds the pitch extractor only when `needs_pitch` (with the governor's light-F0 switch), adds no post stage (families that answer `rms_mix` / `formant` run `engine::post::PostStage` themselves) and carries the family's EP outcomes, lever notes, warnings, `model_delay_16k` and reference embedding into the voice. `LoadedVoice::load_cancellable` installs the reference and `SingingFlags::from_range(f0_range)` in the harness (`ConversionCtx::{reference, singing}`). The in-harness GTCRN denoiser is skipped with a warning for a model whose input is not 16 kHz (P5-I0; it used to leave the voice silent). A load nobody wants any more is called off: `EngineRequest::cancel` → `FamilyRequest::cancel` carries the flag of a background load (`VoiceSet`, set when another voice is selected) and of the worker's first load (set by Stop or a newer start, checked every 100 ms), so a sidecar voice stops waiting for its helper's start or handshake at once and the worker's first load ends quietly (no `rvc_load` error).
- **Output buffer** (P5-I0, per voice since the P5 final gate): `families::min_output_buffer_ms(kind, ep, manifest)` is the smallest prefill / queue a voice of a family plays with (each block computes in one 15–60 ms burst, and the default 35 / 70 ms ran dry 0–527 times per 20 s): Sigil-ZS per preset and EP (`sigil_zs::min_output_buffer_ms`: `sigil_low` 95 / 165 ms on CUDA, 85 / 155 on DirectML, `sigil_lean` 80 / 150, `upstream_readme` 120 / 190 and 125 / 195; never below 80 / 150, the prefill always below one 100 ms burst), MeanVC2 80 / 150 for its 160 ms tick only, DDSP-SVC 70 / 140 as the fallback. A loaded voice that knows its need better returns `FamilyEngine::min_output_buffer_ms`, which wins (DDSP-SVC from the EP its graphs landed on: 70 / 140 for the 100 ms presets on CUDA, 80 / 160 on DirectML, 100 / 200 and 150 / 300 for `upstream_gui`). It travels as `CreatedEngine` / `LoadedVoice::min_output_buffer_ms`; the worker's `port_limits` plays the active voice with the larger of it and the user's, and the benchmark's paced runs do the same (`EngineInfo::min_output_buffer_ms`). The timeline and `e2e_ms` measure the real queue, so the raised buffer is counted.
- **Output queue floor of template voices** (`voice_changer/block_buffer.rs`; found by the P7-B review, where the CPU rows played 48-63 % of the audio they converted). A template voice runs its model once per engine block `B`. When `B` is longer than the device chunk `D`, the synchronous worker pushes one chunk per tick for `B/D - 1` ticks and then spends the whole model call (p50 74-81 ms idle and 88-98 ms under the game stand-in at 120 ms blocks on 6 threads; p99 90-106 and 98-130 ms) pushing nothing. If the queue stands shorter than the call, the device runs dry, `OutputPlayback` starts a recovery, and while recovering every push trims the queue to `ring_target()` (gate level + last chunk + capture burst + 1.3 ms, 57 ms at the 35 / 70 ms default), which discards the catch-up burst (about 45 ms of each 120 ms block); the next call dries the ring again, so the recovery never ends. All of the trimmed audio is recovery trim; the cap (`queue_cap`) and drift trims remove nothing, so **raising only `output_max_queue_ms` does nothing** (35 / 170 and 35 / 300 replay identically to 35 / 70; the `playback.rs` test `a_burst_workers_loss_is_a_recovery_trim_that_only_the_prefill_removes` pins it with a burst worker, and the `bench/paced.rs` test `a_burst_engine_loses_audio_at_the_default_buffer_and_plays_it_with_the_floor` end to end). The prefill is the lever, because the gate level and `ring_target()` follow it. The rule (pure; `min_output_buffer_ms(block_ms, chunk_ms, on_cpu, enabled)`): `n = ceil((B - 0.4) / D) - 1` pushes happen before the first model call (`pushes_before_first_call`: 11 at 120 ms blocks on 512 frames, 3 at 40 ms; 0.4 ms is `FIXED_LEAD_16K` plus the input resampler's jitter), `prefill = min(ceil5(0.9 B), floor5(n D - 2))` on a 5 ms grid, no floor when that is not above the 35 ms default, and `queue = ceil(prefill + 2 D + 4)`. The first term covers the call (an assumed real-time factor of 0.9; the benchmark rig measures 0.74-0.89 idle), the second is the trap guard: **never size a prefill above `n D - 2`**, because the prefill gate would open after the first call and the queue would stand 20-40 ms higher for the whole run. 120 ms blocks on 512 frames at 48 kHz give **110 / 136 ms**. The 40 ms reference shape (n = 3, limit 30 ms), the app's 20 ms blocks and any block of 40 ms or less give none.
  - **Wiring.** `create_sigil` computes the floor from the realized generator rung (the `vc.flowdec` outcome's active EP, so a GPU request that fell back to the CPU counts; strictly `cpu`, since `tensorrt` is a GPU rung; the requested EP when there is no outcome), the engine's fixed block and the request's `chunk_frames` / `device_rate`, stores it in `CreatedEngine::min_output_buffer_ms` and adds a lever note ("output buffer: at least 110 / 136 ms for 120 ms blocks on the processor ...") and a `tracing::info!` line. `LoadedVoice::load_cancellable` sizes it again after `merge_stream_report`, because the stream configure may rebuild the generator on the CPU. The worker's `port_limits(h, floor, custom_cannot_play)` (floor = the active voice's `VoiceFloor`: its minimum, and `block` for a `SlotFormat::SigilRvc` voice) and the benchmark's `EngineInfo::output_buffer_ms` play the active voice with the larger of the floor and the stored values, so `sve-cpu`, `sve-cpu-pool`, `sve-cpu-t6`, the H3 run, the autotuner and "Benchmark this PC" size the queue like the app; the benchmark also hands the floor to the adaptive cushion (`OutputSide::with_voice_floor`, as `OutputPort::set_limits` does), so an adaptive run cannot shed below it.   - **Result** ([VC_BENCHMARKS.md](benchmarks/VC_BENCHMARKS.md#re-run-with-the-floor), three passes, 120 ms blocks, 6 threads on the 8-core dev rig): `sve-cpu`, `sve-cpu-pool` and `sve-cpu-t6` play 99.1-99.8 % of the converted audio in the paced and the H3 game-load runs (worst single pass 98.8 %, against 48-63 % at 35 / 70 ms), with 0-0.42 s of dry output per 60 s run, nothing dropped, `engine.min_output_buffer_ms` = `[110, 136]` in every CPU report and absent from the CUDA report; latency p50 265-278 ms, p99 273-305 ms (T1's 280 ms under the game is missed: 305 ms for the Streamer policy, 288 ms for the pool, 295 ms for 6 threads). With `SIGIL_VC_BLOCK_BUFFER=0` the same build plays 65.8 % again. The 4-thread policy and FCPE were not re-run with the floor. Judge a CPU row on `played_ratio` and dry output before its RTF or latency.
  - **Stored values.** Nothing is rewritten: `settings.json` / `slot.json` keep the user's numbers and the sliders show them. The rule is in `worker::port_limits` and `block_buffer.rs` and is tested row by row (`the_stock_buffers_are_raised_to_the_block_floor`, `a_typed_buffer_stays_unless_the_run_proves_it_cannot_play`): (1) the **stock buffers** (Low latency 35 / 70 ms; Stable 80 / 150 ms, which `apply_params` forces whatever numbers came with it; recognised by `params::output_buffer_is_stock` and stored in the hot params as `output_buffer_stock`; a Low latency label over other numbers counts as typed) are raised to `clamp_output_buffer_ms(max(stored prefill, floor prefill), max(stored queue, floor queue))`: at a floor of 110 / 136, 35 / 70 becomes 110 / 136 and Stable 80 / 150 becomes 110 / 150; (2) a **typed** buffer (latency preset `custom`, which the UI sets on the first edit of either number) is the user's choice and stays as it is, 5 / 10 included, **unless the run proves it cannot play a block**. The proof (`block_buffer::StoredBufferProof`, fed by the worker with the model time of every RVC tick, ticks of three chunks or more counting as calls): once at least 16 of the last 33 calls are known and their median is longer than the stored prefill, the output keeps a queue of about the prefill while nothing is pushed for the whole call, so it runs dry in more than half of the blocks and its recovery trims the catch-up of each. The verdict is latched for that stored value (a different value is judged anew; another voice with another floor resets the window), the worker logs it once, and from then on the typed buffer is raised like a stock one (at a floor of 110 / 136: 60 / 65 becomes 110 / 136, 100 / 200 becomes 110 / 200, 115 / 120 becomes 115 / 136); a larger value (120 / 240, 150 / 300, 300 / 600) is never touched in any state. The criterion is the knee of the burst-worker simulation, not a guess: `playback::tests::the_proof_criterion_is_the_knee_of_the_burst_worker` runs 70-110 ms calls against five buffers and requires that wherever the proof raises, the simulated output loses at least 1 % of the audio and runs dry in at least 100 callbacks of the minute, and wherever it does not, at least 98 % is played; it also agrees with the replay of the recorded runs (replayed through a port of the output queue, not run at those sizes: 60 / 120 plays 84 / 71 % paced / game, Stable's 80 / 150 98 / 88 %, 100 / 125 at least 98.3 % in every pass). Borderline values just under the call (80 / 150 against 78 ms calls loses 1.3 % in the simulation) are left to the user. A voice family's minimum is not a template voice's: it raises every stored value, as before. The adaptive cushion's floor is the voice's prefill when the floor applies (so at the stock defaults it is a no-op on a CPU template voice: floor and cap are equal) and none for a typed buffer that stays. A hot switch between voices with different floors re-gates once (one short dropout). A stored prefill above the first-call limit (118 ms or more at 120 ms / 512 frames) plays everything but stands 20-40 ms higher: the "dry-free" choice. The **benchmark** has no Custom buffer (a spec's `stream.output_prefill_ms` / `output_max_queue_ms` stand for the stock one), so it always plays with the floor: an Autotune candidate measured with a typed buffer below the floor reports the floored latency, which the app reaches by the proof when the buffer cannot play.
  - **Trade-offs.** Calibrated on one rig (Ryzen 7 7800X3D, 8 cores, SwiftF0): the cover term is an RTF assumption, so faster CPUs and autotuned configurations (RTF 0.5-0.6) are over-provisioned by 30-50 ms at long blocks (at 200 ms blocks the call is about 128 ms and the floor is 180 / 206) for the stock buffers, while a typed buffer that plays is left alone. The trap guard wins over the cover when they disagree (a call longer than about 108 ms: the 4-thread policy at RTF p99 0.96, FCPE on 6 threads at 0.97): the prefill stays at the first-call limit, and the slowest calls of each minute leave a dry hold and a recovery (a call 10 ms past the prefill loses 1.4 % of the audio in the simulation when every call is that long, `playback::tests::a_call_ten_ms_past_the_prefill_costs_a_little_audio_not_all_of_it`); those shapes were not re-run with the floor. A CPU whose call is longer than the block cannot be fixed by any buffer (the 300 ms latency budget drops audio): the one-thread "Protect game FPS" Streamer, RTF 2.6. The device's callback period needs no term of its own: `OutputPlayback` stands the queue's valley a callback above the gate (`ring_target`, `drift_slack`), and `playback::tests::a_longer_device_callback_needs_no_larger_floor` plays 90-110 ms calls at 110 / 136 ms with no dry callback on 10, 20, 30 and 40 ms callbacks. The headless benchmark and the replays cannot see WASAPI or Bluetooth timing, so a live listening check on a real device is still open.
- **Streamer block on the processor** (`presets::cpu_streamer_block`, `CPU_STREAMER_AUTO_BLOCK_MS` = 120, `CPU_STREAMER_KEEP_FROM_MS` = 60). With the **Block size** on Auto (`block_ms` 0) the engine derives its block from the device chunk: 10.67 ms at the default 512 frames, which the plan rounds to 20 ms. On the processor each model call has a large fixed part whatever the block: a 20 ms block measured RTF p99 3.8 on 6 threads (one headless paced run, 40 s: call p50 57 ms, p99 76 ms, 26 s of 40 s of input dropped, latency p99 515 ms; a straight line through the 120 and 200 ms rows had predicted 45-85 ms), and a voice that cannot keep up falls behind for good. So for the **Streamer** profile on the CPU rung with no block set (a request of 0 or less) a derived block shorter than 60 ms becomes 120 ms, the shape every CPU row of the benchmark measures; an explicit block, a derived block of 60 ms or more (a deliberately big device chunk), every other preset and every GPU rung are left alone. `create_sigil` and `bench::rvc_build::build_sve` both apply it (so a bench spec that leaves `block_ms` out measures what the app runs), the worker's `run_chunk_frames` treats it as an explicit block for `device_block = model_divisor`, a lever note ("block: 120 ms (automatic for the Streamer on the processor ...)") and an info log line say so, and `SIGIL_VC_STREAMER_BLOCK=0` (`0` / `off` / `false` / `no`, any case) restores the derived block. The trade-off is delay, not fidelity (the block is only how much new audio each call takes): about 270 ms end to end at 120 ms, against a voice that breaks up at 20 ms. Pinned by `the_cpu_streamer_takes_a_long_block_only_when_none_is_set` (`presets.rs`); the end-to-end check is one headless paced run with the block left out ([VC_BENCHMARKS.md](benchmarks/VC_BENCHMARKS.md#the-streamer-button-and-the-automatic-block)).

#### Voice library (`voice-library`, P5-F)

- **Layout:** `app_data/voices/<id>/{ref.wav, meta.json, cache/<backend>.bin}`. `ref.wav` is 16-bit mono at the source rate (at most 48 kHz), normalized to −20 LUFS (BS.1770-4) under a −1 dBFS peak (no limiter: a clip that reaches the peak first stays quieter, and its measured loudness is in `meta.json`). `meta.json` is `VoiceMeta` (camelCase). Ids are never reused; writes are atomic under one library lock with staging and trash folders.
- **Rust API** (`services::voice_library`): `voices_dir`, `valid_voice_id`, `voice_dir`, `list_voices`, `reference_clip` (the sha256 is read from the file, so a re-recorded clip invalidates every cache), `read_cache` / `write_cache` (used by `families::reference::cached_embedding`).
- **Recording** goes through the capture hub at the device rate in its own consumer (no mute group; `recorder::consumer_options()`), with level, peak, clipping and Silero speech count at ≤ 20 Hz; it stops at its length limit (12 s), on a device format change, a stream restart or backlog drop (`interrupted`, keeping the audio so far), a lost device or no audio. WAV, FLAC, Ogg and MP3 files go through the same pipeline: a 40 Hz high-pass, Silero trimming (speech plus pads, long pauses spliced, at most 10 s, cut at a pause), clipping / peak / SNR checks, loudness normalization. `no_speech` and `too_short` block saving; the other issues are warnings.
- **IPC:** 12 commands `voice_library_{list, get, record_start, record_stop, record_cancel, import_clip, read_take, read_clip, discard_take, save_take, update, delete}` (`read_*` return binary WAV), events `voice_library:changed` and `voice_library:record_progress` (`stopped` / `stopReason`).
- **Transcripts** come from the local STT in the background with installed models only (never a download), one job at a time; a user edit wins over a late automatic result; `transcriptError` is `no_stt_model`, `failed` or `empty`; a detected language is stored when none was given.
- **TS:** `@/core/services/voice_library` (`voiceLibraryUi` (valtio), `ensureVoiceLibraryHost`, `refreshVoices`, `startRecording`, …; not an `ApiServer` service); the UI is `<ReferenceVoiceRecorder>` / `<ReferenceVoicePicker>` in `src/core/ui/inspector/components/ReferenceVoiceRecorder.tsx` (`compact` draws no frame; P6 mounts the picker with `needsTranscript` for TTS cloning).

### Speech pipeline (`speech`)

`speech/pipeline.rs` (plugin `speech`) runs keyed pipelines (`mic`, `loopback`; the crate-internal `legacy-whisper` key serves `whisper::start_recording`): a capture-hub `Raw16kMono` consumer gated by the source's mute group (`MuteGroup::Stt`, or `Others` for `loopback:*`), the Silero segmenter on one capture thread, then one of three routes: **finals-only** (an ordered utterance worker), **streaming** (a stream worker that also hosts the two-pass queue) or **capture-only** (`captureOnly: true`, or no engine with `retainPcm`).

- **IPC:** `start_pipeline { config }` → `{ pipelineId, epoch, plan }` (resolves once the engines are loaded and the device is attached; its status events may arrive first, so drivers accept the first epoch above the one they last stopped), `stop_pipeline { pipelineId, epoch? }` (with `epoch` only that session, while it is still the key's current one, and no queued start is cancelled: the HTTP driver's late cleanup stop uses it), `get_pipeline_status`, `take_pipeline_utterance { pipelineId, segmentId }` (binary f32le PCM, once), `preview_route { request }` (plans without installing anything). `PipelineConfig` (camelCase, every field optional): `pipelineId`, `source`, `vad`, `language`, `route`, explicit `streaming` / `final` engines (they bypass the router), `smartTurn`, `hotwords`, `prompt`, `hallucinationFilter`, `latencyBudgetMs`, `maxBacklog`, `retainPcm`, `captureOnly`. Mirrors: `RustSpeech*` / `SPEECH_EVENTS` in `src/types.ts`.
- **Events** (`speech::events`, every payload carries `pipelineId` + `epoch`): `speech:partial`, `speech:final` (`pass` first / second, `tags`, `startMs` / `endMs`, `forced`, `latencyMs`, `turnEnd`), `speech:status` (`state` starting / loading / listening / stopped / error, `code` from `events::codes`, `detail`, `progress`, `level`, `modelId`), `speech:utterance` (kind `speech_start` / `utterance` / `dropped`), `speech:turn_end`. The TS segment id is `<pipelineId>-<nonce>:<epoch>:<segmentId>`, where the nonce (`PROCESS_NONCE`, `src/utils/processNonce.ts`) is random per process so ids stay unique across restarts and linked hosts; translation line ids carry the same nonce.
- **Epoch discipline:** each key has an emit lock and an epoch; every start, stop and fatal error bumps the epoch under the lock and every emit happens under it with the epoch checked, so no event of a stopped session is ever delivered, and the last event of an epoch is status `stopped` or `error`. Segment ids come from a per-key counter that is never reused; a segment book keeps revisions strictly increasing in emit order.
- **Terminal rule:** with an engine, every closed utterance ends with at least one final or exactly one `dropped`; a segment with a final is never dropped and vice versa. Drop reasons (`RustSpeechDropReason`): `backlog`, `latency_budget`, `muted`, `no_speech`, `merged` (the previous segment's final carries this text), `engine_error`, `rate_limited`, `stream_skipped`, `queue_full`.
- **Mute and gaps** (`mute.rs`): the hub withholds muted audio; at the mute edge the open utterance ends with `muted` and is never decoded. Other gaps (restart, device move, overrun) close it as forced, decode it and warn `capture_gap`. Segment times follow the capture clock (QPC) across mutes and device restarts.
- **Utterance worker** (`worker.rs`, `utterance.rs`): drop-oldest queue of `maxBacklog` (default 3); latency budget 20 s by default (1–120 s); merge on backlog (up to 28 s, 200 ms of silence between utterances); an optional `BatchPolicy` hold (the Groq billing minimum: 3.5 s, or 8 s while the next utterance is being spoken); language ID first in auto mode; a CPU fallback replaces a failing GPU engine for the rest of the session. Fatal error kinds stop the pipeline; transient ones only warn, until 5 fail in a row.
- **Stream worker:** partials at most every 80 ms and only when the text changed, then the first-pass final; the two-pass job is submitted after that final (so the replacement has revision + 1). A stream more than 3 s behind skips partials for that utterance; no sample goes to two streams, even across a forced split. A stream that needs a language waits for a detected one only when a two-pass final covers the utterance.
- **Language:** an explicit language goes to every engine; with `auto`, utterance engines detect it unless the route has a language-ID engine, and a streaming engine that needs one uses the latest detected language.
- **Tests** inject `SessionDeps` (source, segmenter, engines, router, second pass, turn detector, sink): `cargo test speech::pipeline` needs no device, model or network; `real_model_whisper_transcribes_through_the_pipeline` (ignored) runs real Silero and Whisper tiny.en with `SIGIL_TEST_MODELS_DIR`.

### STT engines

`speech::engines::create(&EngineSpec, &EngineContext)` dispatches on `EngineKind` (`whisper`, `http`, `sherpa-online`, `sherpa-offline`, `transcribe`); creation blocks (model load), engines never download (`NotInstalled` names the catalog id), and `engines::requirements` lists the catalog ids an explicit spec needs (the transcribe engine adds the runtime pack this PC would use, plus `runtime/nvidia-cuda13` for `cuda13`). The `AsrEngine` trait (`speech::engine_api`) has `transcribe` plus optional `begin_stream` / `push_stream` / `end_stream` / `abort_stream` and a `canceller`; tags are `<kind>:<value>`.

- **Whisper** (`engines/whisper.rs`): one reused `WhisperState`, `single_segment`, `no_context`, `suppress_nst`, a token cap scaled to the utterance, the prompt / hotword token cache, OpenAI's start-of-transcript no-speech probe (whisper.cpp's own value is stale for multi-token prompts, so its internal skip is off), abort through a cancel generation, Cantonese (`yue`) mapped to `zh` except on large-v3. Model resolution: the model store, then the legacy `whisper/` folder, then an absolute bring-your-own path. Options: `noSpeechThreshold`, `preset: "anime-whisper"` (Japanese bring-your-own).
- **HTTP** (`engines/http.rs`): presets `openai` (hand-written multipart), `groq` and `moonshine` (base64 JSON after a `/health` probe); options `preset`, `baseUrl`, `model`, `apiKey` (only in the Authorization header, never logged or echoed; `PipelineStarted.plan` strips secret-looking keys), `language`, `prompt`. 429 honours `Retry-After` (an HTTP date falls back to 5 s); 408, 425, 5xx and network errors retry 4 times with 1–2–4 s back-off; other 4xx are fatal; every wait is cancellable. A process-wide Groq limiter (20 requests / min, 2,000 / day, 7,200 audio s / hour, 10 s billing minimum, a daily pace that asks the pipeline to merge) paces every session. `moonshine_stt.rs` reuses its Moonshine request code.
- **sherpa** and **transcribe**: see [CPU speech runtime](#cpu-speech-runtime-speech_rtsherpa) and [GPU speech runtime](#gpu-speech-runtime-speech_rttranscribe).

### STT routing, two-pass finals and Smart Turn

- **Routing table:** `src-tauri/model-catalog/stt-routing.json` (`routing` object, read by `speech::router` with `include_str!`; mirrored by `src/core/services/stt/router.ts`). Rows by normalized language (`speech::lang`: Cantonese tags, deprecated and three-letter codes), then `auto`, then `*`; the first usable `streaming`, `cpuFinal` and fitting `gpuFinal` model (VRAM the resource governor grants, `vramMb`, `minTotalVramMb`). Rules enforced in code whatever the table says: Cohere never for ja / zh / ko / ru / yue or auto; Nemotron always gets a language (in auto mode only next to a final that detects it, or a language-ID engine); sherpa models only for their catalog languages; GPU specs only on the GPU tier; fallbacks are CPU models; unpublished and not installed, or uncatalogued, models are never planned. Tiers: `auto` ("Best for my PC") keeps cards under 16 GB for a running GPU voice changer, `gpu` shares the card. Two passes on the CPU (and a GPU final's CPU fallback next to a CPU stream, else note `no_cpu_fallback`) need at least 6 physical cores and no voice changer that may use the CPU (a running voice changer on an unknown device counts). In auto mode the streaming spec carries `options.streamLanguages` (`STREAM_LANGUAGES_OPTION`: the detected languages whose own row streams with that model, never zh / yue); the pipeline opens a stream only for those, and other utterances get the final alone. `RoutePlan` lists `models`, `missing`, `vramMb` and `notes` codes (UI text `stt.route_note_<code>`; governor reasons `models.gpu.rec_reason_<code>`). To add a language or model: edit the table, add a case to `src-tauri/test-fixtures/routing.json` (shared with the TS mirror) and keep `table_models_match_the_catalogs` green.
- **Current table** (CPU unless noted): en → Nemotron 560 ms partials + Parakeet Ultra re-decode (Cohere on the GPU); European languages → Parakeet Ultra finals (GPU: Cohere or Qwen3-ASR 1.7B for de / es / fr / it / pt / nl, Cohere for pl / el); zh / yue → SenseVoice (GPU: Qwen3-ASR 1.7B), no live partials; ja → Nemotron partials + SenseVoice finals; ko → Nemotron partials + Qwen3-ASR-0.6B finals; ru → Nemotron partials + Parakeet Ultra finals; vi and the 30-odd languages only Qwen3-ASR covers → Qwen3-ASR-0.6B finals; ar / hi / tr / nb → Nemotron's own finals; auto → Qwen3-ASR detects the language and Nemotron follows it; other languages → Whisper. P7-A chose the CPU rows from its own-microphone campaign (clean plus the two microphone-side conditions; the bleed conditions play no part, user decision 2026-10-09): Russian moved from Qwen3-ASR 0.6B to Parakeet Ultra (WER 7.3 against 22.1) and Japanese from Qwen3-ASR 0.6B to SenseVoice (CER 6.8 against 10.0); English, the other Parakeet languages, Korean and Chinese were confirmed ([benchmarks/SPEECH_BENCHMARKS.md → The defaults this campaign sets](benchmarks/SPEECH_BENCHMARKS.md#the-defaults-this-campaign-sets)). The GPU rows and the BF16 / Cohere VRAM figures are still vendor tables and P2-D's measurements (opt-in, not benchmarked in P7). The shared fixture `test-fixtures/routing.json` and both router test suites encode the table.
- **Interim results** (`stt.local.interim`, default on; `RouteRequest.interim`, serde default true): off, the local backend publishes finals only and the route drops a streaming model that runs next to a final engine (English on 8 cores: Nemotron + Parakeet Ultra becomes Parakeet Ultra), so the streaming model is not downloaded, loaded or run; a language whose only engine is a streaming model keeps it and still publishes its finished sentences. The setting is read at each start.
- **Two-pass** (`speech::two_pass`): re-decodes the whole closed utterance under the same `segmentId` with revision + 1. Budget 1.5 s + 0.5 s per audio second, at most 8 s (a job with no first-pass final gets 20 s); a queue of 4 evicts the oldest replacement first, never an utterance's only final; the first GPU failure switches the rest of the session to the CPU fallback (`promoted_fallback`) and frees the GPU engine. Skip reasons: `budget`, `queue_full`, `empty`, `cancelled`, `engine_error`.
- **Smart Turn** (`speech::smart_turn`, `vad/smart-turn-v3.2`, BSD-2-Clause, 8.7 MB, `model-catalog/smart-turn.json`): Sigil's ORT on the CPU with 2 threads (component `stt.turn`), about 30 ms per non-forced pause. Input: the last 8 s, start-padded, normalized, Whisper 80 × 800 log-mel (matches transformers' extractor within 2e-3); an unfinished utterance within 3 s is joined in front of the next. It is a commit hint only (`speech:turn_end` at probability ≥ 0.5, copied to `turnEnd` on later finals) and never shortens, splits or delays caption finals. Real-model tests read `SIGIL_TEST_MODELS_DIR/smart-turn/smart-turn-v3.2-cpu.onnx`.

### TTS sink (`tts-sink`)

`tts_sink` (plugin `tts-sink`) is the one output of every PCM TTS backend and of `Service_Sound`: one persistent cpal output stream per device and a scheduler thread that keeps a ring about 200 ms ahead of playback, each sample tagged with its utterance, so stop and skip act at once, even on audio already in the ring.

- **IPC:** `begin_utterance { spec: { id, target: { route, device, volume } } }`, `push_pcm` (raw little-endian f32 body with headers `x-sigil-utterance`, `x-sigil-sample-rate`, `x-sigil-channels`; no JSON number arrays), `end_utterance { id }`, `cancel_utterance { id? }`, `flush_sink`, `get_sink_status`. Rust producers use `tts_sink::{begin, writer(id).push(..), end, cancel}`. Events `tts_sink:utterance` (every state change: queued / playing / done / cancelled / error) and `tts_sink:state` (at most 4 Hz).
- **Order and flow:** utterances play strictly in begin order, across device and route changes; sentence joins are gapless with a linear crossfade. Back-pressure: the playing utterance may hold 30 s of unplayed audio and all of them 120 s; a push is accepted whole or waits, and cancelling ends the wait. A streamed utterance starts after 200 ms of audio; one whose producer is silent for 120 s fails. Resampling is stateful (rubato, exact lengths), plus channel adaptation and the gain.
- **Devices:** names match exactly, then ignoring case, then ignoring Windows' `N- ` renumbering, then by unique prefix (which adopts SAPI names cut to 31 characters); a SAPI audio-output token id (`...\AudioOutput\TokenEnums\MMAudioOut\{endpoint id}`, P6-J) resolves through the endpoint's friendly name. Idle streams close after 5 minutes; the default-device stream reopens on the next sentence after a Windows default change.
- **Routes:** `device`; `voiceChanger` feeds the voice changer's aux input in tagged blocks (the aux queue counts and cancels a sentence there with a 5 ms fade; the voice changer's 60 s cap and mic duck / mute still apply) and plays on the device while the voice changer is stopped; `both`. The old `voice_changer_push_aux_pcm` / `_wav` commands stay for compatibility (untagged clips are never cancelled by sink stop / skip). `plugin:audio|play_async` is gone.
- **Mic policy** (P6-J): `set_mic_policy { policy }` mirrors the voice changer's aux mic gate; with `mute` the scheduler closes `MuteGroup::VoiceChanger` while TTS flows into the voice changer (see [Windows SAPI into the sink](#windows-sapi-into-the-sink-and-the-tts-mic-policy-p6-j)).

### Local TTS (`local-tts`)

`local_tts` (plugin `local-tts`) runs Kokoro v1.0 (54 voices: en / ja / zh / es / fr / hi / it / pt-BR), Kokoro v1.1-zh (103 voices), 36 Piper voices and Kitten 0.8 through sherpa-onnx `OfflineTts` with C espeak-ng, serialized process-wide, on one `sigil-local-tts` worker thread (never the main thread; a unit test checks it). Commands: `list_local_tts_models`, `load_local_tts { model, threads? }`, `speak_local_tts { request, utteranceId }` → `SpeakReport` (pushes each sentence straight into the begun sink utterance), `synthesize_local_tts { request }` → f32le mono, `cancel_local_tts { utteranceId? }`, `unload_local_tts`.

- **Models** come from the model store (`model-catalog/tts-local.json`: 41 hash-pinned entries plus `runtime/sherpa-onnx`), a folder (`speech_package_v1` or an official sherpa package; the family is detected from the ONNX metadata and the folder validated in a child process first), or `hub:<repo>` (`HUB_CATALOG` maps KittenML 0.8 repos onto catalog packages; a drift test keeps it equal to the TS list). The vendored Kitten is the fallback when sherpa cannot load.
- **Engine:** jobs run in order, waiting sentences in the sink's play order; stop and skip cancel the running and waiting jobs; a model is freed after 10 minutes idle (an unload with a load waiting behind it keeps the model). The first sentence of a burst synthesizes its first clause on its own. Threads: `auto` = half the physical cores within 2–4.
- **Kokoro on Sigil's ORT** (`kokoro_ort.rs`, default since P2-I0): sherpa's text frontend runs through a tiny token-tap graph, and the real Kokoro graph runs on Sigil's ORT with the CPU memory arena. Same speech as sherpa-onnx (correlation 0.996–0.997, identical length) for about 22 % less CPU and a lower RTF (median 0.294 vs 0.319 on 4 threads at integration). `SIGIL_LOCAL_TTS_KOKORO=sherpa` runs Kokoro entirely inside sherpa-onnx; any failure of the hybrid falls back to it. The token tap is a few-KB ONNX written once per model to `%TEMP%\sigil-local-tts\`.
- Real-model tests: `SIGIL_APP_DATA_DIR` with the models (dev setup `%LOCALAPPDATA%\sigil-dev-cache\appdata-p2h`) and `SIGIL_TEST_MODELS_DIR` (SenseVoice for the intelligibility checks), `cargo test local_tts -- --ignored --test-threads=1`.
- The `neural-onnx-tts` plugin is legacy: the TS `neuralOnnx` backend speaks through `local-tts`.
- **P6:** the cloning engines Pocket TTS and Chatterbox Multilingual V3 live in this plugin (see [In-process cloning TTS](#in-process-cloning-tts-local-tts-p6-i)); `Loader::text_reader` lets a model rewrite request text before chunking (Kokoro's Japanese voices read kanji through the shared OpenJTalk reader when `text/jpreprocess-naist-jdic` is installed).

### OpenAI-compatible speech client (`openai-speech`)

`openai_speech.rs`: `POST {base}/audio/speech` (a base URL without a path gets `/v1`) with only the fields that are set, `extra` merged in (it may override anything but `input`), and the key only in a sensitive `Bearer` header. The response is decoded as it arrives: raw s16le PCM (rate from `Content-Type rate=` when present), streamed WAVs with placeholder sizes, several WAVs back to back and every integer / float / extensible format; MP3 / Ogg / FLAC answers are buffered and decoded with rodio; JSON or text answers fail with the server's message. A blocking hand-off thread pushes pieces of at most 0.5 s into the sink, so waiting for playback never counts toward the network timeouts: local or LAN servers get 60 s plus 1 s per character (at most 10 min) to the first audio and 60 s between chunks, remote ones 60–120 s and 30 s; an explicit `timeoutMs` is clamped to 1 s – 10 min. `openai_speech_cancel` (by id or all) and a cancelled sink utterance end the request within about 25 ms. `openai_speech_check` (`GET /models`: 2xx / 4xx reachable, 401 / 403 an error naming the key) and `openai_speech_list_voices` (`/audio/voices`, then `/voices`). `HttpSpeech` / `speak_http` also serve `melo_speak_to_sink`, `fish_speak_to_sink` and `neural_sidecar_tts_speak_to_sink`. Live test: `SIGIL_TEST_OPENAI_SPEECH_URL` (+ `_MODEL`, `_VOICE`) with `cargo test openai_speech_live -- --ignored`; the reference server is `scripts/neural-sidecar/tts_sidecar.py`.

### Shared LLM client (`src/core/services/llm`)

One OpenAI-compatible client for the AI transform and the translation LLM engine (P4-A; the contract in [`types.ts`](../src/core/services/llm/types.ts) is frozen, members may be added).

- **Modules:** `providers.ts` `resolveLlmEndpoint(settings, { inTauri? })` → `LlmEndpoint` (providers `bundled`, `gemini`, `openrouter`, `openai`, `custom`; missing key / URL / model, a bad URL, or a key with spaces or non-ASCII characters throw `LlmError("not_configured")` with a localized message; a pasted `…/chat/completions` URL is cut back and `localhost:11434/v1` gets `http://`); `client.ts` `createLlmClient(endpoint, deps?)` → `chat(req, { signal, onDelta })`, `complete(req, …)` (raw prompts), `listModels(signal)`; `transport.ts` (the webview `fetch` transport with `credentials: "omit"` and UTF-8-safe streaming, and the Rust proxy transport); `stream.ts` (incremental SSE parser: chunks may split anywhere, including CRLF pairs; chat, legacy completion and llama-server payloads); `sanitize.ts` (`cleanLlmOutput` strips reasoning, `<|…|>`, Gemma and `</s>` tokens; `visibleStreamText` never shows a half-received tag; `redactKeys(text, secrets?)` masks the endpoint's own key and `sk-`, `gsk_`, `x-goog-api-key`, `api_key=` patterns).
- **Transport rule (`auto`):** cloud providers use the webview; non-loopback `custom` hosts (LAN, and remote APIs such as Groq) use the Rust proxy (the CSP's `connect-src` allows `https:` and only loopback `http:`); `bundled` and loopback `custom` hosts use the webview with the proxy as `LlmEndpoint.fallbackTransport`: when the browser cannot reach a server, or Ollama answers the app's origin with 403, the client retries through Rust and remembers that origin (`resetLlmTransportMemory()` in tests). An explicit `webview` / `rust` choice is honoured without fallback; outside Tauri everything uses the webview.
- **Rust proxy transport:** `plugin:llm-server|llm_proxy_chat { request: { requestId, url, method, headers, body, stream, timeoutMs }, onEvent: Channel }` with events `response` / `chunk` / `done` / `error`, `llm_proxy_cancel { requestId }` on abort, a 3 s grace for events that arrive after the command resolves; a `not_implemented` error or no Tauri means "proxy unavailable".
- **Abort and errors:** every call honours `signal` and an abort rejects with the signal's reason, never an `LlmError`. A request deadline gives `LlmError("timeout")`, and a stream silent for 30 s is cut off. Kinds: `not_configured`, `unauthorized`, `rate_limited`, `timeout`, `network`, `server`, `bad_request`, `truncated`, `empty`, `unsupported`, with `status`, `retryable` and `retryAfterMs` (from `Retry-After` or Gemini's `RetryInfo`). Errors inside a stream (OpenRouter's, llama-server's `error:` lines, Gemini's array-wrapped errors), a server that ignores `stream`, and HTML answers are detected; messages are redacted.
- **Body mapping per provider:** OpenAI gets `max_completion_tokens`, others `max_tokens`; OpenRouter gets `reasoning: { effort }` (and attribution headers), others `reasoning_effort`; Gemini 3 cannot disable thinking, so `none` is sent as `minimal`; the bundled server's `none` becomes `chat_template_kwargs.enable_thinking = false`; `top_k`, `min_p` and the repetition penalty go only to providers that accept them; `extra` is merged last. Raw completions (`complete`, e.g. Seed-X, MiLMMT) use llama-server's native `/completion` (`n_predict`, `cache_prompt`) on the bundled server, `/completions` elsewhere, and are `unsupported` on Gemini. `listModels` reads the OpenAI, Gemini (`models/` prefix stripped) and Ollama list formats.
- **Keys** travel only in headers (`Authorization: Bearer`, Gemini `x-goog-api-key`), never in URLs or logs.

### Local model server (`llm-server`)

`src-tauri/src/services/llm_server/` (P4-B) runs llama.cpp's `llama-server` through `process_host::recipes::llama_server` ([ADR 0005](adr/0005-process-host-llama.md)) for the GGUF translation models in `model-catalog/llm-gguf.json` (family `mt-llm`; its `routing.models` table carries prompt format, role, availability, languages, directions, KV size and the authors' sampler).

- **Commands:** `llm_server_start { config }` → `{ status, endpoint }`, `llm_server_stop`, `llm_server_status` (never contains the key), `llm_server_endpoint` → `{ baseUrl, apiKey, model }` or null, `llm_server_logs { limit? }`, `llm_server_plan { config }` → `LlmServerPlan`, `list_llm_models` (`LlmModelInfo` with `role`, `availability`, `directions`, `sampling`, `description`, `license`), event `llm_server:state`. Config: `model` (`auto`, a catalog id or an absolute `.gguf`), `variant` (`auto` / `vulkan` / `cuda13` / `cpu`), `ctxSize`, `gpuLayers`, `flashAttn`, `allowOverBudget`. Errors are `{ kind, message, missing }`.
- **Lifecycle** (`server.rs`): one server at a time; a start gate, a stop epoch and generations make a stop during a slow model load cancel the start; a watcher (every 400 ms) follows the helper; the same launch is reused, a different model or variant replaces it (killing the old process and releasing its claim); a crash loop ends `failed` with the claim released.
- **Plan** (`plan.rs`, pure, table-tested): the `resources::policy::room` arithmetic plus the 8 GB rule (while the voice changer runs on the GPU of a card under 10 GB, models above 4.5 GB, the 7B class, are refused with `vc_running`). Variant `auto`: CUDA 13 only when `runtime/llama-server-cuda13` is installed and the primary GPU is NVIDIA Turing or newer with driver R580+; else Vulkan; the CPU pack when the model does not fit. An explicitly chosen GPU variant is never moved to the CPU silently. `allowOverBudget` overrides a budget refusal, never `needs_runtime_update` or `no_gpu_runtime`. Model facts come from the bounded, cached GGUF header reader (`gguf.rs`: per-layer KV heads, encoder-decoder detection).
- **Launch:** `--no-webui -fit off --reasoning off --log-colors off`, `--poll 0` on full GPU offload, `--device none` on the CPU pack; with more than one hardware GPU the server is pinned to the primary one (`--device` from `--list-devices`, else `-sm none`, `devices.rs`). A `claim_external_vram` sized to the plan is resized to the device buffers llama-server logs (plus 100 MB Vulkan / 400 MB CUDA base). Note: the pinned b11146 prints those buffer lines only at `-lv 4`, which the launch does not pass (it also logs about 24 lines per request), so today the claim stays at the plan's estimate (Hy-MT2 1.8B on Vulkan: planned 1600 MB, logged buffers 1380 MB + 100 MB base, measured at the P4 gate).
- **Proxy** (`proxy.rs`, `llm_proxy_chat` / `llm_proxy_cancel`): http / https only, no credentials in the URL, forbidden headers refused, header values never echoed in errors, no redirects, a 30 s stall timeout plus the caller's deadline, an 8 MB body cap, UTF-8 characters never split between chunks, cancel by request id (a duplicate id is refused), loopback hosts skip the system proxy. A failure is always an `error` event, then `Ok`.
- **TS host** ([`src/core/services/llm_server`](../src/core/services/llm_server/index.ts)): `acquireLlmServer(holder, config, signal?)` → `LlmServerLease { holder, endpoint, refresh(), release() }`; one shared server (the last acquire's config wins); `LLM_SERVER_IDLE_STOP_MS` (10 s) after the last release it stops; an abort rejects at once and a start Rust finishes later is stopped unless someone acquired it meanwhile; a server that already failed is not stopped again, so its error stays visible. `llmServerSession.overBudget` holds the "Start it anyway" consent for the session (per model and variant); `llmServerConfigFromSettings` maps the translation `llm` slice; `ensureLlmServerHost()` (a host init task, "Local model server") subscribes to state events and stops a server nobody leases after a webview reload. The key is returned to TypeScript for direct loopback calls (random per session, `127.0.0.1` only).
- **Tests:** a fake llama-server built into the test binary runs through the real start path (`cargo test llm_server`); `real_model_end_to_end` is the manual run with `SIGIL_TEST_LLM_RUNTIME` and `SIGIL_TEST_LLM_GGUF`. Making a GGUF: [`scripts/models/make-gguf.md`](../scripts/models/make-gguf.md).

### Translation pipeline (`src/core/services/translation`)

P4-C. `Service_Translation` ([`index.ts`](../src/core/services/translation/index.ts)) is a thin host over one pipeline; `createTranslationPipeline({ name, settings, engines, publish, pair? })` ([`pipeline.ts`](../src/core/services/translation/pipeline.ts)) makes independent instances (P6's other-player translation passes `pair: () => ({ from, to })` and its own `publish`).

- **Flow:** TextEvent (stt / textfield) → `UtteranceTracker` ([`tracker.ts`](../src/core/services/translation/tracker.ts)) → `TranslationSequencer` ([`sequencer.ts`](../src/core/services/translation/sequencer.ts)) → engine or router → LocalAgreement-2 ([`localAgreement.ts`](../src/core/services/translation/localAgreement.ts)) → publish.
- **Tracker:** lines keyed by `segmentId`; interims after a final or with a stale revision are dropped; a new segment without its predecessor's final abandons the old line silently, and a late final of a given-up segment is still translated. Events without ids get the late-interim text check. Smart Turn (`partials.turnEndCommit`): a final with `turnEnd: false` is held and merged with the next segment; the line commits on a final with `turnEnd` true or unknown, after `partials.turnHoldMs` (2.5 s) without events, past 280 characters, or on STT's cancel marker. The pipeline reads `turnEnd` from finals (it does not listen to `speech:turn_end`).
- **Sequencer:** per-stream lines, latest-wins interims throttled by `partials.throttleMs` (`interimGapMs`), ordered finals, deadlines 15 s (interim) and 30 s + 10 ms per character (final, scaled with the chain length or the LLM timeout), one retry for a failed final, then a report. `publish` returning `false` closes a line that never showed anything silently.
- **Interim translations on the processor** (`interimPolicy.ts`, P7-I0). `translation.llm.interim` and `translation.auto.interim` are `boolean | "auto"` (`zInterimSwitch`; a stored boolean is the user's choice and wins; no key or anything else reads as `"auto"`, the default). `"auto"` means on, except while the bundled llama-server translator runs on the processor (`bundledTranslatorOnCpu`: provider `bundled` and the running server's `variant` is `cpu` or its `gpuLayers` is 0, else, with no server up, the settings say `cpu` variant or 0 layers; variant `auto` with no server is unknown, so on until the status shows the governor's choice) and the backend uses it (`llm`, or `auto` with `llm` in the chain or a pair rule). `interimTranslationsOn(state, backend, onCpu)` is the one rule; the pipeline reads it per partial through the option `translatorOnCpu` (`translatorOnCpuNow()` in `translation/index.ts` reads `llmServerUi.status`; the other-players pipeline passes it too), and the inspector's checkbox shows the same value (`useInterimSwitch`) with a hint while the automatic rule holds it off. Why: Hy-MT2 on the processor with an interim every 300 ms took 4.0 cores on average next to a game (6.7 at the peak), final lines only 1.5 ([benchmarks/SPEECH_BENCHMARKS.md → App footprint](benchmarks/SPEECH_BENCHMARKS.md#app-footprint)); a GPU variant takes 0.2-0.4. The router's own member rule is unchanged (`state[id].interim === false` skips an engine for interims; `"auto"` never blocks a member). Profiles of earlier builds of this unreleased branch that stored `interim: true` keep it. Tests: `__tests__/interimPolicy.test.ts`, the "automatic interim switch" block of `pipeline.test.ts`.
- **LocalAgreement-2:** each interim translation is a hypothesis for the whole line; the whole-token common prefix of the last two is committed and never shrinks (whitespace words, or `Intl.Segmenter` words for unspaced scripts). The final, translated from the complete source, may replace the committed interim text once (quality first). `partials.showTentative` adds the uncommitted tail. Streamed LLM finals are shown as interims only while they extend what the line shows and the line is next to publish.
- **Published events** (`text.translation`): `segmentId` = the line id (its first STT segment id, or a generated `tr.<stream>.<epoch>:<n>`), rising `revision`, the target `lang`, `stableLength` on interims (committed UTF-16 prefix, excluding trailing whitespace) and `turnEnd` on the final. Every final an engine translates is published once, in line order; untranslated source text is never published as a translation.
- **Requests:** the language pair comes from the settings, then the STT `lang`, then a script guess; rolling context = earlier final pairs with the same target (`context.turns`, dropped after 5 minutes) plus `context.background`; the glossary is filtered to terms in the line ([`glossary.ts`](../src/core/services/translation/glossary.ts): whole words in spaced scripts, anywhere in CJK, NFKC, language filters, at most 24 terms).
- **Router** (`auto`, [`router.ts`](../src/core/services/translation/router.ts)): the pair's chain (first matching `auto.pairOverrides`, else `auto.chain`, default `[llm, bergamot, nllb]`); members start concurrently and the router is ready on the first ready member (other pairs' members start lazily; a failed start retries after 60 s); every attempt is bounded by `auto.attemptTimeoutMs` (6 s; a hung engine is aborted and the next tried); a member still loading is skipped while a later one is ready; `supports() === false` skips a member; a circuit breaker per member and pair (2 failures, or 1 non-retryable, open it for 15 s doubling to 5 min, then one probe); `auto.cloudFallback` tries Bergamot and NLLB after a cloud failure even when they are not in the chain; interims go to `auto.interimEngine` (`auto` = the cheapest ready local engine, Bergamot first) with at most 2 attempts. The engine that produced a line is reported (`serviceState.activeEngine`); a fallback shows a warning status.
- **Prompts** ([`prompt.ts`](../src/core/services/translation/prompt.ts)): families `hy-mt2` (the model card's default / terminology / background templates, Chinese wording when Chinese is on either side), `translategemma` (raw Gemma turns on the bundled server, chat elsewhere), `milmmt` and `seed-x` (raw), `lmt`, `sakura`, `vntl`, `madlad`, `generic` (source fenced in `<source>` tags with a system rule not to follow instructions inside it) and `custom` (`{source_lang}`, `{target_lang}`, `{text}` fenced, `{context}`, `{glossary}`, `{background}`). Every family neutralizes chat-template special tokens and its own markers in source, context and glossary (llama.cpp parses special tokens in rendered prompts). `cleanTranslationOutput` strips labels, tags, explanations and quotes models add. The LLM engine takes the family and languages from the catalog (name guess as fallback), the family's recommended sampling, and a fixed seed on local servers.
- **Languages** ([`languages.ts`](../src/core/services/translation/languages.ts)): 198 languages with FLORES-200, Azure and ISO 639-1 codes; `canonicalLanguage` accepts aliases, Whisper codes (`jw`, `no`, `fil`, `iw`), Chinese script / region forms, FLORES, ISO 639-3 and Azure codes. `__tests__/languages.fixture.json` is shared with Rust `mt_local/flores.rs` (Santali is `sat_Beng`, the token NLLB's tokenizer has).
- **Service state:** `serviceState` = `{ status, error, statusText, statusLevel, progress, activeEngine, missing }` (mount `<ModelRequirement ids={missing}>`).

### Local machine translation (`mt-local`)

`src-tauri/src/services/mt_local/` (plugin `mt-local`, shared types `MtRequest { text, source, target, kind, requestId?, model?, beam?, threads? }`, `MtResponse`, `MtEngineStatus`, `MtPair`, `MtError { kind, message, missing }`; event `mt_local:status`). Language codes in requests are canonical BCP-47 (source "" = unknown); engines never download (`not_installed` names the catalog ids).

- **NLLB-200** (`nllb.rs`, `tokenizer.rs`, `flores.rs`, P4-D): Optimum's encoder plus merged decoder with KV cache, built only through `ort_session` (component `mt.nllb`, CPU, 2 threads by default, spinning off). The first decoder step feeds `</s>` and the target-language token uncached, which also yields the encoder cache reused afterwards. Greedy, or beam search up to 4 for finals (interims always greedy); padding, `<s>`, language tokens and `<mask>` are never generated; output length is capped at 3× the source + 10 tokens with a repetition guard; long lines are translated sentence by sentence; stray spaces between CJK characters are removed; an unknown source is guessed from the script, and text without letters or already in the target language comes back unchanged. One worker thread at below-normal priority serves `nllb_load` / `nllb_translate` / `nllb_unload` in order; `nllb_cancel` stops a request at the next decoding step. The FLORES table covers all 202 NLLB language tokens. Parity tooling: `scripts/mt-bench/nllb_reference.py` and `fixtures/nllb_parity.json` (token ids 27/27 with Python sentencepiece; greedy output 24/27 exact, the rest near-ties under a 0.05 logit gap between ORT 1.28 and Python ORT 1.19.2); real-model tests are ignored and run with `SIGIL_APP_DATA_DIR` pointing at an app-data folder holding the model. The 1.3B model is built by `scripts/mt-bench/export_nllb.py`.
- **Bergamot** (`bergamot.rs` + `bergamot/{catalog,client,pack,protocol,tests}.rs`, P4-E, [ADR 0008](adr/0008-bergamot.md)): the `sigil-bergamot.exe` helper under `process_host` (`StdioMode::Protocol`, JSON lines protocol 1 over stdio, `--jsonl [--threads N] [--cache-size N]`, 1.5 GB job memory cap, below-normal priority). Direct or English-pivot routing (an unknown source is refused); models load on demand, the least recently used unload beyond `min(6, what fits in 1.2 GB)`; a final gets one retry after a helper crash, interims none; more than 3 interims in flight are `busy`; a hung helper is restarted; after a failed start requests fail fast for 30 s; after a process-host restart the client re-attaches; a model whose load crashes the helper twice is refused. Before each start the pack's protocol version, CPU features (AVX2 by default) and exe sha256 are checked. The helper source (C++, `engine_bergamot.cpp` is the only file touching the upstream API) and `build.ps1` (`-Fake` builds the protocol shell with a fake engine, `-SelfTest -Models <dir>` measures p95) are in [`scripts/runtime-packs/bergamot/`](../scripts/runtime-packs/bergamot/README.md); ids `mt-bergamot/<src>_<tgt>` come from `gen-catalog.mjs`. `bergamot_pairs` returns every direct direction plus the English pivots (about 2,800 rows).
- **DeepL** (`translate/deepl.rs`, P4-D): `deepl_translate { request: { text, source?, target, apiKey, plan, formality?, context?, modelType?, timeoutMs? } }` → `{ text, detectedSource, billedCharacters }`, `deepl_usage`, `deepl_languages { kind }`. The key goes only in a sensitive `DeepL-Auth-Key` header; keys ending in `:fx` use `api-free.deepl.com`; each request has its own timeout (10 s default); errors start with the HTTP status (403 wrong key or plan, 456 quota used up, 429 / 529 too many requests). The TS engine maps canonical codes (`en` → `EN-US`, `zh-Hant` → `ZH-HANT`), always sends the lenient `prefer_*` formality, sends the last 3 source lines as (unbilled) context, checks the key once at start and warns at 90 % of the monthly quota.
- **TS engines:** [`services/nllb.ts`](../src/core/services/translation/services/nllb.ts) (only the most recently started instance unloads on stop), [`services/bergamot.ts`](../src/core/services/translation/services/bergamot.ts) (`supports()` from installed directions, refreshed on `models:state`), [`services/deepl.ts`](../src/core/services/translation/services/deepl.ts) (its static helpers feed the DeepL panel).

`Sigil.exe --headless mt-bench <spec.json> [--out <dir>]` (`mt_local/bench.rs`) reads a JSON spec and a JSON-lines corpus and writes `report.json`, `report.md` and `hyps/*.jsonl`. ### Speech benchmark (`--headless speech-bench`, P7)

`Sigil.exe --headless speech-bench <spec.json> [--out <dir>]` (`bench::speech::headless_speech_bench`, `src-tauri/src/services/bench/speech.rs` and `speech/`) measures the app's own STT, machine-translation and TTS backends on the P7 corpus and writes what the Python scorers, the listening pages and a friend's export need. It never re-implements inference: every engine is created through the code the app itself uses, so a benchmark number is the number of the shipped feature. The default output folder is `bench-results/speech/<name>-<timestamp>/`:

| File | Content |
|---|---|

**How a run flows:** parse the spec (strict types, then the cross-reference rules: unique names, a backend that belongs to its task, runs that name engines whose task the mode takes, no secret-looking option names) → expand paths → build the environment block (versions, GPUs, power plan, runtime packs) → for each run: check the GPU timing lock (`gpu_lock.require` defaults on for the speed modes; the runner **checks** that the lock file names the tag and never takes it, because the campaign wraps the whole command with `pwsh scripts/bench/gpu-lock.ps1 -Run <tag> -Command "..."`) → start the load simulator (`load_profile` / `load` expand through `bench::contention`; its CPU is subtracted from the engines' process CPU) → start the run-state probe → for each selected engine create its driver (a model or pack that is not installed fails only that engine's rows with `not installed: <catalog id>`; nothing is downloaded) → `warmup` untimed items, then `repeat` timed passes (per-item timings are the median of the passes, text and audio come from the first) → aggregate, evaluate thresholds, write the report, hypotheses, audio and Markdown → derive `export.json` and verify it with the privacy rules before writing it (a leak writes no export and fails the run). A fallback is never hidden: the report records the execution provider requested and the one that ran, with the engine's reason.

**Adding a backend:**

1. Add its wire name to `spec::backends(task)` and keep the Python side equal: the `backend` description in `schemas/speech-bench-spec.schema.json` and `BACKENDS` in `scripts/speech-bench/validate.py`.
2. Implement the driver trait for its task (`SttDriver`, `mt::MtDriver` or `tts::TtsDriver`), filling `DriverInfo` (device, why it fell back, variant, threads, VRAM, runtime version, streaming, whether it runs in a helper process, extra facts for the engine row), and route to it: STT in `Production::stt` (`speech.rs`), MT in `mt::create_driver`, TTS in `tts::create_driver`. Use the app's own code for the engine; do not copy it.
3. If it needs a runtime pack, add the catalog ids to `runtime_pack_ids(backend, variant, helper)` so the environment block lists the pack.
4. Test it through the `Drivers` trait: `speech/tests.rs` scripts engines and runs whole specs, so the new backend needs a scripted case plus, if it parses new options, a parse test in `spec.rs`. Add an example spec under `scripts/speech-bench/examples/` (the contract test deserializes every `spec.*.json`) and run `validate.py` over it.
5. Record the choices the runner made for it in the "As built" list of `scripts/speech-bench/README.md`. The first real run of a new backend is a 2-item check.

**Privacy of an export:** no audio paths and no `files`; every absolute path inside a string becomes `<path>/<file name>`; a bring-your-own model is `byo`; host and user names never leave the environment block; item text is kept only when the spec's `output.export.include_text` is true and never for real clips (`real/...` ids). `SIGIL_BENCH_RIG` labels a rig (`H1`, `friend-3`), never a host name.

**Scoring and listening:** `scripts/speech-bench/score/` holds `score_stt.py` (WER / CER with bootstrap intervals and paired comparisons), `score_mt.py` (chrF2, BLEU, MetricX merge, A/B pair export), `score_tts.py` (pre-screen), `make_export.py` and `merge_exports.py`; `tools/listening-test/` builds the blind MT A/B and TTS listening pages and aggregates the answers. The Python tests run with `python -m unittest discover -s scripts/speech-bench -p "test_*.py"` in the venv from `setup-venv.ps1`. The corpus (FLEURS speech under 14 conditions, 12,600 items) and its `content_sha256` are quoted in every published result, together with the normalizer stamp `sigil-norm/1`.

**The P7 campaign tools** ([`scripts/speech-bench/campaign/`](../scripts/speech-bench/campaign/README.md)): the specs it ran (`specs/`), `lock-run.ps1` / `run-bench.ps1` (a run under the GPU timing lock, on a CPU slice, with the process tree sampled), `stt_table.py` / `mt_table.py` / `summarize_report.py` (compact tables), `own_mic.py` (the own-microphone default rule: clean plus the mic-side conditions, bleed conditions play no part; unit-tested in `scripts/speech-bench/tests/test_campaign.py`) and `footprint/` (`footprint.ps1`, `driver.mjs`, `diagnose.ps1`, `close-window.ps1`: the real release app with captions, an OBS page and translation next to a game stand-in, in a scratch Windows profile, started with `SIGIL_START_MINIMIZED=1` and closed by window title).


Not run against real packs when the runner was written (first campaign runs are 2-item checks): the GPU variants of `transcribe`, a live `http` server, `crispasr`, `llama-server` and `bergamot` (the Bergamot pack is unbuilt), the `tts-helper` engines, `co_load` (a paced voice-changer run beside an STT run), the load simulator's GPU part and NVML / DXGI VRAM sampling. VRAM semantics: engines in this process are read per process through DXGI; engines in a helper process are read device-wide through NVML as growth over the baseline taken before the engine started, so another program's VRAM change during the run shows up in those rows.

### Streamer features and extended engines (P6)

Every P6 feature is off by default or a new backend value. Frozen contracts (P6-S0) change only through an INTEGRATE step; structs may gain fields.

#### Topics outside `text.*`

- `others.stt` / `others.translation` (`OthersEventSource`, payload `TextEvent`) carry other players' speech and its reverse translation; `readings.stt` (`ReadingsEventSource`, payload `ReadingsEvent {utteranceId, revision?, source, lang, value, hiragana?, romaji?, pinyin?, segments?}`) carries readings. They sit outside `text.*` on purpose: pubsub-js bubbles `text.*` up to `text`, which would echo other players into the chatbox, TTS and history. `CaptionEventSource = TextEventSource | OthersEventSource` is what displays accept (text element `sourceMain`, caption window, VR overlay; `InputTextSource includeOthers` is for displays only, never for chatbox, TTS or chat targets).
- `inbound.ts`: `sanitizeClientPubSubFrame` validates `others.*` as `TextEvent` and `readings.*` with `ReadingsEventSchema` (every string neutralized) on `/client`; `routeInboundMessage` never accepts them from WebSocket peers.
- `TextEvent.tags?: string[]` (`<kind>:<value>`, at most 8; malformed values dropped): SenseVoice emotion / event tags, published by `SegmentPublisher.final` in `meta.tags`.

#### Other players (`src/core/services/others`, P6-A)

- **Capture:** source id `process:<exe>` (`SourceSpec::Process`, `PROCESS_PREFIX`) is Windows per-process loopback (`audio/loopback_process.rs`, wasapi 0.19 application-loopback client, include-tree, event-driven, `CAPTURE_FORMAT` 48 kHz stereo f32, Windows 10 build 20348+). It resolves to the root of the same-name process tree (EasyAntiCheat launches VRChat.exe as a child), counts as loopback (`MuteGroup::Others`, the speech front end's loopback idle fill) and never follows the default device; `process:` without a name means `loopback:default`. The `sigil-capture-process` thread follows the real-time rules (MMCSS there only, one 2 s scratch buffer, QPC packet times), fills up to 2.5 s of paced silence after 300 ms without packets, and waits in place for a program that exits (no `audio:stream_error`, same hub epoch); only real capture failures reach the `ErrorSink`.
- **IPC:** `plugin:audio|list_loopback_processes { source?, fallback?, processes? }` → `{ supported, processes[{pid, exe, title, audio}], windowsBuild, plan? }` (additive; `processes: false` = plan only). The plan is `speech::session::plan_source_with`: program running → capture it and watch it; not running → `loopback:default` with the fallback on, or wait; old Windows → default output, or an error with the fallback off; devices as requested; the default microphone is never used for other players.
- **TS:** `OthersSpeechDriver` (`driver.ts`) previews the route first (never downloads; the panel shows a `<ModelRequirement>`), starts `start_pipeline` with `pipelineId: "loopback"` (Rust VAD defaults, 12 s latency budget, optional music gate), re-plans every 5 s while a program is watched, restarts with the STT driver's back-off and refuses a `loopback` epoch left by an earlier webview; it never touches `mic`. `publish.ts` publishes on `others.stt` only; `translation.ts` computes the reverse pair (`from` = other players' language or per-line detection, `to` = `translateTo`, else the main translation's source, the STT language, the app language, `en`) for a second `createTranslationPipeline` instance that shares the Translation tab's engine settings. Settings `services.others` (`autoStart`, `source = "process:VRChat.exe"`, `language`, `tier`, `interim`, `translate`, `translateTo`, `fallback`, `twoPass`, `musicGate`); `PERSISTED_SERVICE_KEYS` includes `others`. NLLB counts its users (like Bergamot), so the second instance stopping never unloads the model under the main pipeline.

#### Caption window and SteamVR overlay (P6-B)

- **Caption window** (`caption_window.rs`, plugin `caption-window`): `caption_window_open { options }`, `caption_window_set_options`, `caption_window_close` (waits until the window is gone), `caption_window_status`, `caption_window_reset_position`; event `caption_window:state` (`RustCaptionWindowStatus`, plus `closedExternally` when Alt+F4 or the OS closed it, which turns the setting off). Window label `captions`, route `/captions`: undecorated, transparent, no taskbar entry, `focusable(false)`, always on top, click-through by default; the foreground goes back to the window that had it. `src/index.tsx` sends `/captions` to an early route (`src/overlay/**`) **before** `AppConfiguration`, `ApiShared`, `ApiClient` or `ApiServer` exist, so the window never boots a second host; outside Tauri the route renders nothing (Playwright smoke). `capabilities/captions.json` grants that window only `core:event:allow-listen` / `allow-unlisten` and `core:window:allow-start-dragging`. Position and size persist through `tauri-plugin-window-state`, which skips its own restore for `captions` (`skip_initial_state`; `caption_window::settle` restores without `show()` / `set_focus()`). `main.rs` closes every secondary window when the main window is destroyed.
- **Frames:** the main window's overlay service keeps one caption feed per display from `text.*` / `others.*` with the text element's revising rules (`segmentId`, revision, superseded interims, `maxLines`, `clearAfterMs`) and sends `caption_window:frame` with `emitTo` (bursts merged within 30 ms, re-sent every second); `src/overlay/frame.ts` checks every field and the page renders text only as React text with `dir=auto` and `lang`. - **SteamVR overlay** (`vr_overlay/**`, plugin `vr-overlay`): `vr_overlay_start { config }`, `vr_overlay_set_config`, `vr_overlay_stop`, `vr_overlay_status`, `vr_overlay_set_text { caption }`, `vr_overlay_recenter`; event `vr_overlay:state` (`state`, `runtimeInstalled`, `error`, `reason`). `openvr_api.dll` is the `runtime/openvr` pack (pinned by git blob id; `SIGIL_OPENVR_DIR` is a development override), loaded lazily with hand-written FFI (`FnTable:IVRSystem_026` / `IVROverlay_028`). #### VRChat OSC (`osc`, `osc_query.rs`, `src/core/services/vrc`, P6-C)

- **Sending:** one socket per destination kind (`127.0.0.1:0`, `0.0.0.0:0` for VRChat on another PC, IPv6 on first use); `localhost` always means 127.0.0.1; other host names cached 30 s; ints clamped to i32.
- **Receiver:** `listen_start { options: { host, port, oscQuery, muteSync } }` → `OscReceiverStatus`, `listen_stop`, `listen_status`; events `osc:mute_self { muted, origin }` (repeats ignored), `osc:receiver` (status: mode `off` / `oscQuery` / `port`, address, port, `oscQueryPort`, `advertised`, `vrchatFound`, `muteSelf`, `packets`, `lastPacketAgoMs`, `error`, `warning`) and `osc:vrchat { present }`. OSCQuery mode binds a free UDP port and an HTTP description (`/?HOST_INFO`, `/avatar`, `/avatar/change`, `/avatar/parameters/MuteSelf`) on 127.0.0.1, announces both over mDNS (mdns-sd) and watches VRChat's own `VRChat-Client-*` service, reading its current MuteSelf. The fallback listens on a fixed port (9001 by default) on 127.0.0.1, or on 0.0.0.0 for VRChat on another PC (that PC and loopback only); a port in use is reported and retried every 5 s. With `muteSync`, a MuteSelf mute closes the hub's `MuteGroup::Stt` gate in Rust **before** the event is sent (test: under 200 ms); the webview then calls `stt.setMuted` and resets the gate to STT's own state. Epoch discipline as everywhere else.
- **TS:** `muteSync.ts` owns mute ownership (a VRChat unmute lifts only a mute VRChat caused), `receiver.ts` runs the receiver while the integration and mute sync are on, `chatboxPager.ts` paces every `/chatbox/input` at least `pageIntervalMs` apart (1.3–10 s, default 1.5 s; short waiting messages merged) and paginates (`paginate`, numbered pages, only page 1 notifies) or cuts at a word boundary with `…`, `tags.ts` maps tags to the Int parameters (`SigilEmotion`: neutral 0, happy 1, sad 2, angry 3, fearful 4, disgusted 5, surprised 6; `SigilEvent`: laughter 1, applause 2, cry 3, cough 4, sneeze 5, breath 6, bgm 7; reset after `tags.resetMs`) and optional chatbox emoji. STT's `[...]` cancel marker never reaches the chatbox, KillFrenzy or TTS.
- **Turn commit:** `TurnCommitGate` (`vrc/turnCommit.ts`, pure, generic) holds finals Smart Turn marked `turnEnd: false` and commits them joined on the next finished final, after `holdMs` without speech (interims re-arm), or at `maxChars`; `passThrough` for typed text, `reset` on stop. The chatbox (`textbox.commitOnTurnEnd`) and TTS (`tts.commitOnTurnEnd` / `turnHoldMs`, wired in `Service_TTS` by P6-I0) use it; a translation source that already commits on turn end is not held twice.

#### LAN access stage 2 (`web/auth.rs`, P6-D)

- Root setting `lanAccess { mode: "lan" | "localhost" = "lan", token, legacyNoToken: false }`. Rust reads it from the settings file (or `settings.bak`) at startup, so the token is enforced before the webview loads; `main.rs`'s port pre-check binds the same address (`web::startup_bind_ip`).
- **Token:** 26 Crockford base32 characters (130 bits) from the OS random generator, persisted, normalized on input (case, `-`, spaces, o / i / l look-alikes), compared in constant time, never logged, emitted or shown in `Debug`. It travels as `?token=` on `/pubsub` and LAN page links and as the PeerJS `key` on `/peer`.
- **`AccessGuard`** combines the Origin allow-list and the token: a foreign Origin is a plain 403 (the token never bypasses it, and the Origin kill switch never turns the token off); same-PC peers (loopback or one of this PC's addresses, without reverse-proxy forwarding headers) are exempt; an origin-less tool on another machine needs the token. Token refusals happen after the upgrade with close codes 4401 (`missing_token` / `invalid_token`) and 4403 (`lan_disabled`); `/peer` first sends PeerJS `INVALID-KEY`. `Access::revoked` re-checks every admitted socket when the rules change (new token, This PC only, legacy off, Origin check back on). Refusals reuse the throttled `web:origin_rejected` event with the new reasons.
- **Bind mode:** `lan` binds 0.0.0.0, `localhost` binds 127.0.0.1 and refuses non-local peers; `serve_supervised` rebinds live (graceful shutdown, 3 s drain, bind ladder) and falls back to the previous mode on failure. Commands `set_lan_access { settings }`, `regenerate_lan_token` → `{ token, status }`; `WebServerStatus.lan { mode, boundMode, boundAddress, tokenSet, legacyNoToken }`; `config.lan_addresses` (IPv4, primary first). Asset responses send `Referrer-Policy: same-origin`.
- **TS:** pure helpers in `src/shared/services/peer/lanAccess.ts` (token rules mirrored from Rust with shared test vectors); `Service_PubSub.attachHostWebServer` pushes `lanAccess`, creates a token on first start (or when malformed) and toasts refusals; `regenerateLanToken`; `localPageUrl({ token })` for LAN links; `/client` reads `?token=` into `Config.clientNetwork.token` and passes it as the PeerJS key; Link apps send it on the socket (a "Remote token" inside `linkAddress`) and stop reconnecting on 4401 / 4403; `mic.html`, `obs-captions.html` and `inputfield.html` forward `?token=` and explain a refusal. **Rule:** same-PC links carry no token; only LAN links do (Settings → LAN access, OBS inspector "Copy LAN link").

#### TTS helpers (`tts-helpers`, P6-E / P6-F / P6-G)

- **Interface** (`tts_helpers/mod.rs`, scaffold-owned): engine ids `qwen3`, `magpie`, `breeze`, `omnivoice`, `s2`, `sbv2` (helper names `tts-<id>`); each engine module implements `info()`, `async start(app, config) -> TtsHelperEndpoint {engine, baseUrl, apiKey, model, pcmSampleRate}`, `async stop()`, `status()`; IPC `tts_helper_start { engine, config }`, `tts_helper_stop`, `tts_helper_status`, `tts_helper_list`; event `tts_helpers:state`. #### Cloud TTS with local fallback (`edge-tts`, `gemini-tts`, P6-H)

- **Failure tag contract:** Rust cloud plugins reject with a tag in square brackets — `cloud-tts:` plus the kind (`network`, `rate_limited`, `unavailable`, `stalled`, `auth`, `rejected`, `no_audio`, `other`), optionally `:partial` and `:retry=` plus milliseconds — then the message (`edge_tts::cloud`; TS `parseTtsFailure`). `edge_tts/cloud.rs` is shared: Retry-After and HTTP-date parsing, the per-utterance cancel registry, the sink hand-off thread and cancellable waits. Failures on this PC's side (a sink push refused or timed out, the utterance gone, a second request for the same utterance) are sent untagged with the sink's text (`SpeakError::Local`), so `TtsFallbackChain` rethrows them without touching the breaker.
- **Edge** (`edge_tts.rs` + `edge_tts/{protocol, session, voices}.rs`): a native tungstenite client imitating the Edge browser (headers, Origin, `muid` cookie, `Sec-MS-GEC` token and version; the service clock is read from a 403 and the request retried once); MP3 decoded as it arrives (rodio / symphonia over a streaming reader) into the sink utterance; text over 4096 bytes split; voice list cached 6 hours; voice names validated against SSML injection; an async watchdog bounds connect and first audio. Commands `edge_tts_speak { request, utteranceId }`, `edge_tts_cancel`, `edge_tts_list_voices`. The protocol constants live in `edge_tts/protocol.rs`. DNS + TCP connect is bounded by a third of the timeout (at least 1 s); the resolved addresses are raced RFC 8305-style (`session::race_connect`: families interleaved, the next attempt 250 ms later or at once after a refusal). A close after the SSML is `rejected` only when it names the voice (or is 1003), `no_audio` for a payload or size refusal (1007/1009), `rate_limited` for throttling, else `unavailable`. Voice names accept a script subtag (`iu-Cans-CA-…Neural`).
- **Gemini** (`gemini_tts.rs` + `gemini_tts/stream.rs`): `POST /v1beta/interactions` (`model`, `input`, `response_format: audio`, `generation_config.speech_config`, `stream: true`), key only in the sensitive `x-goog-api-key` header; SSE parser for `step.delta` / `content.delta` / `inlineData` (summaries only when nothing streamed); s16le (odd byte carried over), WAV or compressed audio; Google errors mapped (`RESOURCE_EXHAUSTED` / 429 → `rate_limited` with the `RetryInfo` delay, `API_KEY_*` → `auth`); a 404 switches to `streamGenerateContent?alt=sse` for that base URL (3.8+ models get no "Say in a … tone:" prefix there); a new connection must be made within a third of the explicit timeout (at least 1 s, rounded up to 250 ms); a 400 `INVALID_ARGUMENT` about one sentence's text (for example "should only be used for TTS", text too long, a bare invalid argument) is `no_audio`; one about the model, voice, request shape or account stays `rejected` (the settings check always rejects). `gemini_tts_check` reads `GET models/{model}`. TS uses larger sentence chunks for Gemini (`BACKEND_SENTENCE_OPTIONS`).
- **TS:** `TtsFallbackChain` + `FallbackBreaker` (`tts/pipeline.ts`): a failed sentence is spoken by the local voice into the same sink utterance at once (never repeating words after a partial failure, never on stop / skip); later sentences of an outage stay local (back-off 15 s doubling to 5 min; Google's retry delay on 429, else 60 s; 10 min for a refused key, voice or model; `no_audio` affects that sentence only; a settings change resets it). `CloudTtsBackend` / `LocalFallbackVoice` (`tts/services/edge.ts`) are the reusable base: Kokoro kept loaded and warm, language from the text's tag, script or voice hint. Schemas add `fallbackToLocal` (true) and `fallbackAfter` (3 s). `LocalFallbackVoice` re-checks a missing Kokoro on every sentence (a download from the panel is used from the next sentence on, no restart) and retries a failed load after 60 s (`FALLBACK_RETRY_MS`); "Test voice" (`previewCloud`) shows the failure without its tag.

#### Gemini Live STT and Live Translate (P6-K)

- STT backend `geminiLive` (`stt/services/geminiLive.ts`): the capture hub's raw 16 kHz feed (`start_audio_capture({ sampleRate: 16000 })` + `audio:chunk`, already withheld by the Rust STT mute gate) sent as 100 ms PCM16 frames over a webview WebSocket. ### Revising captions (text element, P4-G)

The text element ([`elements/text/index.tsx`](../src/client/elements/text/index.tsx)) renders revising text through [`revising.ts`](../src/client/elements/text/revising.ts), pure logic plus a DOM-independent line view (tested in node by `__tests__/revising.test.ts`):

- **Pairing:** an update pairs with its line within the same topic, first by `segmentId`, then by numeric `id`, then (sources with neither) with the topic's open interim that has no id. An update with a `segmentId` falls back to its `id` only onto a line without a `segmentId` (so the AI transform's streamed replies, which carry only `id`, land on their line); `text.transform_raw` pairs with `text.transform_source`. Lower revisions and interims after the line's final are dropped (equal revisions are accepted). Lines cleared after inactivity are remembered per topic and `segmentId` (at most 256): a line that ended final never comes back; one cleared while interim comes back only for an update that is not older.
- **Rendering:** the line keeps the longest common prefix of the shown and the new text (cut back to a grapheme boundary, never splitting a mask or emote) and changes the DOM in place: text nodes are shortened or extended, emote `<img>` nodes kept, and only the rest is animated (or rendered at once). A half-revealed mask survives an update that keeps it.
- **Tentative tails:** with `stableLength`, the committed prefix is plain text and the tail is `span.interim.tentative` (masks `interim profanity tentative`, emotes `interim tentative`); interims without `stableLength` keep the whole line `.interim`; finals are fully committed.
- Remote-safe: no Tauri imports, text is never parsed as HTML, and pairing fields from peers are validated.
