# Changelog

All notable changes to **Sigil** are documented here. Sigil continues from the **Curses / Curses+** lineage; compare **0.3.0** to **Curses+ 0.2.2** for the largest delta.

Entries before **2026** may name documentation files that were later merged or renamed; the current layout lives under [`docs/`](docs/).

## [0.5.0](https://github.com/Mewnah/Sigil/releases/tag/v0.5.0) - 2026-10-12

**The speech-stack release.** Speech-to-text now defaults to **Built-in (on your PC)**: live captions that a more accurate final line replaces per sentence, with the models picked for your language and PC and a question before anything downloads; the speech pipeline, the models and their accuracy are measured on a public corpus. **Translation** gets a local default (Hy-MT2, NLLB-200 for about 200 languages, free cloud options) whose partial captions no longer flicker. **Text-to-speech** plays through one output with local, keyless and cloud voices. The **voice changer** runs on Sigil's own engine: import the RVC voices you already have, zero-shot and singing voices, GPU and CPU presets and a benchmark you can rerun. The interface has one **Speech** group in the left menu, Rewrite as a tab of Speech to Text and a five-step **setup wizard** on the first run. Other computers on your network now need a token, and a scene you open can no longer run code through its event text. The installers bundle the CUDA and DirectML providers; NVIDIA's CUDA runtime stays an opt-in download. The interface comes in 20 languages (machine-assisted; corrections are welcome).

- **Documentation** — Consolidated detailed guides into [docs/OPERATOR_REFERENCE.md](docs/OPERATOR_REFERENCE.md), [docs/DEVELOPER_GUIDE.md](docs/DEVELOPER_GUIDE.md), [docs/RELEASE_AND_ENGINEERING.md](docs/RELEASE_AND_ENGINEERING.md), and manual chapters under [docs/manual/README.md](docs/manual/README.md). Older bullets in this file may still reference previous filenames.

### Security

- **Client secrets and API keys moved out of the web bundle.** A build used to put every `VITE_*`, `SIGIL_*`, `CURSES_*` and `TAURI_*` variable of its environment into the JavaScript that Sigil's own web server serves (to the whole LAN in LAN mode), including the Kick client secret and the Google Fonts API key. Vite now gets only an allow-list of public names ([`scripts/release/env-classification.json`](scripts/release/env-classification.json): the Twitch and Kick client ids and redirect overrides). The secrets are compiled into `Sigil.exe` by `build.rs` (lightly obfuscated, which is not protection: Kick requires a client secret, so it has to ship), and a new Rust plugin makes the Kick and Twitch token exchange and refresh and the Google Fonts list request; the frontend never sees a secret. Kick sign-in now needs the desktop app, and the Kick `*_REDIRECT_LOCAL` override is gone (Rust accepts only the two localhost callbacks). Kick access tokens are now refreshed instead of expiring. `SIGIL_GOOGLE_FONTS_API_KEY` is the new name of the fonts key (`VITE_GOOGLE_FONTS_API_KEY` still works). New guards: `check-no-secrets.mjs` (run by `verify-bundle.ps1` and the release workflow), a vitest on `src/`, and tests of the classification. See [Secrets in the build](docs/RELEASE_AND_ENGINEERING.md#secrets-in-the-build); rotate the Kick secret and the fonts key if an earlier build was shared.

### Speech stack overhaul

Implements [docs/SPEECH_STACK_RESEARCH_2026-09.md](docs/SPEECH_STACK_RESEARCH_2026-09.md) per [docs/SPEECH_STACK_IMPLEMENTATION_PLAN.md](docs/SPEECH_STACK_IMPLEMENTATION_PLAN.md) (phases P0–P7). Work landed on the `speech-stack` branch, one commit per phase.

#### P0 — stabilize (bug fixes, hardening, tooling)

- **Speech-to-text** — A Silero VAD v6.2 segmenter with sinc resampling replaces the RMS silence gate, so Whisper is never fed silence (fewer "thanks for watching" captions). Whisper also gets hallucination filters, token caps and an ordered worker. HTTP engines (Moonshine, OpenAI-compatible) send one request per spoken utterance instead of one every 500 ms. New Groq preset with a request limiter. Status messages no longer leak into captions. Desktop users on the broken browser-native default move to Whisper once.
- **Cloud STT** — Deepgram requests the Nova-3 model (Nova-2 selectable), and the existing profanity-filter toggle now works. Azure finalizes phrases faster (segmentation silence 500 ms).
- **Voice changer** — Latency budget (default 300 ms) drops stale audio instead of building a backlog. TTS routed into the voice changer is no longer cut after 2 s. Real-time threads use MMCSS and event wake-ups instead of a 2 ms sleep loop. Settings and devices persist across restarts. The inspector shows the execution provider actually in use plus p99 latency, backlog and dropped-audio metrics.
- **GPU** — GPU execution providers report failures and fall back explicitly (no more silent CPU). A startup probe covers providers, drivers and adapters, and provider DLLs are staged for release builds.
- **TTS** — AivisSpeech preset for the VOICEVOX backend. Fish Speech uses its real health and voice-list endpoints. Uberduck moves to its v1 API and plays on the selected device. Azure SSML is escaped. VOICEVOX zero values are kept, and the pitch slider can return to 0.
- **Translation / AI transform** — Final translations are never dropped when a newer interim arrives. On-device (Chrome/Edge) translation is detected correctly. Transform output is no longer truncated at 100 tokens.
- **Security** — The LAN WebSocket server gets an Origin allow-list and a topic allow-list, refuses binary frames, and has XSS fixes in the caption renderer and pages.
- **Tooling** — Data-driven `build.rs` (`src-tauri/plugin-commands/*.txt`), i18n staging merger, vitest (`pnpm test:unit`), `--headless` CLI, rotating diagnostics log.

#### P1 — platform foundations and decision gates

- **ONNX Runtime 1.28** — `ort` 2.0.0-rc.13 (CUDA 13: driver R580+ and a GeForce 16/20 series or newer GPU for CUDA; DirectML covers the rest). KittenTTS is vendored, so `kittentts` and `hf-hub` are gone. The bundled CUDA provider shrank from 144 MB to 62 MB ([ADR 0001](docs/adr/0001-ort-upgrade.md)).
- **Models & Runtimes tab and model store** — One verified, resumable, mirror-aware downloader for models and runtime packs: HTTP Range resume, 30 s stall timeout, pinned checksums, automatic hf-mirror.com fallback, custom LAN mirror, safe archive extraction, one download at a time. Existing Whisper and Vosk files are adopted without downloading again; Vosk downloads now go through it, and all 11 Vosk models plus the Whisper catalog are hash-pinned. `Sigil.exe --headless fetch <id>` does the same from the command line. A reusable model-requirement card for later features.
- **Microphone capture hub** — Every STT engine shares one stream per microphone. Unplugging and replugging a microphone recovers automatically without stopping STT, "System default" follows the Windows default device, a missing saved device is shown as "(not connected)", and muting STT stops audio at the source. Vosk receives 16 kHz mono (about a sixth of the old traffic).
- **GPU runtimes** — The NVIDIA GPU runtime (CUDA 13.2, cuDNN 9.26) installs from Models & Runtimes; the Settings installer now also extracts the two cuDNN 9.26 sub-libraries CUDA needs. **Test GPU acceleration** reports which runtime and CUDA provider were used. A GPU and runtimes card shows your GPUs, drivers, video memory, which acceleration options work and suggested model sizes; `Sigil.exe --headless sysinfo` prints the same.
- **Native runtimes (spikes, not user-facing yet)** — sherpa-onnx 1.13.8 as the in-process CPU speech runtime ([ADR 0002](docs/adr/0002-sherpa-onnx.md)); transcribe.cpp as Sigil-built GPU/CPU `sigil_transcribe.dll` packs ([ADR 0003b](docs/adr/0003b-transcribe-cpp.md)); the `sigil_engine` DLL ABI, loader and local pack build scripts ([ADR 0007](docs/adr/0007-native-runtime-packs.md)); helper processes in kill-on-close Job Objects bound to 127.0.0.1, with llama-server runtime packs ([ADR 0005](docs/adr/0005-process-host-llama.md)).
- **Voice changer foundations** — RVC voices as Sigil split-graph templates with a Rust importer (allow-list pickle parser, weight-norm fold) matching PyTorch within the parity gates on CPU, DirectML and CUDA ([ADR 0004](docs/adr/0004-rvc-templates.md)); benchmark harness (`Sigil.exe --headless bench`, paced / offline / loopback modes, GPU and CPU load simulator, perf gate) ([docs/benchmarks/README.md](docs/benchmarks/README.md)).

#### P3 — the Sigil Voice Engine core (voice changer)

- **Import the voices you already have** — Drop a community RVC `.zip` or `.pth` (plus its `.index`) onto Sigil and it converts in-process into Sigil's own split-graph templates: an allow-list pickle parser in an isolated worker, weight-norm folding, metadata detection, a 22-template matrix (v1/v2 × 32/40/48k × f0/nof0 × HiFiGAN-NSF) that passes PyTorch parity on CPU, and a 200-file malformed-input fuzz corpus with 0 crashes. The MIT default voice imports in 0.84 s. Existing bring-your-own ONNX slots keep working.
- **Quality machinery other engines lack** — Partial decode (only the return window is decoded each tick), counter-based time-anchored noise and phase-continuous NSF excitation (0 block-boundary clicks in every run), incremental pitch tracking with a cache, exact GPU kNN retrieval, an adaptive quality governor, and a stale-audio latency budget that never let the backlog exceed budget + one block even through 3 s GPU stalls. Every lever is independently switchable and falls back to the proven legacy path; the benchmark picks the defaults.
- **GPU layer** — Fixed-shape IOBinding with CUDA graphs, a highest-priority CUDA stream, a DirectML high-priority queue, and a TensorRT-RTX option. P3 integration defaults cut CUDA per-call p95 from 21.7 ms to 10.9 ms and RTF p99 from 0.95 to 0.28; CUDA now ties DirectML per call.
- **Pitch bank, retrieval and post stage** — SwiftF0, FCPE, RMVPE, CREPE-tiny, PESTO and fusion; rms_mix, cepstral formant shift (±12 st), a silence gate and a limiter. A final-gate pitch-track fix (end-aligned RMVPE mel) raised speaker similarity on 8 of 8 clips and cut F0 error on 8 of 8.
- **Benchmark v2 and autotuner** — Quality metrics (MCD, F0 RMSE/GPE/V-UV, CAM++ cosine, DNSMOS, CER via Sigil's own STT, click detector), an offline ceiling, contention and live-record modes, a competitor compare mode, and an in-app autotuner that picks a working preset on CPU and GPU. Scorecard: [docs/benchmarks/VC_BENCHMARKS.md](docs/benchmarks/VC_BENCHMARKS.md).
- **Honest status against the targets (T1–T10)** — Met: T7 (backlog/stall recovery), T2 context scaling and over-budget rate, T5 clicks and CER, T8 fuzz/default-voice/import time, T4 GPU core use and silence on DirectML. **Not yet met:** T2 absolute per-block cost (p95 10.9–25.5 ms vs the 6 ms target), T1 engine latency at the reference quality (132.6 ms vs 85 ms; 80.6 ms reachable only at a fidelity cost), T3 VRAM with RMVPE (861–1312 MB vs 650 MB; 484–537 MB with lighter pitch extractors), T4 the one-thread CPU Streamer preset (RTF 3.4), T5 MCD (1.68 dB vs 0.5 dB) and F0 RMSE (47–53 cents vs 15), T9 DirectML cold load (2.7–3.2 s vs 2.5 s). Speaker cosine meets ≥ 0.97 only with 20 ms of lookahead (the Quality preset). T6 head-to-head and T8's 40-voice corpus need your competitor outputs and voice files. Closing these gaps is the remaining engine work; see the scorecard's "what is left" paragraph.
- **Zero-shot and singing feasibility ([ADR 0006](docs/adr/0006-vc-zero-shot-singing.md))** — Seed-VC real-time: GO in-engine at fp32 on CUDA and DirectML (parity 58–62 dB SNR; fp16 fails waveform parity and stays a switch). DDSP-SVC 6.3 singing: GO on CUDA from Sigil's own export; NO-GO on DirectML as exported. MeanVC2: GO as an experimental CPU family pending an A/B. A cross-cutting finding: ONNX Runtime and PyTorch divide the last partial window of `AveragePool(ceil_mode)` differently, so CAM++ speaker-similarity exports need custom pooling to match — this affects the benchmark's cosine metric too.

#### P3B — voice-engine optimization (voice changer)

- **Faster, lighter engine** — The content encoder runs as a fixed-shape, graph-captured plan and F0 overlaps it on a helper thread (content call CUDA 4.9 → 1.8 ms, DirectML 4.3 → 1.5 ms; per-call p95 CUDA 11.7 → 7.4 ms, DirectML 12.2 → 9.0 ms offline, and CUDA under a 70 % GPU load 19.2 → 9.6 ms). Lookahead now runs on DirectML too. The generator keeps `enc`'s output on the device, the CUDA wait blocks instead of spinning (worker CPU on CUDA down 84–94 %), and DirectML voices share one GPU queue.
- **Faster voice load** — A voice loads in about 1 s on CUDA (was 1.8 s) and 1.1–1.3 s on DirectML (was 2.5 s): the load plans its final shapes once and builds the pitch model, content encoder, generator and index side by side. A second hot voice shares RMVPE and adds about 130 MB instead of a full copy.
- **Pitch** — The F0 cache never calls RMVPE beyond its plan, picks up cleanly after silence, and the SwiftF0 / RMVPE fusion runs both at once. Opt-in or experimental: a 32-frame RMVPE "VRAM saver" plan (environment switch), filled F0 calls and a cross-tick pitch decoder.
- **Safer content plan** — The content encoder's fixed-shape plan on the GPU is cross-checked against a CPU session of the same file the first time a shape loads, so a driver that compiles it wrongly falls back to the dynamic session instead of playing garbled features (`SIGIL_VC_CONTENT_CHECK=0` switches the cross-check off). The running-content-normalisation lever is offered only when a stream encoder variant is installed, and the content-context environment override is a benchmark-only setting.
- **Advanced pacing (new, off by default)** — Output cushion (fixed or experimental adaptive), device block (10 ms blocks cut about 17 ms of delay in our paced test), join search window and content context, under Advanced in the voice changer panel.
- **Benchmark you can trust** — An interleaved A/B perf gate (paired statistics, GPU-clock state flags, a GPU timing lock), per-stage and VRAM attribution, an out-of-process game-like GPU load, a fidelity scorer v2 with an exact CAM++, fed-F0 errors and conditional click tests ([ADR 0009](docs/adr/0009-vc-scorer-v2.md)), and a corpus head-to-head (T6) with neutral references, fairness checks and Pareto latency. The decisions and what was left off are [ADR 0010](docs/adr/0010-sve-optimization-p3b.md); the numbers are in [docs/benchmarks/VC_BENCHMARKS.md](docs/benchmarks/VC_BENCHMARKS.md#p3b-voice-engine-optimization-p3b-i0).

#### P4 — translation stack

- **Local LLM translation** — Tencent **Hy-MT2** is the default translator, run by a `llama-server` helper that Sigil starts and stops itself (bound to 127.0.0.1 with a random key, killed with Sigil even if Sigil is force-closed). Automatic model and VRAM planning picks 1.8B or 7B for your card and steps aside while the voice changer runs. **MiLMMT-46-4B**, TranslateGemma and Seed-X are selectable challengers. Verified live on the dev PC: EN→JA translated in one round trip, corpus chrF 59.9 vs 58.6 for NLLB-600M.
- **Partial captions translate without flicker** — LocalAgreement-2 commits only the text two consecutive translations agree on, so the translated caption grows instead of rewriting itself; finals are never dropped when a newer partial arrives (property-tested).
- **Long tail and fallback** — **NLLB-200 (600M / 1.3B int8)** runs inside Sigil on ONNX Runtime for ~200 languages; the router falls back from the LLM to NLLB within one timeout and stays on captions if the LLM stops.
- **Prompt builder** — Rolling context of previous lines plus a glossary of names and slang, per-model templates (Hy-MT2 background/terminology blocks, Sakura, VNTL, generic chat), with a shared glossary editor in the translation panel.
- **Free cloud options** — DeepL API Free (called from Rust, quota read live) and Gemini Flash-Lite through the shared OpenAI-compatible client; AI Transform moves onto that same client and gains streaming, a configurable token limit and reasoning effort.
- **Pending** — The Bergamot zero-VRAM CPU helper is not built yet (manual build per ADR 0008); until then the CPU fallback chain is NLLB + Hy-MT2 on the llama-server CPU pack.

#### P5 — voice families in the engine and the shared voice library

- **Zero-shot voices (Sigil-ZS)** — Seed-VC real-time runs inside Sigil's own engine on CUDA and DirectML: pick or record a 5–10 s reference clip and the voice converts toward it with no training. The default **Low delay** preset measured about 250 ms end to end on an RTX 4090 (upstream's live GUI: 430–690 ms) and matched or beat upstream's offline speaker similarity on our clips (0.582 vs 0.559); the prompt is taken from the clip's speech, not its first seconds. Voices with the same shape share one set of GPU sessions, so a second zero-shot voice or a reference switch does not load another 0.9 GB ([ADR 0006](docs/adr/0006-vc-zero-shot-singing.md#p5-outcomes)).
- **Singing voices (DDSP-SVC 6.3)** — Import a DDSP-SVC `model_*.pt` + `config.yaml` (allow-list reader in the isolated import worker; about 1 s). Follows the voice from E2 to D#7 with 0.00 % gross pitch error using CREPE, SwiftF0 or fusion F0 (new DDSP voices start with CREPE in the singing range; RMVPE misses the top notes). Runs on CUDA and now DirectML (the `ddsp` graph's inverse STFT was rebuilt: 4.2 ms per call instead of 2–4.6 s), about 28 ms per 100 ms block.
- **MeanVC2 (experimental)** — Zero-shot on the CPU at 0.2–0.3 of one core, leaving the GPU to the game: real time on one thread where RVC's CPU tier is not. Its speaker encoder is still a manual download.
- **so-vits-svc 4.0 / 4.1 and w-okada files (experimental)** — so-vits-svc ONNX exports (MoeVS / `onnx_export.py`, speaker mix, w-okada's 4.0 exports) run on the engine; wok000's three-output content encoders serve v1 and v2 voices; every loader names a wrong file for what it is (a pitch model set as the encoder, VCClient's fused RMVPE pipeline, a PyTorch file, …). FCPE also runs mel-input exports.
- **Sidecar protocol v2** — X-VC, StreamVoiceAnon and seed-vc-realtime (or your own server) run as separate programs that Sigil starts on 127.0.0.1 with a random key, with frames pipelined and a per-frame deadline equal to the latency budget: a stalled engine is muted and cancelled, never stalls the voice. The scripts ship with the app.
- **Shared voice library** — Record or import reference voices once (Silero-trimmed, checked for clipping and noise, normalized to −20 LUFS, transcribed locally) for zero-shot voices now and TTS cloning in P6; per-engine embeddings are cached with the clip.
- **Family UI** — **New voice…** creates any family's voice, with its options, reference picker, singing mode, execution-provider switch and experimental labels.
- **Integration fixes** — Family voices that compute a block in one burst play with at least the output buffer they need, per voice (Sigil-ZS 80–95 ms by preset and GPU path, DDSP-SVC 70–150 ms, MeanVC2's 160 ms tick 80 ms; the default 35 / 70 ms ran dry); selecting another voice or pressing Stop while a sidecar voice's helper is still starting now takes effect at once; the 16 kHz noise removal no longer silences a voice whose model takes another rate; a voice without its own reference no longer inherits the previous voice's; the benchmark scores family voices against their own offline ceilings.
- **Pending (manual)** — An H1 (RTX 3060 / 4060) live-record of zero-shot voices, a listening check with a real trained DDSP-SVC voice and a real so-vits-svc export, the MeanVC2 speaker encoder download and A/B, X-VC / StreamVoiceAnon with their checkpoints, and a microphone recording in the app.

#### P6 — streamer features, extended engines and free cloud

Every new feature is off by default or a new backend you pick.

- **Other players' captions** — Transcribe what other players say in VRChat (on Windows 11 only the game's sound, so your own voice, TTS and music stay out), optionally translated into your language. Kept apart from your own captions: they never reach the chatbox, TTS or history.
- **Caption window and SteamVR overlay** — An always-on-top, click-through caption window that never steals focus from a game (pinnable in XSOverlay / OVR Toolkit), and a native SteamVR overlay on your head, hand or in the world with CJK and right-to-left text. Sigil never starts SteamVR.
- **VRChat** — Captions mute when you mute in VRChat (OSCQuery, so no port clash); chatbox messages are paced so VRChat no longer drops them, long text can be split into numbered pages instead of being cut, and a mid-thought pause can wait for the end of your turn; SenseVoice emotion and sound tags drive avatar parameters and optional emoji.
- **LAN access with a token** — Phones, a second PC with OBS and Link apps need the LAN token in their link; everything on this PC works without it. "This PC only" mode, a New token button and a legacy switch (off by default).
- **New voices** — Microsoft Edge voices (keyless) and Gemini TTS (your free key), both falling back to the local Kokoro voice within about a second when the service fails; Qwen3-TTS (built-in voices, cloning from the voice library, voice design); Pocket TTS (CPU cloning) and Chatterbox Multilingual (23 languages) inside Sigil; Style-Bert-VITS2 / AivisSpeech `.aivmx` voices inside Sigil; GPT-SoVITS servers; and experimental GPU voices (NVIDIA Magpie, Breeze TTS 2, OmniVoice, Fish S2 Pro) as local helpers, with cloning on Breeze, OmniVoice and S2.
- **Magpie v2607 (Korean, Arabic, Brazilian Portuguese)** — The Magpie packs are NVIDIA's NeMo-Speech.cpp v0.2.0, which reads NVIDIA's own v2607 model file as it is (no conversion step; v0.1.0 refused it), and still runs v2602, which stays the default. Each model uses the tokenizer of its own checkpoint. v2607 and its tokenizer are imports until their files are published; choosing it with an older installed pack says to update the pack.
- **Windows voices** now play sentence by sentence through Sigil's output (skip, stop, the voice-changer route), and **Mute the microphone** keeps the voice changer's microphone shut for a whole spoken reply. TTS can also wait until you finish speaking (Smart Turn).
- **Gemini Live speech-to-text** — Transcribe or Live Translate on your own key, with sessions renewed every 9.5 minutes without losing or repeating words.
- **Readings and music filter** — Hiragana / romaji for Japanese and pinyin for Chinese captions (published for displays; not drawn under captions yet), and an experimental filter that drops music-only and singing segments. Kokoro's Japanese voices read kanji with Japanese readings once the dictionary is installed.
- **Pending (manual)** — The two-PC LAN token matrix, a real VRChat / SteamVR session, every new engine on real weights (downloads over the phase limit), the cloud voices and Gemini Live with real keys, and SAPI through the voice changer by ear.

#### P7 — measure, set defaults, document

Scope for this release (2026-10-09): Sigil's core audience is VRChat streamers who run speech-to-text captions into OBS while in VR, so the goal is that everything works, stays light enough not to steal resources from the game, and ships good defaults and options. Everything was measured outside VR, under a benchmark game-load simulator that stands in for the running game. The heavy GPU models (Voxtral, Cohere Transcribe, Qwen3-ASR 1.7B, Hy-MT2 7B, MiLMMT 4B, TranslateGemma, Qwen3-TTS 1.7B, Magpie, Breeze, OmniVoice, Fish S2 Pro) stay opt-in and were not benchmarked or tuned.

- **Moonshine no longer drops long captions** (fix `f8eedb8`) — sherpa-onnx 1.13.8 returns an empty result, without an error, when the Moonshine model decodes 9.272 s of audio or more at once, so any sentence over about 9 s lost its whole caption. Utterances over 9 s are now cut at quiet points, each piece is decoded on its own and the texts are joined; a piece that still comes back empty is decoded again as two halves, and a rate-limited log warning names the case. On the P7 English corpus the long utterances now caption at a word error rate of 19.9 % instead of 100 %. The new engine option `moonshineMaxSegmentMs` can only lower the 9 s limit (`0` never splits).
- **Fewer popups at launch** (`661cc67`) — The one-time "Try natural local voices?" question now only goes to people who use text-to-speech: it waits until a profile has started TTS once, starts it with the app, or picked a Web Speech / Windows voice. Caption-only users are no longer asked about a feature they don't use.
- **Speech benchmark** — `Sigil.exe --headless speech-bench <spec.json>` measures the app's own speech-to-text (Whisper, HTTP, sherpa-onnx, transcribe.cpp, and the real pipeline with voice detection, routing and two-pass finals), translation (NLLB, Bergamot, llama-server, OpenAI-compatible) and text-to-speech (local voices, GPU helpers) backends on a reproducible corpus (FLEURS speech in 9 languages under 14 conditions with music, effects, babble, room and microphone-codec bleed: 12,600 clips) or text sets, under a CPU/GPU load simulator and the GPU timing lock. It writes a report, the hypotheses or renderings and a privacy-checked export a friend can send back. Python scorers (WER/CER with bootstrap intervals, chrF2, MetricX, TTS pre-screens) and offline blind-listening pages come with it ([docs](docs/DEVELOPER_GUIDE.md#speech-benchmark---headless-speech-bench-p7), [`scripts/speech-bench/`](scripts/speech-bench/README.md)).
- **Documentation** — A new operator-reference section, [Choosing engines for your PC](docs/OPERATOR_REFERENCE.md#choosing-engines-for-your-pc): speech-to-text, translation, text-to-speech and voice-changer choices by hardware tier (CPU only, mid-range GPU, high-end GPU) with what each costs, what Sigil itself costs next to the game, a [VRChat streamer quick start](docs/OPERATOR_REFERENCE.md#vrchat-streamer-quick-start), how to keep Sigil light, the voice-changer defaults and opt-ins as shipped by the engine optimization, and how to use another voice changer over a virtual cable. The developer guide lists every `--headless` command (including `mt-bench`, `speech-bench`, `gpu-load` and `stt-worker`). The VR, SteamVR, two-PC and friends'-PC checks moved to an optional "verify when convenient" section of the release guide. The old voice-changer plan is marked superseded by the Sigil Voice Engine docs.
- **Better defaults for Japanese and Russian captions** — Chosen on the own-microphone conditions (clean speech plus a reverberant room and a poor headset link; the game-audio conditions play no part, because headphones keep the game out of your microphone). Russian now uses a Parakeet Ultra final instead of Qwen3-ASR 0.6B (error rate 7.3 % against 22.1 %) and Japanese a SenseVoice final instead of Qwen3-ASR 0.6B (character error rate 6.8 % against 10.0 %, with 5.5 times less processor time). English, the other Parakeet languages, Korean (Qwen3-ASR 0.6B, 5.1 % against SenseVoice's 7.9 %) and Chinese are confirmed, and so is the translation chain (Hy-MT2 1.8B, Firefox Translations, NLLB-200) and the text-to-speech default (Kokoro). The route is a table, so no saved setting changed; the next start of a Japanese or Russian profile plans the new final and asks before downloading it. Setting the spoken language still matters most: **Detect automatically** gives every language a Qwen3-ASR 0.6B final.
- **Interim translations are off while the local AI translator runs on the processor** — Live partial translations with the bundled Hy-MT2 on the processor took 4.0 cores next to a game (6.7 at the peak); final lines only take 1.5. The **Interim results** switch of the AI model and Automatic translation panels is now automatic by default: on, except while the local model server runs on the processor (the `cpu` variant, or `auto` resolved to it), with a note in the panel. A GPU variant keeps them on (0.2-0.4 cores). A switch you set yourself is kept as it was and can be turned on again at any time; finals are always translated.
- **Better European translations on a processor-only PC** — While the local AI translator runs on the processor, English with French, Portuguese, Dutch and Spanish (both directions; the source is your Source language setting or, left on automatic, the language the speech engine reported for the line) is now translated by NLLB-200 600M with beam 4 first, with the AI model behind it. Measured on 480 lines of casual captions, WMT24++ and FLORES-200 (French +6.0 chrF, Portuguese +4.8, Dutch +3.6, Spanish +2.8, each with the 95 % interval above zero): NLLB takes about 1.6 s a caption line (p95 2.4 s) for 1.8 cores, against 0.4 s for 3.7 to 5.0 cores. German and Italian tied and stay on the AI model; Japanese, Korean and Chinese, every graphics-card setup and a chain or a language pair rule you set yourself are unchanged. The route needs the NLLB model (0.9 GB, **Models & Runtimes**); without it translation runs exactly as before. #### Clean-machine fixes (found by the Windows Sandbox smoke)

The release rehearsal ran the installer's app in a clean Windows (Windows Sandbox: virtual GPU off, no network) for the first time and found four problems, all fixed:

- **The installers carry the Visual C++ runtime** — `Sigil.exe` imports `vcruntime140.dll`, `vcruntime140_1.dll`, `msvcp140.dll` and `msvcp140_1.dll` when it starts. A PC that never installed a program built with them (a clean Windows, a new VM) has none, and Sigil exited with `0xC0000135` before it showed anything. Both installers (NSIS and MSI) and the portable zip now put the four files next to `Sigil.exe`, app-local. `scripts/release/stage-native-dlls.mjs` takes them from the Visual Studio redistributable folder (`VC\Redist\MSVC\<version>\x64\Microsoft.VC14*.CRT`, found with vswhere, the newest of all installations; files Microsoft licenses for this), never from System32 and never downloaded, and fails the build when they are missing. `verify-bundle.ps1` checks that both installers contain them (byte for byte as staged) and fails on any other `vcruntime` / `msvcp` import; `release.yml` finds them before the long compile; the packaged smoke's `layout` check requires them.
- **Sigil starts on a PC with no network** — With no default route (airplane mode, a cable that is unplugged, Windows Sandbox with networking off) the app's first IPC call failed with "Error retrieving local IP" and the window showed "Application failed to start". It now advertises the first LAN address, else loopback.
- **The Basic Render Driver is never a GPU** — In a clean Windows, DXGI lists Microsoft's software renderer several times and only one entry carries the software flag. The others (vendor 0x1414, device 0x8C / 0x8E, "Microsoft Basic Render Driver") counted as hardware GPUs: `--headless sysinfo` reported them, the smoke's no-GPU check failed, and the startup log recommended DirectML where `--headless ep-probe` said CPU. One rule now classifies them as software everywhere.
- **Smoke harness** — An app that dies silently no longer hides its exit code behind a null-reference error (Windows PowerShell 5.1 turns the empty stderr of Get-Content -Raw into `$null`); exit codes are printed in hex and named (`0xC0000135 STATUS_DLL_NOT_FOUND`); a WebView that never exposes its DevTools page writes `gui-page-diag.txt` (processes and command lines, listening sockets, the `/json/version` answer). Windows Sandbox's WebView2 does not apply the `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` override the smoke uses to open a DevTools port (Edge itself opens it), so there `gui-page` judges the front end by the app's own log (the page's first system-log line), says in its detail that the page was not inspected, and `gui-models` rests on the catalog check; `-NoDevTools` exercises that path on any PC.

#### Stream reliability (captions that keep going for hours)

An audit of the main setup (one Windows PC, Built-in speech-to-text, an OBS browser source, Sigil minimized for hours) looked for ways the captions could stop in the middle of a stream. Everything it found is fixed.

- **The OBS canvas source starts every time, in any order** — About one load in nine ended on "Application failed to start" because the source picked a connection id that PeerJS refuses; the id is now always valid. A source that loads before Sigil is listening keeps showing "Connecting to Sigil…" and connects as soon as Sigil is up (after three failed tries it names the address it is waiting for), instead of stopping on the error page.
- **The OBS canvas source reconnects by itself, for as long as it lives** — The old stop after about 8 minutes is gone. After a Sigil restart, crash or sleep the source tries again 1, 2, 4, 8 and 16 s apart and then every 30 s, with the yellow "Lost connection to Sigil — reconnecting." bar on stream meanwhile, and shows the host's current scene and language again once it is back. An attempt that stalls is dropped after 20 s and a link the network has cut for 10 s is rebuilt, so captions never sit frozen on a dead link. Only a refused link (the LAN token changed, or LAN access is "This PC only") needs your hand: copy the LAN link again; the source asks again every minute.
- **A blip in the web server no longer cuts the source** — A lost signaling connection (a Wi-Fi roam, Sigil's server rebinding) no longer tears down a healthy link. Sigil renews its own registration after a dropped socket, a taken id or a server that was not up yet, and holds the "host left" notice for 30 s, so a hiccup of that one connection costs the OBS sources nothing. The captions page (`obs-captions.html`) picks a random id for every connection, so two sources with the same address no longer silence each other; a second connection that reuses a `/pubsub` id now closes the first with code 4409 instead of leaving it open and deaf.
- **A bad scene shows nothing, then heals** — A scene that did not hold every element of the canvas could crash the `/client` page. It now shows nothing on stream and the page reloads itself after 4 s (twice as long for every further reload within 10 minutes, at most 2 minutes), once Sigil answers. Deleting the active scene moves the sources to **main**.
- **The local web server never gives up** — If the port is busy at start-up, or the listener ever ends (or its task crashes), Sigil retries after 1, 2, 5 and 10 s and then every 15 s for as long as it runs, and OBS and browser sources reconnect once it is back. Switching LAN access or restarting Sigil is no longer needed.
- **Starting Sigil twice, or right after closing it** — A second launch brings the running window to the front instead of showing "Port 3030 is not available". A start within seconds of closing waits quietly (up to about 25 s) for the old copy to finish ending. If the port stays busy the message now names what holds it (a program, or the other Sigil), mentions the ports Windows reserves, and suggests `--port`.
- **Built-in speech recognition no longer stops for good** — After the quick retries (1, 2, 5, 10 and 20 s) it keeps trying about every 45 s until you press Stop, and shows "Speech recognition is not running (…). Trying again in N s" instead of an error. A first start that fails because the microphone is busy (another app, exclusive mode) or an engine fails to load is retried the same way, **Start on launch** included. A crash of a speech capture or recognition thread now ends the session as an error that the automatic restart handles; it used to leave a session that looked connected and heard nothing. Errors a retry cannot fix (a missing model, an unsupported request) still stop with a message.
- **A renamed USB microphone is found again** — A microphone picked by name is matched again when Windows renumbers its endpoint after a USB port change or driver update ("Microphone (USB Audio)" becomes "Microphone (2- USB Audio)"). It matches only when exactly one device has that name, never falls back to the system default, and while Sigil reopens a microphone it lost, only a device that was not listed when the loss began counts, so a second identical headset never takes its place.
- **Cloud speech recognition reconnects** — OpenAI-compatible, Groq, Deepgram and Azure speech recognition reconnect after a lost connection or a network failure (the same retries, then about every 45 s) with a "reconnecting" status line and no error popup. A rejected key or bad settings still stops with the message, and a rate limit waits and tries quietly every 45 s. An unreadable answer (a login page in the way, cut-off JSON) is retried instead of being treated as a bad request. A Start you press yourself that fails still shows its error right away.
- **Stop with Twitch stream waits for the stream to stay offline** — Speech to Text, Text to Speech and Rewrite stop only after the stream has stayed offline for 60 s (a dropped connection no longer ends them), and what they stopped starts again when the stream comes back during the same session.

#### Release polish (voice changer Chunk size, silent microphone, window recovery, Windows questions, installers, languages)

- **Voice changer: you can choose the Chunk size** — How much audio the engine converts in one go (it was **Block size**, hidden in the closed **RVC tuning** section) is now **Chunk size**, directly under **Preset** in the RVC settings. The first choice is **Auto (N ms on this PC)**: the Streamer on the processor takes 120, 160 or 200 ms by your physical cores and every other preset follows the Audio device buffer. Then come 20 to 200 ms in steps of 20; the old 30 and 50 ms ran as 40 and 60 ms and are gone, and a stored one stays visible, marked "runs as". A size you pick is kept through restarts, presets, voices and the execution provider (only **Apply these settings** after Autotune changes it), and the automatic output buffer, the latency budget and the crossfade limit follow it. The control is greyed out, with the reason, for bring-your-own ONNX, Sigil-ZS, MeanVC2 and sidecar voices; so-vits-svc takes it, and DDSP-SVC takes 60 to 200 ms with its preset's block as Auto. On the Streamer on the processor, a size shorter than Auto takes on your PC gets a note under the control on any PC, not only the small ones.
- **Voice changer: two sizes, two names, and fair readouts for long chunks** — "Processing chunk size" is now **Audio device buffer** and "Device block" is **Device buffer mode**, so the sound card's buffer and the engine's chunk no longer share a word. The status panel shows **Chunk** and **Device buffer** rows and "Running N ms chunks". For the 120 to 200 ms chunks it times the model calls themselves (**Conversion per chunk**): a healthy Streamer on the processor no longer reads "slower than real time", and a slow call is no longer hidden among the idle ticks. A latency budget under what one chunk needs is raised while the voice runs, instead of dropping most of the speech after every call, and a crossfade longer than the device buffer now takes effect on a long-chunk voice.
- **Speech to Text says when the microphone is silent** — A microphone that delivers only silence for about 5 seconds (Windows microphone privacy off, a headset mute switch, "System default" following Windows to a silent device) now shows "Sigil hears nothing from" its name under **Start**, with the Windows setting to check, and the status-bar card reads **No signal** instead of ONLINE. It clears by itself when sound returns and restarts nothing. A microphone that was heard earlier in the session gets a minute, so a noise gate (NVIDIA Broadcast, Krisp) that sends silence between phrases does not trigger it; a quiet room or a low Windows input volume is not silence. The built-in engine and the HTTP engines report it; Whisper (old), Vosk, Gemini Live and Chrome / Edge do not.
- **A crashed or hung Sigil window comes back** — If the web renderer behind the Sigil window exits, the page reloads by itself after 1, 5 and 15 s (at most 3 times in 2 minutes, then one more try when the oldest leaves that window) and the microphone session of the dead page is stopped. A renderer that is only busy is left alone; one that stays unresponsive for 30 s is reloaded once. The new page also stops speech recognition that the old one left running (after F5 as well), so nothing runs twice, and with **Start automatically** on, captions start again.
- **The VRChat tab explains what Windows may ask** — Next to **Find VRChat automatically (OSCQuery)**, a fixed **Listen port** and a VRChat on another PC, a note says why Windows may ask once to allow Sigil on the network (OSCQuery listens on UDP 5353 to find VRChat; a fixed port is checked on every address first; a VRChat on another PC is reached over the network, and its mute only arrives if Sigil may listen). It says to choose **Allow access**, never **Cancel**, which would make Windows block Sigil for good. Limiting OSCQuery discovery to the loopback address was evaluated and is not possible with the mDNS library (it binds every adapter when it starts), so the binding stays and is documented.
- **The installers embed Microsoft's WebView2 bootstrapper** — The release NSIS and MSI installers carry the bootstrapper (about 1.8 MB more) instead of downloading it while installing. It still downloads the WebView2 runtime itself when the PC has none, so installing on a PC with neither the runtime nor internet still does not work (that needs Microsoft's offline installer, about 130 MB more per installer, which these installers do not carry). The portable zip has no installer and needs the runtime already on the PC: Windows 11 includes it and an up-to-date Windows 10 usually has it. `verify-bundle.ps1` checks the install mode, the bootstrapper's Microsoft signature and that both installers contain it.
- **Sigil is now translated into 20 languages** — English plus 19 translations (Español, हिन्दी, العربية, Français, Português (Brasil), Русский, 日本語, Deutsch, 한국어, Italiano, Bahasa Indonesia, Türkçe, Tiếng Việt, Polski, ไทย, বাংলা, اردو, 中文（简体） and 中文（繁体）). They are machine-assisted, and corrections are welcome ([Translation review](docs/DEVELOPER_GUIDE.md#translation-review-human--community)).

#### P2 — in-process speech engine (STT and TTS)

- **Speech-to-text "On this PC (automatic)"** — New backend and the default for new desktop installs: Sigil picks the speech models for your language and PC and runs them inside the app, with live captions (Nemotron 3.5 streaming) replaced by a more accurate final line per sentence (Parakeet Ultra, Qwen3-ASR, SenseVoice, Whisper; on NVIDIA GPUs Qwen3-ASR 1.7B or Cohere Transcribe through transcribe.cpp, admitted by the video-memory governor). It asks once before downloading (about 1.1 GB for English, or a smaller single-pass setup), shows a route preview, restarts itself after device or engine errors, and supports hotwords and Smart Turn end-of-turn hints. Existing users on the browser default are asked once whether to switch.
- **One speech pipeline in Rust** — Whisper, the OpenAI-compatible / Groq and the Moonshine HTTP engines now run in Rust behind the same voice detector with ordered decoding, a 20 s latency budget, merging when behind, retries and a Groq limiter; keys stay in headers, LAN servers work, and captions carry segment ids and revisions. Whisper downloads go through the model store (pinned, resumable). Deepgram stops sending (and billing) while muted; Azure loads its SDK only when used; the Moonshine server backend is legacy.
- **TTS sentence pipeline and unified output** — Long text starts speaking after its first sentence; every PCM backend plays through one Rust output that honours the output device and volume, can route speech into the voice changer (or both), and has **Skip** / **Stop speaking** on the status bar. Output device lists show Windows device names (old names migrate automatically). Azure streams raw PCM; VOICEVOX, Uberduck and the server backends stream sentence by sentence.
- **Local voices "Kokoro / Piper (local)"** — Kokoro v1.0 (8 languages), Kokoro v1.1-zh, 36 Piper voices and Kitten run inside Sigil (CPU, about 3.4× real time for Kokoro on 4 threads) with a consented one-time download; the default TTS for new desktop installs (existing users on browser or Windows voices are asked once). With the default voice, each sentence gets a voice of its caption's language (tagged text, else the script). The ONNX (local) backend runs on the same engine.
- **OpenAI-compatible TTS** — A streaming `/v1/audio/speech` client with presets for Kokoro-FastAPI, Chatterbox, Voxtral-4B-TTS, IndexTTS-2.5 and VoxCPM2 (vLLM-Omni) and qwentts; Kokoro, Chatterbox, Melo, Fish Speech and the HTTP server backends stream through it. The reference `tts_sidecar.py` gained a streaming mode and OpenAI routes and binds 127.0.0.1.
